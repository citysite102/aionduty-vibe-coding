對簡報第 $1 頁到第 $2 頁執行教學模擬。你是導播，負責串接三個 agent 並整理成報告。
persona 參數是 $3，沒給就用 `marketer`。

頁碼是 LIVE 頁碼（1 起算），不是檔名編號。

## 執行順序

1. 跑 `node scripts/slide-manifest.mjs $1 $2` 取得這一段有哪些頁、標題與檔案路徑。
   **你自己不要讀投影片內容**，那是講師 agent 的工作，讀了只會佔掉你的 context。

2. 讀 `sim/handoff.md`（不存在就當作空的，代表這是第一段）。

3. 呼叫 `lecturer` subagent，傳入：
   - 步驟 1 的頁碼對照表原文
   - `sim/handoff.md` 的內容，標明這是「前面段落已經講過的內容」，並點名到目前為止仍然零定義的關鍵名詞
   - 輸出檔路徑 `sim/transcript/seg-P$1-P$2.md`
   - 要它把交棒摘要**附加**到 `sim/handoff.md` 末尾

4. 對每一個 persona，呼叫 `student` subagent（多個 persona 時**同時**呼叫，它們互不影響），傳入：
   - persona 檔路徑 `sim/personas/{persona}.md`
   - 知識狀態檔路徑 `sim/state/{persona}.md`（不存在就說明這是第一段，狀態從空的開始；
     若這個 persona 中途才加入，要它先讀前面的逐字稿掌握「它人在場但沒寫過反應」的那幾段）
   - 逐字稿檔路徑 `sim/transcript/seg-P$1-P$2.md`
   - 輸出檔路徑 `sim/reactions/seg-P$1-P$2.{persona}.md`
   - 提醒它逐字稿裡的 `[缺口:...]` 是內部註記，台上聽不到，要忽略
   - 若這一段有叫學員動手的頁，要它演完並誠實寫「到底有沒有做出東西」

5. 呼叫 `observer` subagent，傳入：
   - 逐字稿檔路徑
   - 所有學員反應檔路徑（多個 persona 時全部給它，並要它比對差異）
   - 前面段落的診斷檔路徑，要它判斷前一段的「先修」有沒有在這一段被還清
   - 輸出檔路徑 `sim/findings/seg-P$1-P$2.md`

6. **驗證觀察員與學員的主張**，見下方「驗證」。

7. **產出報告**，見下方「報告」。

## 驗證

**不要照單全收。**在報告裡引用任何一條主張之前，凡是可以用 `grep` 或 `Read` 查的，就去查。

已經發生過三種錯，這三種每次都要查：

| 錯誤類型 | 實例 | 怎麼查 |
|---|---|---|
| 講師編了簡報上沒有的話 | 把投影片的暗示硬化成「不會有任何一段是你看得到做不到的」這句承諾 | 逐字稿裡每一句像「保證」「一定」「不會有」的話，回去 `grep` 投影片 |
| 學員說某頁「沒有 X」，其實有 | 說 P32 沒給 Git 下載網址，其實有超連結 | 直接 `grep` 那個檔案 |
| 觀察員把單一段落的巧合當成結論 | 兩位學員分佈數字相同就斷言「技術背景不是變數」 | 要它進到頁面層級比對「同色是不是同因」，證據不足就要它說不能判斷 |

查出來不成立的，**要在報告裡寫出更正**，不要默默刪掉。結論可能仍然成立但要降級，也要寫清楚降到什麼程度。

## 報告

寫進專案根目錄 `教學模擬報告_{段落名}.md`，用中文白話，**不要出現 C1 到 C9 這種代碼、也不要用 P0/P1/P2**，課程作者不看代碼。嚴重度寫「先修／再修／有空再修」。

固定八節：

1. **摘要**：涵蓋範圍表、模擬學員表（代號、名字、背景、涵蓋頁數、用來檢查什麼）、理解程度分佈表、最該記住的三個數字
2. **學員 A**：走的路線、逐頁問題表、問了但簡報沒回答的問題、這一段結束時手上有什麼
3. **學員 B**：同上
4. **學員 C**（有幾個就寫幾節）
5. **觀察員視角**：失敗點是不是同一個、有沒有達成目標、這份報告哪裡可能不準
6. **修改建議**：照 `observer.md` 的六欄格式，按先修／再修／有空再修排序
7. **按投影片索引的問題總表**：一頁一列，方便一個檔案一個檔案改
8. **下一步**

逐頁問題表固定五欄，內容直接抄學員反應檔的欄位，不要自己重新概括：

| 頁 | 投影片檔案 | 程度 | 卡在哪 | 缺什麼 |
|---|---|---|---|---|

**幫每個 persona 取一個中文名字**（小陳、老林、阿凱⋯）並在摘要的學員表裡對照代號。報告全篇用名字，`marketer` 這種代號只出現在那張對照表跟指令範例裡。

## 在對話中回報

只回報：本段先修 x 個、再修 x 個、有空再修 x 個，逐條列出先修的標題與頁碼，學員理解程度分佈，以及產出的檔案路徑。不要把逐字稿或完整反應貼在對話裡。

## 注意

- 三個 agent 有順序相依，不要平行呼叫講師與學生。只有多個 persona 的學生之間可以平行。
- **subagent 的純文字輸出傳不到你這裡**，一定要在 prompt 裡要求它用 SendMessage 傳給 `main`，或是寫進檔案讓你去讀。
- 學生的知識是累積的，靠 `sim/state/` 維持。**投影片改過之後要清掉 `sim/state/` 重跑**，不然模擬學員會帶著舊的誤解往下走。
- agent 中途可能因為 API 中斷而失敗。失敗時先檢查它的輸出檔寫到哪裡，多半逐字稿是完整的、掛在後續的收尾動作，這種情況你自己補收尾就好，不要整段重跑。
- 如果某個 agent 回傳的東西明顯偏離規格（例如學生每頁都寫「懂了」、觀察員寫了鼓勵性總評、
  建議寫成「建議增加互動」這種廢話），直接指出問題並要它重做，不要照單全收往下傳。
