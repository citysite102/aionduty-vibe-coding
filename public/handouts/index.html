完整教學案例

四份 PDF，每一份從空資料夾走到上線。先寫規格，再做網站。 都標明了閱讀與動手各要多久，沒有程式背景也走得完。檔案大，建議在 Wi-Fi 下載。

課前作業：規格文件怎麼寫
案例一開始之前先寫完這一份。七個區塊寫成一份 spec.md：一句話定義、不做什麼、真實素材、參考方向、硬性限制、驗收條件、素材清單。判斷標準只有一句，這一條是形容詞，還是可以被檢查的條件。
case-01-spec-writing.pdf ・ 2.2 MB ・ 60 到 90 分鐘
案例一：器 VESSEL，陶藝工作室一頁式網站
把「我想要這樣」變成 AI 能穩定執行的規則。沒有資料也沒有表單，所以不需要任何工具。使用 Astro、TypeScript、原生 CSS 與 Vercel。
case-01-vessel.pdf ・ 7.9 MB ・ 閱讀約 1.9 小時，動手約 5.7 小時
案例二：東京環状 24 時，捲動穿越的 3D 藝廊
判斷什麼問題該用什麼技術，每一個工具都要說得出它在解決什麼問題，以及不用它會怎樣。十張照片沿深度排開，捲動時鏡頭穿過它們。使用 Three.js、GSAP 與原生 CSS，不需要看懂 shader 或 JavaScript。
case-02-tokyo-loop.pdf ・ 6.5 MB ・ 閱讀約 2.6 小時，動手約 8.6 小時
案例三：開窯預約，有帳號與資料的網站
哪些事情不能只相信前端。有人繞過網頁直接送請求的時候，擋得住的只有資料庫的規則。可以登入、預約、取消，而且只看得到自己那幾筆。使用 Astro、Supabase 與原生 CSS，不需要看懂 SQL。
case-03-kiln.pdf ・ 6.1 MB ・ 閱讀約 2.5 小時，動手約 7.8 小時

回去之後的第一件事：把模板複製到你手上真正在跑的專案，填完之後開一個新對話， 輸入 /context，確認 CLAUDE.md 出現在 Memory files 清單裡。沒被載入的規則，寫得再好都沒有用。

想不起來某一句指令怎麼打：課程裡出現過的指令都收在 課程工具箱的「指令速查」， 照單元排，可以直接複製。同一個工具箱裡還有 Prompt 組裝器、CLAUDE.md 產生器與規則分流器。
