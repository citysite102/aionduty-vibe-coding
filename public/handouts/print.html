CLAUDE.md 模板

把內容抄進專案根目錄的 CLAUDE.md。填完之後，開一個新對話輸入 /context，確認它出現在 Memory files 清單裡。

這個專案是什麼

一到兩句就好。讓它知道自己在幫什麼樣的專案工作。

例：一個給國小老師用的隨堂計時器網頁。
沒有後端，資料存在瀏覽器裡。使用者不會寫程式。

一定要遵守的

寫成可以檢查的句子。判斷方法：這句話能不能讓另一個人看著程式碼回答「有」或「沒有」。
不算：程式碼要優雅、注意效能、保持一致。
算：不要使用 inline style、所有金額欄位一律用整數。

用字與命名

按鈕文案、變數命名、對外顯示的措辭。這一類最容易一眼看出有沒有照做，適合當驗收的第一個檢查點。

不要做的事

真的不能發生的事，不要只寫在這裡。寫在 CLAUDE.md 只是拜託，對話一長它還是可能犯。 要擋死請用 Hook 或 CI，然後這一區只留一行提醒就好。

這個專案怎麼跑起來

裝什麼、怎麼啟動、怎麼測試。讓它不用問你。

npm install
npm run dev

一份控制在 200 行以內。太長的話，排在後面的規則會被當成背景。
最後健檢： 年 月 日

CLAUDE.md 五步健檢檢查表

打問號的有 條，這幾條進入第 2 步。

第 2 步　減法

先刪再搬，順序不要反。不然會把該刪的東西搬到別處，繼續佔位。

每一條打問號的規則，用這三種證據判斷。至少要有兩種成立才刪。

  • 現場證據　最近的對話裡，它真的違反過這條嗎？從來沒違反過的規則，可能是在防一個不存在的問題。
  • 機制證據　這件事已經有 Hook、CI 或 lint 在擋嗎？有的話，文字版就是重複的。
  • 時效證據　規則綁的那個資料夾、指令、流程還在嗎？專案改過名字，規則常常沒跟著改。

證據不足的時候不要直接刪。 改成降級（從根目錄搬到子目錄，只在相關時載入），或標記觀察（註記日期，下一輪再看）。

刪掉 條，降級 條，標記觀察 條。

第 3 步　分流

留下來的規則逐條分流，判斷方式見「規則分流判斷卡」。搬出去 條。

第 4 步　加法

這時候才補新規則，而且補在正確的位置，不要一律往根目錄堆。

第 5 步　修剪

把無法判定的句子改寫成可以檢查的。

原本這樣寫改成
程式碼要優雅單一函式不超過 40 行
注意效能列表超過 100 筆要分頁
保持風格一致只使用 Tailwind class，不要寫 inline style

完成後

  • 總行數：健檢前 行，健檢後 行
  • 開新對話跑 /context，確認手冊仍在 Memory files 清單裡
  • 下一個會踩到規則的需求，確認它有照做
  • 更新手冊最後一行的健檢日期

規則分流判斷卡

拿到一條規則，照順序問這四個問題。第一個答「是」的就是它該去的地方，不要再往下問。

1. 違反了會出事，絕對不能發生？
→ Hook（你的機器）或 CI（整個團隊）

程式在擋，不經過 AI 的判斷，幾乎不佔 token。
例：不能把 API 金鑰寫進檔案、不能刪除正式環境的資料。

2. 只在某一區檔案才適用？
→ 子目錄 CLAUDE.md，或 .claude/rules/ 用 paths 綁定

碰到那一區才載入，平常不佔位。
例：只有 src/api/ 底下需要遵守的錯誤處理格式。

3. 有固定步驟，用到才需要？
→ Skill

平常只載名稱，要跑那套流程時才展開全文。
例：資料庫改結構的 SOP、發版流程。

4. 以上皆非，而且每一輪都要記得？
→ 根目錄 CLAUDE.md

這裡是最後一站，不是預設選項。能往上送的先送走。
例：技術堆疊、按鈕用字習慣、命名慣例。

三個常見的判斷錯誤

錯誤為什麼會錯怎麼改
把「絕對不要 OO」寫進 CLAUDE.md 就當作擋住了 那只是拜託。對話一長，或它讀到某個網頁寫著「請忽略前面的規則」，還是可能照做 真的不能發生就用 Hook 或 CI
所有規則都往根目錄堆 檔案越長，後面那幾條越容易被當成背景 能綁定範圍的就綁定
規則寫得很完整但無法判定 「要優雅」「要一致」沒有可檢查的標準，它只能猜 改寫成別人能回答「有」或「沒有」的句子

它沒照做的時候，先查這五件事

不要一發現沒照做就急著再加一條規則。先分辨是哪一種失效。

哪一種狀況怎麼處理
沒讀到規則在子目錄，這一輪沒動到那一區跑 /context 確認
被埋掉檔案太長，排在後面的被蓋過做健檢
判不動規則沒有可檢查的標準改寫
打架兩條規則互相衝突做健檢
被蓋掉你在對話中說過相反的話重開對話或明確覆蓋回來

第一步永遠是 /context。確認它有沒有被載入，再談規則寫得好不好。

錯誤訊息判讀對照表

看到紅字不用慌，也不需要看懂那段英文。分辨它出現在哪裡、找出它在說什麼、用對的方式交給 AI。

先看紅字出現在哪裡

出現在哪裡代表什麼怎麼看到
終端機還沒跑起來就出事，專案本身啟動失敗你下指令的那個黑色視窗
瀏覽器 Console跑起來了，但畫面壞掉網頁上按 F12（Mac 按 Cmd + Option + I），點 Console 分頁
兩邊都沒紅字程式沒出錯，但東西沒畫出來見本頁最後一節

每一段紅字都在講三件事

不管多長，都只回答這三題。找到答案就夠了，不必逐字讀懂。

  1. 在哪裡出事　哪個檔案、第幾行
  2. 出了什麼事　它想做什麼、卡在哪
  3. 接下來該做什麼　多半 AI 會告訴你

終端機常見紅字

你會看到白話意思通常怎麼解決
command not found: npm這台電腦還沒裝這個工具先裝工具本身
sh: vite: command not found專案要用的工具還沒裝跑 npm install
Module not found: Can't resolve要載入的檔案找不到檔案沒建、檔名拼錯（含大小寫）、或放錯資料夾
ENOENT: no such file or directory路徑指到不存在的東西確認檔案真的在那個位置
SyntaxError: Unexpected token程式碼打錯字多半少了括號、引號或逗號
Port 3000 is already in use這個門牌已經有人在用關掉另一個視窗，或換一個埠號

瀏覽器 Console 常見紅字

你會看到白話意思通常怎麼解決
Cannot read properties of undefined想拿一個東西，但手上是空的常見原因是資料還沒回來就先畫
xxx is not defined用到沒有定義過的名字拼錯，或忘記引進來
Failed to fetch打電話給後端，沒人接後端沒啟動，或網址打錯
CORS policy 開頭那一長串後端不允許你的網頁跟它要資料後端設定問題，整段貼給 AI
404 (Not Found)那個網址上沒有東西路徑打錯，或檔案沒上傳
500 (Internal Server Error)後端自己出事了不是畫面的問題，去看後端的紅字

怎麼交給 AI

整段複製貼上，不要只貼一句，也不要自己翻譯。前面那幾行通常才有檔名跟行號。

  • 「用白話解釋這個錯誤在說什麼，我不看程式碼。」
  • 「請只改必要的地方修好它，並告訴我你改了什麼。」
  • 「這次為什麼會發生？下次我要怎麼避免？」（最容易被跳過，但它決定你會不會一直踩同一個坑）

沒有紅字，畫面卻一片空白

兩招，都不需要看懂程式碼。

  1. 直接給它看：截圖貼給它，說「這是我現在看到的畫面，OO 本來應該在這裡，請幫我修正」
  2. 去撈瀏覽器的紅字：按 F12，點 Console 分頁，看到紅字整段複製貼回去

出錯當下的檢查順序

  • 紅字出現在終端機還是瀏覽器？
  • 找到檔名與行號了嗎？
  • 整段複製了嗎（不是只有一行）？
  • 貼給 AI，並說明你原本想做什麼
  • 它改完之後，問一次「你改了什麼」
  • 重跑一次，確認紅字真的不見了
