# 上線前自查卡

交出去之前跑一次。**八題沒有一題要你讀程式碼**，每一題底下都寫著怎麼自己驗。

先決定一件事：**這個東西要給誰用。** 只有自己用、沒放上網、裡面也沒有別人的資料，
下半那四題現在都可以先放著。要給同事或客戶用，八題都要過。

---

## 上半　它做到了嗎

| | 問題 | 怎麼自己驗 |
|---|---|---|
| 1 | 完成條件逐條對過了嗎 | 把當初寫的那幾題拿出來，一題一題點過。「它跑起來了」不算對過。 |
| 2 | 做第二次的時候，真的省到了嗎 | 同一件事再做一次，看你有沒有又把整段話重貼。有的話，回去看〈把工作拆成可交辦、可驗收的流程〉最後那三件：輸入固定放同一個資料夾、產物固定寫同一個檔名、做法整理成 `SKILL.md`。 |
| 3 | 你以外的人，打得開也用得起來嗎 | 傳給一個沒看過的人，不要在旁邊解釋，看他卡在哪一步。 |
| 4 | 你講得出它解掉哪一個問題嗎 | 一句話講完，而且不能出現「比較方便」「比較快」。 |

## 下半　別人動得了它嗎

| | 問題 | 怎麼自己驗 |
|---|---|---|
| 5 | 它有沒有登入？裡面有沒有別人的資料 | 開無痕視窗貼上你的網址。你在那裡看得到什麼，全世界就看得到什麼。 |
| 6 | 資料表是不是誰都讀得到 | 去後台看那張表的 RLS 開了沒，規則有沒有限定「只讀得到自己的那幾筆」。 |
| 7 | 金鑰在不在前端的程式碼裡 | 去那個 repo 的頁面，搜一次金鑰的前幾個字。搜得到就當它已經外洩，直接去後台重產一組。 |
| 8 | 密碼猜錯、表單狂送，會不會被擋 | 故意打錯十次看它擋不擋。對外的 AI 功能與表單也問一次：同一個人一分鐘能送幾次。 |

第 5 題排在這一半的第一個，是因為它是實際掃出來最常見的一類：
公開在網路上、看起來是給公司用的 AI 應用，約四成裝著營運或個人資料卻沒有任何登入。

## 交給它先查一遍

下面這段直接複製。它比上面那四題多帶了兩類你自己問不出來的：
管理類功能有沒有再確認一次身分、以及登入之後有沒有把密碼本身存在瀏覽器裡。

```
請照下面五題檢查這個專案，不要改任何檔案：
1. 哪些頁面或功能不用登入就進得去，它們碰得到哪些資料；管理類的功能有沒有再確認一次身分
2. 資料表的讀寫權限規則目前允許誰做什麼
3. 有沒有金鑰、密碼或連線字串出現在會被打包到前端的檔案裡
4. 登入、表單送出、對外的 AI 呼叫，各自有沒有次數上限
5. 登入之後是用什麼方式記住使用者，有沒有把密碼本身存在瀏覽器裡

每一條都要指出你是從哪個檔案的哪一段看出來的，看不出來就寫「看不出來」，不要用推測的。
最後照「被人利用之後收不收得回來」排出處理順序。
```

**「指出哪個檔案的哪一段」那一句不要刪。** 它說得出位置的才是真的讀過你的專案，
說不出來的多半是照一般專案的樣子寫的。

## Agent 寫完程式，怎麼確認沒有留下問題？

上面那段是三種裡的「請 AI 看」。作品交出去的時候，公司的資訊或資安單位、
客戶的技術窗口會問「做過弱點掃描了嗎」「有沒有做滲透測試」，那是另外兩種。

| 哪一種 | 它在做什麼 | 抓不到什麼 |
|---|---|---|
| **自己掃**<br>弱點掃描 Vulnerability Scanning | 資安研究者發現某個套件有漏洞，會登記到一份公開的名單上。掃描工具拿你用到的每一個套件和版本去對那份名單，幾分鐘跑完。 | 已知清單以外的看不出來，例如誰能看誰的資料。 |
| **請 AI 看**<br>上面那段 Prompt | 把清單交給它，逐條對照你的程式碼，一次涵蓋很廣。 | 它不會真的去打你的網站，看漏了你也不會知道。 |
| **外部單位測試**<br>滲透測試 Penetration Test | 請人照真的攻擊者的做法試一遍，找出看程式碼看不出來的問題，例如好幾個小問題串起來才成立的那種。 | 要花錢，而且要先談好範圍與授權。 |

什麼時候真的需要滲透測試：收錢、存別人的個資、對外公開而且有登入，
或是客戶、公司稽核、所屬行業的規定要求你做。

今天就做得到的三件：

- **GitHub 的 Dependabot 警示**　套件有已知問題時它開一張通知給你，私人專案也免費。
- **金鑰掃描**　推上去的那一刻就擋下來。公開的專案免費，私人的要另外買。
- **`npm audit`**　在專案資料夾裡執行，它會列出有問題的套件與修法。

**只掃自己的東西。** 沒有授權就去掃別人的系統，在台灣可能牴觸刑法的「妨害電腦使用罪」。
想練攻擊那一面，用刻意做成有洞的靶場，例如 OWASP 的 Juice Shop：
<https://owasp.org/www-project-juice-shop/>

## 想再往下對：OWASP Top 10

這是一份公認的清單，公司的資訊或資安單位就是照它在看東西。
現行是 **2025 版**（查證日 2026-10-31，上一版是 2021，大約四年一版，所以它不太會過期）。

這五條課程裡已經提過：

| OWASP Top 10:2025 | 課程裡提過的地方 |
|---|---|
| **A01　Broken Access Control** | 兩層權限、有人繞過畫面直接送請求、上面第 5 題那種沒有登入的工具 |
| **A02　Security Misconfiguration** | RLS 沒開、`bypassPermissions` 全放行、金鑰進了版控 |
| **A03　Software Supply Chain Failures** | 外部來源掛掉整個作品就不會啟動、裝第三方工具前問的那四題 |
| **A07　Authentication Failures** | 密碼猜錯不會被鎖、把密碼本身存在瀏覽器裡 |
| **A09　Security Logging and Alerting Failures** | 它壞掉的時候你查不查得到、後台那幾個分頁 |

另外五條課程裡只念過名字。投影片上不展開是刻意的，但你三個月後翻這張卡的時候，
要對得完十條，所以放在這裡：

| OWASP Top 10:2025 | 白話 | 回去問自己這一題 |
|---|---|---|
| **A04　Cryptographic Failures** | 加密 | 密碼有沒有被原樣存著（存進去的應該是算過之後的結果），對外的網址是不是 https |
| **A05　Injection** | 注入 | 使用者填的字有沒有被直接拼進資料庫查詢或系統指令。接了 AI 的版本在下一段 |
| **A06　Insecure Design** | 設計本身的問題 | 流程本身有沒有繞得過去的地方，例如改一下網址就跳過付款那一步 |
| **A08　Software or Data Integrity Failures** | 完整性 | 更新或下載進來的東西，是不是你以為的那一份 |
| **A10　Mishandling of Exceptional Conditions** | 例外狀況沒處理好 | 出錯的時候會怎樣：畫面有沒有把內部細節印出來、流程有沒有停在一半 |

這五條你現在多半用不到，知道有這幾條存在就好。要它一起查的話，在上面那段指令最後加一句：

```
另外照 OWASP Top 10 2025 逐條看一次，每一條說明這個專案有沒有這個問題、你是從哪裡看出來的。
```

官方清單：<https://top10.owasp.org/2025>

## Agent 能讀、判斷、執行，不代表該放行

一般網站的資安清單上沒有這兩類，它們是接了 AI 才有的。
作品裡只要有「使用者打的字送進 AI、AI 的回答送出來、金鑰放在後端」這個結構，兩類都算在內。

### 它讀到的東西裡可能有指令（Prompt Injection）

送進 AI 的那段文字，它分不出哪些是資料、哪些是命令。使用者打的字、它讀到的網頁、
上傳的檔案裡都可以藏指令。

- 使用者的內容當資料看，要做的事寫在你自己的指示裡
- 會寄信、付款、刪東西的動作不要讓它自己決定，要回來問你
- 內部規則與金鑰不要寫進給它的那段指示裡

### 你給它的權限超過它需要的（Excessive Agency）

那支程式能碰到的範圍越大，一次判斷失誤的代價就越大。
你的後端只該做一件事，不該順便握著整個資料庫的鑰匙。

- 那支程式只做一件事，不要讓它同時能讀會員資料又能發信
- 金鑰放在後端的環境變數，前端只呼叫你自己的網址
- 它做了什麼要留得下紀錄，出事才查得到

這兩類收在另一份清單上，叫 OWASP Top 10 for LLM Applications（genai.owasp.org）。
網站本身對 Top 10，接了 AI 的那一段再對那一份。

## 換一個領域，先問會出事的那一題

這幾個領域這門課沒有教，但你回去很可能會碰到。每一個只給那一題，
而且多數時候它是你已經學過的原則換一個場合。

### 金流

- **卡號不要進你的系統。** 一律用第三方金流（Stripe、綠界、藍新這類），
  你的程式只收它回傳的結果。這一條是四條裡唯一要背的。
- **金額與數量一律在後端重算。** 前端送上來的價格不能信。
  （這就是「有人繞過你的畫面直接送請求，還擋不擋得住」。）
- **同一筆付款按兩次會怎樣。**
  （這就是兩個人同時搶最後一個名額，同一種問題。）
- **你怎麼知道錢真的收到了。** 要有一份對得起來的紀錄。
  （這就是「它說做完了，你自己再確認一次」。）

### 個資與公司資料

- **先問這些資料能不能離開公司，再問怎麼存。** 順序反過來的人會先做完才發現不能用。
- 問的時候把事情講成一句話：「我想做的這個東西，會把某某資料放到某某平台上。」
  不要只問「可不可以用 AI」，他們答不出來。
- 這一條跟影子 AI 是同一件事：資料是公司的，網址是你開的。

### 受監管行業（醫療、金融、兒少）

- **先問法遵，不要先做。** 這幾個行業的規定會直接決定這個東西能不能存在，
  而不是做完再補。
- 做完才發現要整個重來的成本，遠大於先問一通電話。

### 對外公開的內容與著作權

- **素材是不是你的。** AI 生成的圖、你抓來的照片、字型的授權，
  對外公開跟自己看是兩種不同的條件。
- 別人網站上的資料能不能抓、抓了能不能公開展示。
- （案例一最後那三件事裡的「照片改成自己拍並且自己託管」就是這一類。）

## 這張卡的用法

不是每次都跑全部。照你這個東西要給誰用：

| 要給誰用 | 跑哪幾題 |
|---|---|
| 只有我自己，沒放上網 | 上半四題 |
| 給同事或幾個人試用 | 八題，加上領域那一段跟你有關的 |
| 對外公開 | 八題、OWASP 十條、三種檢查裡的前兩種，以及領域全部看一次 |
| 作品有接 AI | 不管給誰用，都加上「接了 AI」那兩類 |

答不出來的那幾題，就是你下一輪的工作。
八題都答得出來不代表它沒有問題，只代表你知道自己檢查過哪幾件事，
所以出事的時候你查得到自己漏了哪一題。
