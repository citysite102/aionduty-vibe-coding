## Slide 1｜封面

**畫面**
AI ON DUTY 系列 ／ 大標「Vibe Coding」↓「Agentic Engineering」／
膠囊「打造可重複的 AI 開發流程」／「補上軟體基礎，從第一個作品一路做到交得出去。」／
講師 Samuel 高玉璁

**逐字稿**

> Hello，我是 Samuel。現在把一件事交辦給 AI，多數人都做得到，而且它真的會給你一整包東西：檔案建好、畫面跑得動，看起來像一回事。問題是那一包常常不是你要的。
>
> 你回頭改，它改一點，再改又歪到別的地方，幾輪之後東西越長越大，卻沒有更接近你要的樣子。卡住的不是它不會做，是這中間少了一套東西。
>
> 規則沒寫下來，它每一輪都在重新猜；什麼叫做完沒有定義，所以沒有人驗得了；做的跟驗的又是同一個，它說好了就是好了。
>
> 這門課要補的就是那一套。把需求講清楚只是第一段，後面還有規範怎麼寫下來、做的跟驗的怎麼分開、什麼時候可以放手。
>
> 這幾件事補起來，它每一輪才會往你要的方向走。畫面上這個箭頭就是這門課的路線。Vibe Coding 是你不用看懂程式碼也做得出東西；但做得出來，跟敢不敢交給別人用，是兩件事。
>
> 第二件叫 Agentic Engineering，而它需要一些軟體基礎：紅字在說什麼、資料存在哪、怎麼上線、每一版怎麼留。這門課會把那一段補起來。

## Slide 2｜動手前的前置作業

**畫面**
必備四樣：Claude Desktop、付費的 Claude 帳號、Git、GitHub 帳號。
選擇性兩樣：Warp、Pinterest 帳號。
底部 muted Callout：裝完 Claude Desktop 先登入一次，開得出對話框就算好了。

**逐字稿**

> 四樣要先有。都是幾分鐘就能弄好的事，但帳號要收驗證信、安裝檔要下載，臨時處理就會卡在這裡，而且卡的時間通常比做完還久。
>
> 第一個是 Claude Desktop，Mac 跟 Windows 都能裝。整門課的操作都在它上面，你的第一個作品也是從這裡做出來的。
>
> 第二個是付費的 Claude 帳號。這一項沒得跳過，沒有額度，Claude Code 跑不動。
>
> 兩種付法：訂閱制，月費二十美金起；或者到 Console 儲值，最低五美金，按用量扣。
>
> 這是我錄的時候的數字，方案名稱跟金額各家都在調，你去官網看一眼當下的就好。先有一種就行，後面成本那一段會講怎麼挑。
>
> 第三個是 Git。一路按下一步就好，裝完你不用開它。後面存檔跟上線的時候，Claude 會自己用到。第四個是 GitHub 帳號，免費。
>
> 作品要上線的話，程式碼會先送到這裡。下面兩樣是選擇性的。Warp 是比系統內建好用的終端機，終端機那一段會用到，不裝也走得完。Pinterest 這一項常被誤會。
>
> 它在這門課裡不是設計工具，是你「拿圖給它看」的來源。這門課教的講清楚方法裡有一條：不要用形容詞描述畫面。
>
> 你說「乾淨一點」「高級一點」，它只能猜；你直接丟一張參考圖過去，它看得到的東西比你講一百個字還多。這幾樣都不需要你現在懂它，先裝好就行。

## Slide 3｜四個階段，從看懂走到自己做出來

**畫面**
上方 sky 橫幅「能自己做出工具與網頁，而不只是會挑工具」，底下一行小字「下面四張卡是主課程，課前導讀與結語不算在內」。
2×2 四張卡：
01 章節二 Vibe Coding 與 Agentic Engineering ／
02 章節三、四 Claude Code 實作與網頁開發基礎 ／
03 章節四、六 CLAUDE.md、運作框架與成本 ／
04 章節六、八 Agent 分工、開發循環與三個實戰案例

**逐字稿**

> 整門課分成四個階段。第一個階段先把名詞分清楚：Vibe Coding 跟 Agentic Engineering 差在哪，市面上那些工具該怎麼挑。
>
> 這一段不動手，但後面你要挑工具、挑做法的時候，一直會用到這一段的判斷。第二個階段開始動手。
>
> 從只能問的對話框，走到一個能真的改你電腦裡檔案的 Agent。
>
> 這一段也會把做網頁需要知道的那幾樣基礎補上。補這些不是要你會寫程式。是因為驗收要靠你：它說「改好了」，你憑什麼相信？
>
> 看得懂它在動哪一塊，你才答得出這一題。第三個階段是把規則寫下來。
>
> 你不會想每次開新對話都重講一次「按鈕要用這個樣式」「檔案放這個資料夾」。這一段教你把這些寫成一份檔案，讓它每次進來都照同一套標準做事。
>
> 這一段也會講錢：它計價的單位是什麼，還有規則寫不寫、怎麼寫，怎麼反映在你的帳單上。第四個階段是分工跟循環。
>
> 一個 Agent 做事、一個 Agent 挑錯，然後讓它自己跑、自己驗、自己修，你只在它卡住的時候出手。
>
> 最後會有三個真實案例，從頭到尾看一次這套流程做出來的東西。這個順序跟很多人的直覺是相反的。
>
> 先分清楚概念，再動手，動完手才寫規則，最後才放手讓它自己跑。多數人想直接從第四個階段開始，因為那個最像「AI 幫我做完」。
>
> 但放手的前提是你驗得動，而驗得動這件事，是在第二、第三階段慢慢長出來的。順序跳過去，你只會得到一個跑得很快、你看不懂的東西。

## Slide 4｜帶走流程、規範、分工與交付成果

**畫面**
三張卡，每張的標題是一件做得到的事，下方「帶走的是⋯」格放它的證據：
01 走完一次從需求到上線的完整流程 → 一組網址 `mission-timer.vercel.app` ／
02 把規範與限制寫成它讀得到的規則 → 一個檔案 `mission-timer/CLAUDE.md` ／
03 讓做的人跟驗的人分開 → 一個角色 `.claude/agents/code-reviewer.md`

**逐字稿**

> 上面那一行是你會做什麼，底下那一格是做完之後手上有什麼。兩層要一起看，因為只講會做什麼，你自己驗不了。第一件是走完一次完整的流程。
>
> 我們會一起做一個任務計時器，從一句需求開始，一路做到部署上線。中間你會走過畫面怎麼做、資料存在哪裡、每一版怎麼留下來、最後怎麼送上網路。
>
> 這一趟走完，比做出一個計時器有用的是：東西壞掉的時候，你知道要去哪一層找。它的證據是一組網址，託管平台給你的那一個。
>
> 對方不用裝任何東西，打開瀏覽器就看得到。第二件是把規範跟限制寫成它讀得到的規則。哪些東西不准用、按鈕要用哪一組詞、設定要集中放在哪裡，這些現在都只存在你腦子裡，所以你每次開新對話都要重講一遍。
>
> 這一段教你把它們寫下來，而且寫成驗得出來的樣子，不是寫成一句感想。寫完之後你手上就有一個檔案，叫 CLAUDE.md。
>
> 它跟著專案走，換一台電腦、隔三個月回來，它都還在。第三件是讓做的人跟驗的人分開。你寫清楚什麼叫做完，主要那個 Agent 動手，換另一個角色來審一次，而且那個角色只准挑錯、不准自己改。
>
> 這個角色也是一個檔案，叫 code-reviewer。把關的標準寫在檔案裡，所以把關的人不必一直是你。
>
> 這三件事跟這三個檔案的關係，就是整門課的主張：腦子裡的判斷要變成檔案，它才留得住。理解三個月後會掉，檔案不會，而且還能照原樣再跑一次。
