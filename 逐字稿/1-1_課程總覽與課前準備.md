## Slide 1｜封面

**畫面**
AI ON DUTY 系列 ／ Vibe Coding ／ 膠囊「實戰：AI 開發流程完整指南」／
「補上軟體基礎，建立一套自己能重複用的 AI 開發流程。」／ 講師 Samuel 高玉璁

**逐字稿**

> Hello，我是 Samuel，歡迎來到這個單元。這門課叫 Vibe Coding 實戰。
>
> 先講在前面：這門課不是要把你訓練成工程師，也不是要你記一堆工具名稱。
>
> 會點進這門課的你，大概對怎麼跟 AI 講話已經很熟了啦。問它問題、請它寫一段文案、叫它幫你想個標題，這些都很順，順到你可能會覺得自己已經蠻會用 AI 的了。
>
> 但我們一開始跟它討論「做出一個東西」的時候，情況就不太一樣了。怎麼跟它配合才對，中間還有一大片模糊的灰色地帶。
>
> 那片地帶長什麼樣子？大概是這樣：它給你一段程式碼，你複製、貼上、打開來看，壞了，再把錯誤訊息貼回去問。來回五六次之後，你已經不知道現在這一版跟三十分鐘前差在哪裡了。
>
> 我先說，這不是能力問題，你沒有做錯什麼。真正的問題是，我們把一個能動手的工具，當成一個只能聊天的對象在用。它其實可以直接打開你電腦裡的檔案、自己跑、自己看到錯誤、自己改，可是我們還卡在中間，替它做複製貼上。
>
> 所以這門課要換掉的，是交代事情的方法，不是換一個更強的模型。你講需求的方式如果本身是模糊的，那模型再強，也只是把原本的混亂做得更快而已。

## Slide 2｜動手前的前置作業

**畫面**
必備四樣：Claude Desktop、付費的 Claude 帳號、Git、GitHub 帳號。
選擇性兩樣：Warp、Pinterest 帳號。
底部 muted Callout：裝完 Claude Desktop 先登入一次，開得出對話框就算好了。

**逐字稿**

> 四樣要先有。都是幾分鐘就能弄好的事，但帳號要收驗證信、安裝檔要下載，臨時處理就會卡在這裡，而且卡的時間通常比做完還久。
>
> 第一個是 Claude Desktop，Mac 跟 Windows 都能裝。整門課的操作都在它上面，你的第一個作品也是從這裡做出來的。
>
> 第二個是付費的 Claude 帳號。這一項沒得跳過，沒有額度，Claude Code 跑不動。兩種付法：訂閱 Pro，月費二十美金起；或者到 Console 儲值，最低五美金，按用量扣。先有一種就行，後面成本那一段會講怎麼挑。
>
> 第三個是 Git。一路按下一步就好，裝完你不用開它。後面存檔跟上線的時候，Claude 會自己用到。
>
> 第四個是 GitHub 帳號，免費。作品要上線的話，程式碼會先送到這裡。
>
> 下面兩樣是選擇性的。Warp 是比系統內建好用的終端機，終端機那一段會用到，不裝也走得完。
>
> Pinterest 這一項容易被誤會，它不是拿來當設計工具用的，是「拿圖給它看」的來源。這門課教的講清楚方法裡有一條：不要用形容詞描述畫面。你說「乾淨一點」「高級一點」，它只能猜；你直接丟一張參考圖過去，它看得到的東西比你講一百個字還多。
>
> 所以這四樣的共同點是，它們都不需要你懂，只需要你先裝好。真正要學的東西一樣都不在這一頁。

## Slide 3｜四個階段，從看懂走到自己做出來

**畫面**
2×2 四張卡：
01 章節二 Vibe Coding 與 Agentic Engineering ／
02 章節三、四 Claude Code 實作與網頁開發基礎 ／
03 章節五、六 CLAUDE.md 設計邏輯與運作框架 ／
04 章節七、八 Agent 團隊與開發循環架構

**逐字稿**

> 整門課分成四個階段。我先說一下為什麼是這個順序，因為它跟多數人的直覺相反。
>
> 第一個階段先把名詞分清楚：Vibe Coding 跟 Agentic Engineering 差在哪，市面上那些工具該怎麼挑。這一段不動手，但它決定你後面選的路對不對。
>
> 第二個階段開始動手。從只能問的對話框，走到一個能真的改你電腦裡檔案的 Agent。這一段也會把做網頁需要知道的那幾樣基礎補上。補這些不是要你會寫，是因為你要驗收它做的東西：它說「改好了」，你憑什麼相信？看得懂它在動哪一塊，你才答得出這一題。
>
> 第三個階段是把規矩寫下來。你不會想每次開新對話都重講一次「按鈕要用這個樣式」「檔案放這個資料夾」。這一段教你把這些寫成一份檔案，讓它每次進來都照同一套標準做事。
>
> 第四個階段是分工跟循環。一個 Agent 做事、一個 Agent 挑錯，然後讓它自己跑、自己驗、自己修，你只在它卡住的時候出手。
>
> 回頭看這四階段的順序：先分清楚概念，再動手，動完手才寫規矩，最後才放手讓它自己跑。很多人想從第四階段開始，因為那個最像「AI 幫我做完」。但放手的前提是你驗得動，而驗得動這件事是在第二、第三階段長出來的。順序跳過去，你只會得到一個跑得很快、你看不懂的東西。
>
> 每一張卡右上角標了它對應播放器裡的哪幾個章節，你要跳著看也找得到。

## Slide 4｜帶走：上線作品、專案手冊、審查角色

**畫面**
三張卡，每張下方有「帶走的是⋯」格：
01 一組網址 `mission-timer.vercel.app` ／
02 一個檔案 `mission-timer/CLAUDE.md` ／
03 一個角色 `.claude/agents/code-reviewer.md`

**逐字稿**

> 三樣都打得開、指得出來，不是「我好像懂了」。
>
> 第一樣是一個真的上線、有網址可以瀏覽的作品。我們會一起做一個任務計時器，從第一行程式碼開始，一路做到部署上線，最後拿到一組託管平台給你的網址。對方不用裝任何東西，打開瀏覽器就看得到。
>
> 第二樣是一個檔案，叫 CLAUDE.md。它是這個專案專屬的手冊，你把規範跟慣例寫進去，每次開新對話它都會自動讀到。這個檔案跟著專案走，換一台電腦、隔三個月回來，它都還在。
>
> 第三樣是一個角色，是一個叫 code-reviewer 的檔案。它的工作只有挑錯：你寫清楚什麼叫做完，主要那個 Agent 做完之後，換它來審一次。把關的標準寫在檔案裡，所以把關的人不必一直是你。
>
> 這三樣有一個共同點：它們都是檔案，都跟著專案走。換一台電腦、隔三個月回來，它們還在，而且還能照原樣再跑一次。這是我判斷一堂課有沒有上完的標準：你帶走的如果只有理解，那個東西三個月後就不見了。

> 那我們從第一個階段開始：Vibe Coding 到底是什麼，它跟 Agentic Engineering 又差在哪裡。
