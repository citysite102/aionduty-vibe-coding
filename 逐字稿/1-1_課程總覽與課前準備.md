# 單元 1-1｜課程總覽與課前準備

Slide 1-4 ／ 4 頁 ／ 章節一 課前導讀

## Slide 1｜封面

**畫面**
AI ON DUTY 系列 ／ Vibe Coding ／ 膠囊「實戰：AI 開發流程完整指南」／
「補上軟體基礎，建立一套自己能重複用的 AI 開發流程。」／ 講師 Samuel 高玉璁

**逐字稿**

> 這門課叫 Vibe Coding 實戰。
>
> 你大概已經很會用 AI 對話框了。問它問題、請它寫一段文案、叫它幫你想標題，這些都很順。但只要事情一牽涉到「做出一個東西」，流程就會變成這樣：它給你一段程式碼，你複製、貼上、打開來看，壞了，再把錯誤訊息貼回去問。來回五六次之後，你已經不知道現在這一版跟三十分鐘前差在哪裡了。
>
> 問題不在你不會寫程式，在於你把一個能動手的工具，當成一個只能聊天的對象在用。這門課要換的就是這一件事。

**【轉場 → Slide 2】**

> 在開始之前，有四樣東西要先準備好。

## Slide 2｜動手前的前置作業

**畫面**
必備四樣：Claude Desktop、付費的 Claude 帳號、Git、GitHub 帳號。
選擇性兩樣：Warp、Pinterest 帳號。
底部 muted Callout：裝完 Claude Desktop 先登入一次，開得出對話框就算好了。

**逐字稿**

> 四樣要先有。都是幾分鐘就能弄好的事，但帳號要收驗證信、安裝檔要下載，臨時處理就會卡在這裡。
>
> 第一個是 Claude Desktop，Mac 跟 Windows 都能裝。整門課的操作都在它上面，你的第一個作品也是從這裡做出來的。
>
> 第二個是付費的 Claude 帳號。這一項沒得跳過，沒有額度，Claude Code 跑不動。兩種付法：訂閱 Pro，月費二十美金起；或者到 Console 儲值，最低五美金，按用量扣。先有一種就行，後面成本那一段會講怎麼挑。
>
> 第三個是 Git。一路按下一步就好，裝完你不用開它。後面存檔跟上線的時候，Claude 會自己用到。
>
> 第四個是 GitHub 帳號，免費。作品要上線的話，程式碼會先送到這裡。
>
> 下面兩樣是選擇性的。Warp 是比系統內建好用的終端機，終端機那一段會用到，不裝也走得完。Pinterest 則不是拿來當設計工具用的，它是「拿圖給它看」的來源。這門課教的講清楚方法之一，就是不要用形容詞描述畫面，直接把參考圖丟給它，那比你講一百個字準。

**【轉場 → Slide 3】**

> 東西準備好了，先看一下這門課會帶你走到哪裡。

## Slide 3｜四個階段，從看懂走到自己做出來

**畫面**
2×2 四張卡：
01 章節二 Vibe Coding 與 Agentic Engineering ／
02 章節三、四 Claude Code 實作與網頁開發基礎 ／
03 章節五、六 CLAUDE.md 設計邏輯與運作框架 ／
04 章節七、八 Agent 團隊與開發循環架構

**逐字稿**

> 整門課分成四個階段。
>
> 第一個階段先把名詞分清楚：Vibe Coding 跟 Agentic Engineering 差在哪，市面上那些工具該怎麼挑。這一段不動手，但它決定你後面選的路對不對。
>
> 第二個階段開始動手。從只能問的對話框，走到一個能真的改你電腦裡檔案的 Agent。這一段也會把做網頁需要知道的那幾樣基礎補上，因為你要驗收它做的東西，就得看得懂它在做什麼。
>
> 第三個階段是把規矩寫下來。你不會想每次開新對話都重講一次「按鈕要用這個樣式」「檔案放這個資料夾」。這一段教你把這些寫成一份檔案，讓它每次進來都照同一套標準做事。
>
> 第四個階段是分工跟循環。一個 Agent 做事、一個 Agent 挑錯，然後讓它自己跑、自己驗、自己修，你只在它卡住的時候出手。
>
> 每一張卡右上角標了它對應播放器裡的哪幾個章節，你要跳著看也找得到。

**【轉場 → Slide 4】**

> 這四個階段走完，你手上會實際多出三樣東西。

## Slide 4｜帶走：上線作品、專案手冊、審查角色

**畫面**
三張卡，每張下方有「帶走的是⋯」格：
01 一組網址 `mission-timer.vercel.app` ／
02 一個檔案 `mission-timer/CLAUDE.md` ／
03 一個角色 `.claude/agents/code-reviewer.md`

**逐字稿**

> 整門課走完，你手上會多出三樣東西。三樣都打得開、指得出來，不是「我好像懂了」。
>
> 第一樣是一個真的上線、有網址可以瀏覽的作品。我們會一起做一個任務計時器，從第一行程式碼開始，一路做到部署上線，最後拿到一組託管平台給你的網址。對方不用裝任何東西，打開瀏覽器就看得到。
>
> 第二樣是一個檔案，叫 CLAUDE.md。它是這個專案專屬的手冊，你把規範跟慣例寫進去，每次開新對話它都會自動讀到。這個檔案跟著專案走，換一台電腦、隔三個月回來，它都還在。
>
> 第三樣是一個角色，是一個叫 code-reviewer 的檔案。它的工作只有挑錯：你寫清楚什麼叫做完，主要那個 Agent 做完之後，換它來審一次。把關的標準寫在檔案裡，所以把關的人不必一直是你。
>
> 這三樣東西你之後都可以指著說「這是我做的」。

**【轉場 → Slide 5，進章節二】**

> 那我們從第一個階段開始：Vibe Coding 到底是什麼，它跟 Agentic Engineering 又差在哪裡。

### 1.【缺漏】階段 03、04 的名稱各漏掉那兩章的一半

- 階段 03 叫「CLAUDE.md 設計邏輯與運作框架」，標的是章節五、六。但**章節五有兩個單元在講 token 計費與成本**（5-2、以及 11c 那一串），階段名裡完全沒有；章節六的主題是診斷、健檢、轉移，也不在名字上。
- 階段 04 叫「Agent 團隊與開發循環架構」，標的是章節七、八。但**章節八有四個單元是三個實戰案例**（8-5 到 8-8），階段名沒提。
- 這一頁自己的檔頭註解寫著「改章節結構時，chapters 那一欄要重新核對一次」。本次會期章節五、六的單元切點動過（多出 6-3），名稱沒跟著核。
- **影響**：這一頁是學員的地圖，看完會以為課程沒有成本那一段、也沒有案例。
- **建議**：階段 03 補上成本，階段 04 補上案例。例如「CLAUDE.md、運作框架與成本」「Agent 分工、開發循環與三個實戰案例」。

### 2.【缺漏】階段 01 涵蓋章節二，但章節一沒有任何階段涵蓋

四張卡標的是章節二到八，章節一（課前導讀，也就是這個單元自己）與章節九（結語）不在圖上。學員看到「四個階段」會以為那是全部。低優先，但如果要補，最省事的是在卡片上方那條橫幅補一句說明這四張卡指的是主課程。

### 3.【語法】`02a_CoreAssets` 第三張卡的描述句子太長

- 現在：「你寫清楚什麼叫做完，它自己驗、沒過自己修，全過了才回來找你。再配一個只負責挑錯的審查角色。」
- 三個逗號串四個短句，念的時候要換兩次氣，而且「再配一個」接得有點硬。
- **建議**：「你寫清楚什麼叫做完，它自己驗、沒過自己修，全過了才回來找你。挑錯的工作交給另一個角色。」
