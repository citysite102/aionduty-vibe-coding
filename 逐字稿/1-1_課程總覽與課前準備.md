## Slide 1｜封面

**畫面**
AI ON DUTY 系列 ／ Vibe Coding ／ 膠囊「實戰：AI 開發流程完整指南」／
「補上軟體基礎，建立一套自己能重複用的 AI 開發流程。」／ 講師 Samuel 高玉璁

**逐字稿**

> Hello，我是 Samuel。這門課叫 Vibe Coding 實戰。
>
> 先講在前面：這門課不是要把你訓練成工程師，也不是要你記一堆工具名稱。
>
> 會點進這門課的你，大概對怎麼跟 AI 講話已經很熟了啦。問它問題、請它寫一段文案、叫它幫你想個標題，這些都很順，順到你可能會覺得自己已經蠻會用 AI 的了。
>
> 但我們一開始跟它討論「做出一個東西」的時候，情況就不太一樣了。怎麼跟它配合才對，中間還有一大片模糊的灰色地帶。
>
> 那片地帶長什麼樣子？大概是這樣：它給你一段程式碼，你複製、貼上、打開來看，壞了，再把錯誤訊息貼回去問。來回五六次之後，你已經不知道現在這一版跟三十分鐘前差在哪裡了。
>
> 我先說，這不是能力問題，你沒有做錯什麼。比較像是我們手上這個工具，其實可以自己動手，但我們一直把它當成一個只能聊天的對象在用。它可以直接打開你電腦裡的檔案、自己跑、自己看到錯誤、自己改，可是我們還卡在中間，替它做複製貼上。
>
> 所以這門課要換掉的是你交辦工作的方式。換一個更強的模型幫不上這個忙，需求講得模糊，模型再強，也只是把原本的混亂做得更快而已。
>
> 課名叫 Vibe Coding，講的是你不用看懂程式碼也做得出東西。但只有這一半還不夠用。做得出來，跟敢不敢交給別人用，是兩件事。第二件有它自己的名字，叫 Agentic Engineering。這門課兩件都要講，而它們的起點是同一個，就是你怎麼把你要什麼講清楚。

## Slide 2｜動手前的前置作業

**畫面**
必備四樣：Claude Desktop、付費的 Claude 帳號、Git、GitHub 帳號。
選擇性兩樣：Warp、Pinterest 帳號。
底部 muted Callout：裝完 Claude Desktop 先登入一次，開得出對話框就算好了。

**逐字稿**

> 四樣要先有。都是幾分鐘就能弄好的事，但帳號要收驗證信、安裝檔要下載，臨時處理就會卡在這裡，而且卡的時間通常比做完還久。
>
> 第一個是 Claude Desktop，Mac 跟 Windows 都能裝。整門課的操作都在它上面，你的第一個作品也是從這裡做出來的。
>
> 第二個是付費的 Claude 帳號。這一項沒得跳過，沒有額度，Claude Code 跑不動。兩種付法：訂閱制，月費二十美金起；或者到 Console 儲值，最低五美金，按用量扣。這是我錄的時候的數字，方案名稱跟金額各家都在調，你去官網看一眼當下的就好。先有一種就行，後面成本那一段會講怎麼挑。
>
> 第三個是 Git。一路按下一步就好，裝完你不用開它。後面存檔跟上線的時候，Claude 會自己用到。
>
> 第四個是 GitHub 帳號，免費。作品要上線的話，程式碼會先送到這裡。
>
> 下面兩樣是選擇性的。Warp 是比系統內建好用的終端機，終端機那一段會用到，不裝也走得完。
>
> Pinterest 這一項常被誤會。它在這門課裡不是設計工具，是你「拿圖給它看」的來源。這門課教的講清楚方法裡有一條：不要用形容詞描述畫面。你說「乾淨一點」「高級一點」，它只能猜；你直接丟一張參考圖過去，它看得到的東西比你講一百個字還多。
>
> 這幾樣都不需要你現在懂它，先裝好就行。要學的東西一樣都不在這一頁上。

> 東西準備好了，先看一下這門課會帶你走到哪裡。

## Slide 3｜四個階段，從看懂走到自己做出來

**畫面**
2×2 四張卡：
01 章節二 Vibe Coding 與 Agentic Engineering ／
02 章節三、四 Claude Code 實作與網頁開發基礎 ／
03 章節五、六 CLAUDE.md 設計邏輯與運作框架 ／
04 章節七、八 Agent 團隊與開發循環架構

**逐字稿**

> 整門課分成四個階段。
>
> 第一個階段先把名詞分清楚：Vibe Coding 跟 Agentic Engineering 差在哪，市面上那些工具該怎麼挑。這一段不動手，但後面你要挑工具、挑做法的時候，一直會用到這一段的判斷。
>
> 第二個階段開始動手。從只能問的對話框，走到一個能真的改你電腦裡檔案的 Agent。這一段也會把做網頁需要知道的那幾樣基礎補上。補這些不是要你會寫程式。是因為驗收要靠你：它說「改好了」，你憑什麼相信？看得懂它在動哪一塊，你才答得出這一題。
>
> 第三個階段是把規矩寫下來。你不會想每次開新對話都重講一次「按鈕要用這個樣式」「檔案放這個資料夾」。這一段教你把這些寫成一份檔案，讓它每次進來都照同一套標準做事。
>
> 第四個階段是分工跟循環。一個 Agent 做事、一個 Agent 挑錯，然後讓它自己跑、自己驗、自己修，你只在它卡住的時候出手。
>
> 這個順序跟很多人的直覺是相反的。先分清楚概念，再動手，動完手才寫規矩，最後才放手讓它自己跑。多數人想直接從第四個階段開始，因為那個最像「AI 幫我做完」。但放手的前提是你驗得動，而驗得動這件事，是在第二、第三階段慢慢長出來的。順序跳過去，你只會得到一個跑得很快、你看不懂的東西。

**【轉場 → Slide 4】**

> 這四個階段走完，你會多出三件做得到的事。

## Slide 4｜帶走：流程、規範、分工，各配一個檔案

**畫面**
三張卡，每張的標題是一件做得到的事，下方「帶走的是⋯」格放它的證據：
01 走完一次從需求到上線的完整流程 → 一組網址 `mission-timer.vercel.app` ／
02 把規範與限制寫成它讀得到的規則 → 一個檔案 `mission-timer/CLAUDE.md` ／
03 讓做的人跟驗的人分開 → 一個角色 `.claude/agents/code-reviewer.md`

**逐字稿**

> 三件事，而且每一件都配一個你打得開的檔案，不是「我好像懂了」。
>
> 第一件是走完一次完整的流程。我們會一起做一個任務計時器，從一句需求開始，一路做到部署上線。中間你會走過畫面怎麼做、資料存在哪裡、每一版怎麼留下來、最後怎麼送上網路。這一趟走完，比做出一個計時器有用的是：東西壞掉的時候，你知道要去哪一層找。
>
> 它的證據是一組網址，託管平台給你的那一個。對方不用裝任何東西，打開瀏覽器就看得到。
>
> 第二件是把規範跟限制寫成它讀得到的規則。哪些東西不准用、按鈕要用哪一組詞、設定要集中放在哪裡，這些現在都只存在你腦子裡，所以你每次開新對話都要重講一遍。這一段教你把它們寫下來，而且寫成驗得出來的樣子，不是寫成一句感想。
>
> 它的證據是一個檔案，叫 CLAUDE.md。它跟著專案走，換一台電腦、隔三個月回來，它都還在。
>
> 第三件是讓做的人跟驗的人分開。你寫清楚什麼叫做完，主要那個 Agent 動手，換另一個角色來審一次，而且那個角色只准挑錯、不准自己改。
>
> 它的證據是一個角色檔案，叫 code-reviewer。把關的標準寫在檔案裡，所以把關的人不必一直是你。
>
> 這三件事跟這三個檔案的關係，其實就是整門課的主張：腦子裡的判斷要變成檔案，它才留得住。理解三個月後會掉，檔案不會，而且還能照原樣再跑一次。
