## Slide 20｜紅字不是壞事，它在告訴你哪裡卡住

**畫面**
開場一句「先認得出哪一行是紅字就好」／左欄「紅字長這樣」（對話模擬：`ls` 打錯字、紅色錯誤訊息，第 3 拍才多出「它自己說要改」那一行）／右欄「輪到你出手的時候，兩個習慣」與一句可以直接抄的提問／頁尾 sky Callout「同一件事會出現在三個地方，長得不一樣」，裡面三個示意畫面（Claude Code 對話、瀏覽器 Console、終端機），每一個都標出紅色那一行。

**逐字稿**

> 紅字一出現就不敢動，這是我最常看到的一個反應。螢幕上冒出一片紅色，直覺就是「我把它弄壞了」，然後關掉重來。
>
> 所以這一頁先做一件很單純的事：把它認出來。為什麼先做這個？因為多數人卡住不是因為看不懂那段英文，是看到紅色就不敢再往下看。
>
> 左邊這個就是你會看到的畫面。你打的是「幫我看看這個資料夾裡有什麼」，它去跑了一行指令，可是資料夾名字打錯了，少一個字母。中間那一行紅色的就是紅字，它說 No such file or directory，沒有這個檔案或目錄。
>
> 你現在要會的就這樣而已：指得出哪一行是紅的。不用知道 ls 是什麼，也不用讀懂那句英文。
>
> 認得出來之後，第二件事：這種紅字多數時候不用你處理。
>
> 你看畫面上多出來的這一行，它自己讀了那句紅字，然後說「資料夾名稱好像拼錯了，我改成 my-project 再試一次」。現在的 Agent 大多會這樣，撞到錯就自己回頭改，你只要看著。
>
> 那什麼時候換你出手？我給你一個數得出來的判準：同一段紅字出現第三次。
>
> 意思是它改了一次、重跑，紅字跟剛才一模一樣；再改一次、再重跑，紅字還是一模一樣。紅字沒變，代表它前面那兩次動的都不是真正出問題的地方。你讓它試第四次，多半還是同一個結果。這時候停下來，換你。
>
> 換你出手的時候，右邊那兩個習慣防的是同一件事：你在還沒搞懂之前就先動手。
>
> 底下那句可以直接抄的提問，我想講它為什麼這樣寫。它要了三樣東西：白話解釋、三個可能原因、具體解法。中間那個「三個」是關鍵。錯誤訊息講的多半是症狀，同一個症狀的成因不只一種，你不逼它一次列三個，它就會咬著第一個猜測改半天，而你還以為它在修。
>
> 最後這三個畫面，是同一件事出現在三個不同的地方。你看它們長得完全不一樣：一個是對話、一個是瀏覽器的開發者工具、一個是終端機。但每一個裡面都有那一格紅色的。
>
> 第一個你剛才已經看過了。第二個要等你的網頁真的怪怪的才用得到，按 F12 打開，Mac 是 Cmd 加 Opt 加 I。第三個要走完選修那一段才有。
>
> 所以位置會換，你要做的不會換：整段複製，貼回對話框。

**這頁的教學意圖**：先學會認出紅字，再知道它多半會自己修；換你出手的判準是「同一段紅字出現第三次」。
**預估時間**：4 分鐘

## Slide 21｜兩個程式要講話，得先講好格式

**畫面**
膠囊「現在開瀏覽器」（下面那個網址現在就打得開）／餐廳點單系統的比喻橫幅／左卡「什麼是 API？」含 Request 與 Response 流程圖、一支免金鑰的真實網址、以及「開頭那個 https 是什麼」／右卡「認識 JSON 格式（點單明細）」／頁尾 Callout「多數 API 還要一把金鑰」。

**逐字稿**

> API、JSON、Request、Response，四個英文詞一起出現的時候最容易讓人直接放棄。所以這一頁整個用餐廳吃飯來想，你聽完會發現它其實只有一來一回兩件事。
>
> 你填一張點單紙送進廚房，廚房做好之後端出餐點跟明細單。點單紙這一趟叫 Request，端回來的那一趟叫 Response。就這樣。
>
> 左邊那張小圖就是這一來一回，回來的時候帶著一個 200 OK，那是「成功」的代號。
>
> 這個比喻只負責一件事：讓你知道中間有兩趟，一趟去、一趟回。廚房裡怎麼煮它不管，那是對方那台電腦的事，你看不到也管不到。你能決定的只有點單紙上寫了什麼。
>
> 卡片下面那一行是一支真的 API，台北今天的日出跟日落時間。它現在就打得開，不用申請任何東西。
>
> 你把那串網址整個複製，貼進瀏覽器的網址列，按 Enter。畫面上會直接噴出一堆大括號，那個就是右邊那張圖在講的東西。你現在看不懂沒關係，我只要你先看到它真的存在。
>
> 開頭那個 https 我要特別講一下，因為它跟 API 很容易被混在一起。
>
> API 管的是內容：這一支要你填哪些欄位、會回什麼給你。http 管的是另一件事，怎麼把這張點單紙送過去，而那條路是所有網站共用的，跟你打的是哪一支 API 沒有關係。https 就是同一條路加了一層加密。
>
> 所以你之後拿到一支 API 的網址，它是 http 開頭、又要你把金鑰放在網址裡，那就先不要用。中間經過的機器看得到你送了什麼，那串金鑰也在裡面。
>
> 右邊是 JSON。你不用記它的規則，看形狀就好：一行一件事，左邊是欄位的名字，右邊是值。送出去那一半寫了品項、份量、不要蔥、桌號；回來那一半寫了狀態、金額、還要等多久。
>
> 為什麼要拆得這麼細？因為兩邊是兩台電腦。你跟人說「大碗牛肉麵不要蔥」，對方自己會拆；程式不會，所以每一件事都要有自己的格子。
>
> 最後這一塊是金鑰。剛才那一支不用金鑰，所以你現在就打得開；但多數 API 要先申請一組，接在網址後面，或者放在另一個地方叫 Header。那串字等於帳號密碼。
>
> 畫面上列了三件不要做的事，我只挑最後一條講，因為前兩條你會記得，最後一條你會跟自己討價還價。
>
> 那一條是：真的貼出去過，就當它已經外洩。很多人會想「應該沒人看到吧」，然後就放著。判準很單純：你不知道有沒有人看到，就是已經外洩。重產一組是三十秒，你猶豫的時間比那個還長。

**這頁的教學意圖**：用餐廳的比喻把 Request／Response 與 JSON 的形狀認起來，並且知道金鑰等於密碼。
**預估時間**：5 分鐘

## Slide 22｜讓 Agent 幫你讀文件並串接

**畫面**
左卡：兩段說明與「三個步驟」清單。右卡：終端協作模擬，使用者貼一份文件網址，Agent 顯示 Fetching，接著一塊「下面這段不用讀懂」的提示，再來是一段程式碼。

**逐字稿**

> 這一頁處理的是「想接外面的資料，可是文件是英文的，而且好長」這件事。
>
> 過去串一支 API 最花時間的，往往不是寫程式，是翻那份厚厚的官方英文手冊，搞懂參數名稱到底叫什麼、認證要怎麼帶。
>
> 現在你可以把文件網址直接餵給 Claude Code。它會自己去解析那個網頁，把關鍵的型別抓出來，寫出一份可以直接跑的呼叫程式碼。
>
> 右邊是模擬的畫面。使用者說：幫我閱讀這份文件，然後寫一個能夠發送訊息給 Claude 的腳本，後面貼上文件網址。它回的第一行是 Fetching，正在抓那一頁，抓完說：我已經順利下載並閱讀了 Messages API 的文件。
>
> 下面那一大塊程式碼不用讀懂。你只要盯那三個字：model、max_tokens、messages。它們不是它自己編的，是從那份文件裡抄下來的。記住它們是從哪裡來的，下一頁你就知道怎麼驗它有沒有抄對。
>
> 這裡有一件事要記著，後面每一次「AI 幫你查資料」都適用：它讀的是當下抓到的那一頁。
>
> 抓錯版本，或者根本抓到別的頁面，它不會告訴你。它會照樣寫出一段看起來很像樣的程式碼給你，而那段程式碼看起來跟正確的版本一模一樣，你從外觀上分不出來。
>
> 省掉讀文件的時間是真的，但驗收這件事沒有跟著被省掉。下一頁那四個定位點，是你自己要對的。

**這頁的教學意圖**：把文件網址交給它可以省掉讀英文手冊，但它抓錯頁不會告訴你，所以驗收的責任沒有轉移。
**預估時間**：3 分鐘

## Slide 23｜API 文件四項重點

**畫面**
膠囊「現在開瀏覽器」／左欄仿瀏覽器的文件畫面，標了 1 到 4／右欄四張卡逐一對應，最後一塊是驗收的三個步驟。

**逐字稿**

> 每一份 API 文件其實都在回答同樣四個問題。左邊這一頁就是上一頁那份 Messages API 的文件，四個記號標在它們實際出現的位置上。
>
> 這四個不是隨便挑的，它們各自擋掉一種失敗：打去錯的地方、沒證明你是誰、少填一個欄位、拿錯回來的值。四個都對了，這一支就通了。
>
> 第一，找端點與方法。先看要打去哪、用什麼動作。畫面上是 POST 加上斜線 v1 斜線 messages。POST 代表送資料出去，後面那串網址就是這一支 API 的門牌。
>
> 第二，看認證方式。幾乎每一支 API 都要你證明你是誰，通常是在 Header 這一區夾帶一把金鑰。這裡叫 x-api-key，後面那個 YOUR_API_KEY 就是上一頁講的那一串。
>
> 第三，掌握必填參數。文件會標示哪些欄位是 required。這一支標了三個紅色的 required：model、messages、max_tokens。下面那個 temperature 是 optional，可填可不填。少一個必填，請求就會被打回來。
>
> 這幾個欄位名稱會隨著版本增減，所以要練的是「去文件上找必填」這個動作，不是背這三個字。
>
> 第四，抄範例回應。直接看官方給的 Example，就知道它回來的東西長什麼樣、該從哪個欄位取值。
>
> 四個定位點看完，右下角這一塊是怎麼驗收。方法就三步。
>
> 一，把文件上標 required 的欄位抄下來，這一支是 model、messages、max_tokens。
>
> 二，回頭數它寫的那幾行，三個都在才算過。上一頁那一段是過的，你可以翻回去對一次。
>
> 三，少了就這樣講：「你少填了 max_tokens，文件上這個是必填，補上去再跑一次給我看。」
>
> 這就是整段的用法。你不用讀懂那份英文文件的每一段，只要在四個固定的位置上找到四樣東西，拿它們去對它交出來的結果。這三步不需要你會寫程式，只需要你會數。

**這頁的教學意圖**：不用讀懂文件，只要在四個固定位置找到四樣東西，拿去對它交出來的結果。
**預估時間**：5 分鐘
