## Slide 20｜紅字不是壞事，它在告訴你哪裡卡住

**畫面**
左欄「你會看到的樣子」（對話框模擬：ls 打錯字、紅色錯誤訊息、它自己說要改回去）／右欄「輪到你出手的時候，兩個習慣」與一句可以直接抄的提問／頁尾 sky Callout「紅字會出現在三個地方」。

**逐字稿**

> 紅字一出現就不敢動，這是我最常看到的一個反應。螢幕上冒出一片紅色，直覺就是「我把它弄壞了」，然後關掉重來。
>
> 我先把這個感覺換掉。紅字是免費的線索，它已經替你指出卡在哪一行了。難查的是反過來那一種：它說做完了，你打開卻不對，畫面上一片乾淨，你連從哪裡開始找都不知道。所以看到紅字，其實是這兩種裡面比較好的那一種。
>
> 左邊那個例子只要看最後一行。前面三行是它打錯資料夾名字、系統回它沒有這個檔案，那些你不用管。重點在最後一行：它自己看懂了那句紅字，然後說我改一下再試一次。
>
> 多數時候就是這樣，你只要看著。那什麼時候換你出手？畫面上給的判準是它連續試了兩三次還在同一個地方繞。繞的意思是它每次改的東西都不一樣，這次改檔名、下次改路徑、再下次叫你重裝，可是紅字從頭到尾沒變。紅字沒變，代表它還沒找到真正的那一個點。
>
> 右邊那兩個習慣我只補一句：它們防的是同一件事，你在還沒搞懂之前就先動手。
>
> 底下那句可以直接抄的提問，我想講它為什麼這樣寫。它要了三樣東西：白話解釋、三個可能原因、具體解法。中間那個「三個」是關鍵。錯誤訊息講的多半是症狀，同一個症狀的成因不只一種，你不逼它一次列三個，它就會咬著第一個猜測改半天，而你還以為它在修。
>
> 最後那一塊是位置。第一個你剛才已經看過了，就是 Claude Code 的對話裡。瀏覽器那個要等你的網頁真的怪怪的才用得到。終端機那個要走完選修那一段才有。
>
> 三個地方長得不一樣，但你要做的是同一件事：整段複製，貼回對話框。位置會換，動作不會換。

**這頁的教學意圖**：紅字是它主動給你的線索，不用看懂，只要知道整段複製貼回去；真正難查的是沒有紅字那一種。
**預估時間**：4 分鐘

## Slide 21｜兩個程式要講話，得先講好格式

**畫面**
膠囊「現在開瀏覽器」／餐廳點單系統的比喻橫幅／左卡「什麼是 API？（服務生）」含 Request 與 Response 流程圖／右卡「認識 JSON 格式（點單明細）」／頁尾 Callout「網址裡的 your_key 是你的密碼」。

**逐字稿**

> API、JSON、Request、Response，四個英文詞一起出現的時候最容易讓人直接放棄。所以這一頁整個用餐廳吃飯來想，你聽完會發現它其實只有一來一回兩件事。
>
> 你填一張點單紙送進廚房，廚房做好之後端出餐點跟明細單。點單紙這一趟叫 Request，端回來的那一趟叫 Response。就這樣。
>
> 左邊是 API。API 是應用程式介面，在這個比喻裡它是服務生。你在瀏覽器這一邊點餐，服務生把指令傳到廚房，也就是另一台電腦，然後端著菜跟帳單回到你面前。下面那張小圖就是這一來一回，回來的時候帶著一個 200 OK。
>
> 卡片下面那一行是真的網址，環境部的空氣品質資料。這種網址就是一支 API 的點單地址。
>
> 這一行上面有兩個東西要講。先講開頭那個 https。http 是兩台電腦講話的那一套規矩：點單紙上要寫哪些欄位、怎麼送過去、怎麼回話。https 是同一套規矩，多包了一層加密。走 http，中間經過的機器看得到你送了什麼；走 https，它們只看得到一堆亂碼。所以帶金鑰的請求一律走 https，你平常在網址列看到的那個鎖頭，講的就是這件事。
>
> 右邊是 JSON。它是一張格式被標準化過的點單明細。左半邊這一段是送出去的點單：item 是牛肉麵，size 是大碗，no_scallions 是 true，也就是不要蔥，table_number 是十二號桌。右半邊是廚房回來的：status 已出菜，price 220，ready_time 一分零五秒。
>
> 形狀就是這樣，一個欄位鍵配一個欄位值，一行一件事。大白話講，它就是把事情列得清清楚楚，這樣電腦不用去猜人類那些模糊的話。
>
> 最後這一塊是金鑰。網址結尾那個 your_key 要換成你自己申請的一串字，多數 API 都要先申請一組。那串字等於你的帳號密碼，別人拿到就能用你的額度、動你的資料。
>
> 所以三件事：不要貼進聊天室或公開的頁面；不要跟著程式碼一起推上 GitHub；真的貼出去過就當它已經外洩，回後台重新產一組，舊的作廢。
>
> 最後那一條請不要跟自己討價還價。很多人會想「應該沒人看到吧」，然後就放著。判準很單純：你不知道有沒有人看到，就是已經外洩。重產一組是三十秒的事。

**這頁的教學意圖**：用餐廳的比喻把 Request／Response 與 JSON 的形狀認起來，並且知道金鑰等於密碼。
**預估時間**：5 分鐘

## Slide 22｜讓 Agent 幫你讀文件並串接

**畫面**
左卡：兩段說明與「三個步驟」清單。右卡：終端協作模擬，使用者貼一份文件網址，Agent 顯示 Fetching，接著一塊「下面這段不用讀懂」的提示，再來是一段程式碼。

**逐字稿**

> 這一頁處理的是「想接外面的資料，可是文件是英文的，而且好長」這件事。
>
> 過去串一支 API 最花時間的，往往不是寫程式，是翻那份厚厚的官方英文手冊，搞懂參數名稱到底叫什麼、認證要怎麼帶。
>
> 現在你可以把文件網址直接餵給 Claude Code。它會自己去解析那個網頁，把關鍵的型別抓出來，寫出一份可以直接跑的呼叫程式碼。
>
> 三個步驟就在左下角：給網址、它自己去查、產出程式碼。
>
> 右邊是模擬的畫面。使用者說：幫我閱讀這份文件，然後寫一個能夠發送訊息給 Claude 的腳本，後面貼上文件網址。它回的第一行是 Fetching，正在抓那一頁，抓完說：我已經順利下載並閱讀了 Messages API 的文件。
>
> 下面那一大塊程式碼，畫面上已經替你講了：不用讀懂。
>
> 要看的只有一件事，這幾行裡的 model、max_tokens、messages，都是它從那份文件裡抄下來的，不是它自己編的。這三個字等一下會再出現一次，你先記得它們是從哪裡來的。
>
> 這裡有一件事要記著，後面每一次「AI 幫你查資料」都適用：它讀的是當下抓到的那一頁。
>
> 抓錯版本，或者根本抓到別的頁面，它不會告訴你。它會照樣寫出一段看起來很像樣的程式碼給你，而那段程式碼看起來跟正確的版本一模一樣，你從外觀上分不出來。
>
> 省掉讀文件的時間是真的，但驗收這件事沒有跟著被省掉。下一頁那四個定位點，是你自己要對的。

**這頁的教學意圖**：把文件網址交給它可以省掉讀英文手冊，但它抓錯頁不會告訴你，所以驗收的責任沒有轉移。
**預估時間**：3 分鐘

## Slide 23｜API 文件四項重點

**畫面**
膠囊「現在開瀏覽器」／左欄仿瀏覽器的文件畫面，標了 1 到 4／右欄四張卡逐一對應，最後一塊是驗收的三個步驟。

**逐字稿**

> 每一份 API 文件其實都在回答同樣四個問題。左邊這一頁就是上一頁那份 Messages API 的文件，四個記號標在它們實際出現的位置上。
>
> 第一，找端點與方法。先看要打去哪、用什麼動作。畫面上是 POST 加上斜線 v1 斜線 messages。POST 代表送資料出去，後面那串網址就是這一支 API 的門牌。
>
> 第二，看認證方式。幾乎每一支 API 都要你證明你是誰，通常是在 Header 這一區夾帶一把金鑰。這裡叫 x-api-key，後面那個 YOUR_API_KEY 就是上一頁講的那一串。
>
> 第三，掌握必填參數。文件會標示哪些欄位是 required。這一支標了三個紅色的 required：model、messages、max_tokens。下面那個 temperature 是 optional，可填可不填。少一個必填，請求就會被打回來。
>
> 這幾個欄位名稱會隨著版本增減，所以要練的是「去文件上找必填」這個動作，不是背這三個字。
>
> 第四，抄範例回應。直接看官方給的 Example，就知道它回來的東西長什麼樣、該從哪個欄位取值。
>
> 四個定位點看完，右下角這一塊是怎麼驗收。方法就三步。
>
> 一，把文件上標 required 的欄位抄下來，這一支是 model、messages、max_tokens。
>
> 二，回頭數它寫的那幾行，三個都在才算過。上一頁那一段是過的，你可以翻回去對一次。
>
> 三，少了就這樣講：「你少填了 max_tokens，文件上這個是必填，補上去再跑一次給我看。」
>
> 這就是整段的用法。你不用讀懂那份英文文件的每一段，只要在四個固定的位置上找到四樣東西，拿它們去對它交出來的結果。這三步不需要你會寫程式，只需要你會數。

**這頁的教學意圖**：不用讀懂文件，只要在四個固定位置找到四樣東西，拿去對它交出來的結果。
**預估時間**：5 分鐘

### 1.【缺漏】`10b_M1_API_Basics` 叫學員開的那個網址，需要先申請金鑰

> **結果**：已處理（`f3a70ad`）。note 改成「這個網址的金鑰要自己申請才打得開，先看它的形狀就好」。

- 膠囊寫「現在開瀏覽器 · 看它回來的東西，是不是就是這種 JSON 的形狀」，指的是卡片上那行帶 `api_key=your_key` 的網址。
- 但同一頁下面的 Callout 自己說了「多數 API 要先申請一組金鑰」。學員照著貼進瀏覽器，`your_key` 是假的，回來的不會是那種漂亮的 JSON。
- 全片預錄自學，沒有人在現場說「這個要先申請」，學員會以為是自己弄錯。
- **建議**：膠囊的 note 改成指向一個不用金鑰就打得開的公開 API，或明講「這個網址要先申請金鑰才打得開，先看形狀就好」。

### 2.【缺漏】`10b3_M1_API_Docs` 的膠囊要學員「拿畫面上那個網址開一次」，但那個網址不能點

> **結果**：已處理（`f3a70ad`）。note 改成學員真的做得到的動作。

- 它在假瀏覽器的網址列裡，是圖片化的文字，不能點也不能複製（真正可點的連結在上一頁 `10b2` 的對話框裡）。
- **建議**：把那個網址在頁面上做成可點的連結，或把 note 改成不需要離開簡報就做得到的事。

### 3.【矛盾】`17_M1_Error` 第一次出現 `mission-timer`，但學員這時手上還沒有這個資料夾
