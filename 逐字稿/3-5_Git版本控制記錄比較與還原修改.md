Slide 30-31 ／ 2 頁 ／ 章節三 Claude Code 實戰入門：從軟體基礎到第一個專案

> **錄製註記**：〈按按看，檔案怎麼從資料夾走到 GitHub〉的互動不在 `stepIndex` 上。
>
> 四個區域裡的檔案與存檔點都是 `useState`，跟翻頁無關。只按下一步的話，後面三格會一直停在「目前是空的」「還沒有存檔點」「還沒推上去」，下方那條說明帶也不會出現，而那條說明帶才是這一頁真正在教的東西。
>
> 載入時那一格寫的是「三個檔案都沒有被改過」。 錄的時候照這個順序點：「你改了一個檔案」（連按三次）→ `git add` → `git commit` → `git push`，最後補 `git pull`。
>
> 要示範 `git restore .` 的話，要在「有改過、還沒 add」的狀態下按，commit 完那顆是暗的。
>

## Slide 30｜Git 幫你記下每一版，不只是程式碼

**畫面**
開場的檔名對照／sky 框的 `git init`／「它會記下你沒排除掉的每一個檔案」四格／「為什麼要留著這些紀錄」／灰底 Callout，講你實際要交代哪兩件事。

**逐字稿**

> 接下來這一段講 Git。前面部署那段指令裡，有三個字還沒解釋過：Git、commit、還有 GitHub。
>
> 先講它要解決什麼，而且這件事你一定做過：報告、報告_final、報告_final_v2、報告_final_v2_真的最後版。
>
> 這個做法的問題不在檔名醜。三天之後你自己也說不出 v2 跟真的最後版差在哪，而且你只留得住你「當下想得到要另存」的那幾個時間點，其他都沒了。
>
> Git 就是把這件事做對的版本：每一次修改它都幫你記下來，你隨時回得到任何一個時間點，而且不用自己想檔名。
>
> 起點只有一個動作，`git init`，開始記錄這個資料夾，一個專案只做一次。做完之後，資料夾裡會多一個叫 `.git` 的隱藏資料夾，平常在 Finder 或檔案總管裡看不到它。
>
> 所有版本都存在那裡，所以你的專案資料夾自己就是一份完整的紀錄，斷網也照樣存得了檔。
>
> 它記的是這個資料夾裡的檔案，而檔案不是只有程式碼。圖片、字型、你放進去的音樂，一樣都在裡面。
>
> 第一格你想得到，後面三格是這門課特別要你先知道的：你之後會寫給 AI 的規則、分給它的角色、還有你自己搭的檢查工具。
>
> 那三樣現在都還沒出現，但它們有一個共同點：全都是放在這個資料夾裡的檔案。所以你在第四章、第五章、第六章做的每一樣東西，都會自動跟著版本走，你不用另外想怎麼備份它們。
>
> 為什麼要留著這些紀錄？因為規則會越改越多，總有一次會改壞。而且讓 AI 動手之後，這件事會比你自己寫的時候更嚴重，因為它改動的速度比你回想的速度快。
>
> 有紀錄，你查得到是哪一次改的、改了什麼、跟現在差在哪，然後退回去。沒紀錄，你只能靠印象猜自己上禮拜寫了什麼。
>
> 再來是你實際要交代的事。這些指令你不會自己打，但「不用打指令」不等於「什麼都不用交代」，有兩件事一定要你講。
>
> 第一件是這次要存哪幾個檔案。第二件是說明寫什麼。合起來就是這樣一句話：「把 `index.html` 和 `style.css` 這次的修改存成一版，說明寫『換掉按鈕的顏色』。
>
> 」為什麼要講到檔案？因為你一次工作下來動到的檔案，常常不只你以為的那幾個。你只說「幫我存一下」，它就自己決定範圍，把這個資料夾裡所有改過的東西一起包進去，裡面可能夾著你臨時測試用的檔案，也可能夾著不該進去的東西。
>
> 所以存完還要再補一句：「這一版存進去的是哪些檔案？」它會列出來，你掃一眼。你在看什麼？看有沒有不該進版本紀錄的東西，最典型的就是金鑰跟密碼。
>
> 這是那種當下沒感覺、出事就收不回來的東西，下一頁的畫面上就看得到。

**這頁的教學意圖**：Git 不是給工程師存程式碼的工具，它記的是這個資料夾裡每一個沒被排除的檔案，包括之後要寫的手冊與設定；不用打指令，但要交代存哪幾個檔案、說明寫什麼。
**預估時間**：4 分鐘

## Slide 31｜按按看，檔案怎麼從資料夾走到 GitHub

**畫面**
四個區域橫排：工作目錄、暫存區、本機存檔點、遠端／GitHub，中間三個箭頭標著 `git add`、`git commit`、`git push`。前兩區 amber、後兩區 emerald。底下是指令按鈕列與一條說明帶，最後是 warn 的 Callout，再一塊灰底的 branch 說明。

**逐字稿**

> 存檔不是一個動作，是三段：先挑這次要存哪幾個，打包成一個存檔點，再送上網路。為什麼要分三段？
>
> 看到第二格就知道了。三段各有各的指令，畫面上這四個地方就是它們的起點跟終點。第一格，工作目錄，就是你打得開的那個資料夾，你所有的改動都先落在這裡。
>
> 我現在按「你改了一個檔案」，`index.html` 變成橘色，旁邊那行寫：Git 看得到這個改動，但還沒把它算進下一次存檔。
>
> 這個狀態叫「已修改」。我再按兩次，三個檔案都改掉。你順便看一下這一格下面那個 `.env`，它被畫了刪除線，寫著「`.gitignore` 擋著」。
>
> 等一下你會看到它一路都不會動。第二格，暫存區，這是最多人一開始不懂的一格。
>
> 按 `git add`，三個改過的檔案跳到暫存區來了。注意這一步還沒有存檔，它只是圈出這次要存哪幾個。為什麼要多這一站？
>
> 因為你一次改了三個檔案，不代表這三個是同一件事。有這一格，你才能說「這次只存這兩個」。而 `.env` 沒有被撿走，你的金鑰就是這樣留在本機的。
>
> 第三格，本機存檔點。按 `git commit`，暫存區清空，三個檔案打包成一個存檔點，附上一句說明「做出倒數的畫面」。
>
> 那句說明就是你三天後回來找版本時唯一的線索，所以不要每一次都寫「更新」。顏色也從橘換成綠，整張圖的分水嶺在這裡：左邊兩格是還沒固定，改壞了回不去；到這一格才算固定住了。
>
> 但是綠色還有第二段。這個存檔點只存在你這台電腦上。按 `git push`，它才送上 GitHub，這時候才有第二份。
>
> 前面講部署的時候說過，託管平台讀的是 GitHub 上的那一份，不是你的電腦，所以這一步不只是備份，它也是上線那條路的起點。
>
> 旁邊還有一個反過來的箭頭，`git pull`，把遠端有、你電腦上還沒有的東西拿回來。我按下去是空的，因為這裡只有我一個人在改。
>
> 換一台電腦接手、或有人跟你一起做，才會用到它。
>
> 再來是兩件最容易誤會的事。第一件我看過很多人踩：commit 一百次，沒有 push，備份份數還是零。
>
> 電腦壞掉就一起沒了。第二件在下面那行小字：`add` 過一次的檔案，Git 就開始追蹤它，之後你每次改它 Git 都會主動報告，不用重新宣告。
>
> 但每一次存檔還是要 `add` 一次，因為 `add` 挑的是「這次的修改」，不是「這個檔案」。
>
> 最下面補一個你一定會看到的字：`branch`，分支。從主線分出一條獨立的線去試新東西，搞砸了也不影響主線。
>
> 這門課不會叫你自己開分支，知道它是這個意思就好。章節七設定 GitHub Pages 的時候，畫面上會叫你選一個分支，那時候選預設的那一個就對了。

**這頁的教學意圖**：把「存檔」拆成 add、commit、push 三段，並且認得出東西現在停在哪一段。
**預估時間**：5 分鐘
