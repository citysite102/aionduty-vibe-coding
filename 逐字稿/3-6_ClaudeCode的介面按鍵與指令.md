## Slide 30｜Claude Code 桌面版：你只要動輸入框

**畫面**
左欄四段標註／右欄是桌面版 Code 頁籤的仿真畫面：問候列、統計面板、中間留白、底部的資料夾標籤、輸入框與模型設定。

**逐字稿**

> 第一次打開這個畫面，多數人會愣一下，因為上面一整片數字跟格子，看起來每一個都要懂。
>
> 我先把結論給你：那一整片幾乎都是資訊，不是要你回答的問題。
>
> 從上面這一大塊開始。Sessions 是你開過幾場對話，Messages 是講過幾句，Total tokens 是花掉多少 token，token 就是它算錢的單位。再來是你用了幾天、連續幾天、最常在幾點用、最常用哪個模型。下面那塊格子是每天的活動量，深一點代表那天做得多。這一整塊跟你要做的事沒有關係，看過就好，不用去調它。
>
> 要看的是下面這一塊。輸入框上面有兩個小標籤，左邊寫著它現在打開的是哪個資料夾。這一格要養成開工前先看一眼的習慣，因為它只會在那個範圍裡讀寫，你如果開錯資料夾，它做出來的東西會長在別的地方。輸入框右邊那一排是它現在用哪個模型。
>
> 然後就是最下面那一條。整個畫面只有這裡要你輸入，上面那一整片都可以先跳過。
>
> 那一條的提示字寫的是 Describe a task or ask a question，描述一個任務，或問一個問題。它在等你講話，不是在等程式碼。你可以直接打中文。你在章節二練過的那幾個檢查點，對象、動作、格式、邊界，講的就是這一條要打什麼。

**這頁的教學意圖**：桌面版畫面上絕大多數是資訊，只有輸入框跟它旁邊的資料夾標籤需要你管。
**預估時間**：3 分鐘

## Slide 31｜Claude Code 的按鍵：補全、退回、貼圖

**畫面**
左欄一張卡：「不用打完整路徑、退得回上一步、貼圖給它看」。右欄三張卡：檔案自動補全（`@`）／做壞了可以退回去（`/rewind`）／直接把畫面貼給它看（`Cmd + V`）。

**逐字稿**

> 接下來這三個動作，是我自己每天都在用的，省下來的都是重複勞動。桌面版跟終端機都成立，提示出現的位置兩邊不太一樣，找不到的時候打 `/help` 看一次。
>
> 第一個是 `@`。你要它改某個檔案，得先讓它知道是哪一個，而檔案的完整路徑長這樣：`src/components/Button.tsx`。你不用打完整路徑，打一個 `@` 加上檔名，它就會跳出選單讓你挑。章節二講代稱的時候說過，「那個」「這邊」「剛剛那份」它聽不懂，要換成名字；`@` 就是那件事在 Claude Code 裡最直接的做法，你不是在描述哪個檔案，你是把那個檔案指給它。
>
> 第二個是 `/rewind`，做壞了可以退回去。打下去會跳出一張清單，列出你這次對話送出過的每一句話。你選一個時間點，可以只退程式碼、只退對話，或者兩個一起退。
>
> 這一個有一條限制要記住，而且很多人是踩到才知道：它只管得到 Claude 自己改的檔案。用指令刪掉的、搬走的東西，它救不回來。所以比較保險的做法還是剛才那一段講的，動工之前先存一次檔，也就是先做一個 commit。`/rewind` 處理的是「它剛才那幾句話做壞了」，Git 處理的是「這個資料夾在昨天長什麼樣」，兩個不是同一層的東西。
>
> 第三個是貼圖。壞掉的畫面、設計稿、你覺得好看的版型，截圖起來，在輸入框直接貼上去，它會照著圖改。這也是章節二那一頁講過的：講不清楚的，直接給它看。

**這頁的教學意圖**：三個動作各對應一件天天會做的事，並且知道 `/rewind` 救得回什麼、救不回什麼。
**預估時間**：3 分鐘

## Slide 32｜Claude Code 指令的四種類型

**畫面**
2x2 四格：查現況／設定與權限／會話控制／自訂與擴充。最後是 sky 的收尾框。

**逐字稿**

> 打一個斜線會跳出一長串指令。第一次看到會想說這些是不是都要背，不用。
>
> 這一頁把它們照「你現在想幹嘛」分成四類，需要的時候回來查就好。天天會用到的其實只有兩三個。
>
> 這份清單會增減，Claude Code 更新蠻勤的，所以要記的是這四種用途，不是這份名單。當下有哪些，打一次 `/help` 最準。
>
> 第一類，查現況，用在你搞不清楚狀況的時候。`/help` 列出所有可用的指令。`/context` 告訴你這場對話還剩多少空間，以及它有沒有真的讀到你寫的那份規矩。`/usage` 是這次花了多少、額度什麼時候重置。
>
> 第二類，設定與權限，決定它能動到哪裡。`/permissions` 設定允許跟禁止的規則，`/model` 換模型，這是控制花費最直接的手段。
>
> 第三類，會話控制，用在對話變長、變貴的時候。`/clear` 開一段全新的對話。`/compact` 是把目前的對話壓縮成摘要再繼續。`/resume` 把先前的對話接回來。`/btw` 是問一句題外話，這一來一往不會進到上下文裡。
>
> 第四類，自訂與擴充，判斷的時機是同一段話你講到第三次。`/init` 會掃過你的專案，產出第一版的 `CLAUDE.md`。`.claude/commands/` 是一個資料夾，你在裡面放一個 `.md` 檔，那就是一個你自訂的指令。`/agents` 這一個跟子代理有關，子代理是什麼、要怎麼用，章節七有一整段在講，這裡先知道有這個東西就好。
>
> 所以這四格你現在真的只需要記兩個：`/help`，忘記指令的時候查；`/clear`，想重來的時候用。其他等你撞到再回來查，那時候記得比較牢。
>
> 只有一件事現在就要知道，在最下面那一句：`/compact` 的壓縮是有損的，細節會掉。
>
> 這一條我要你特別記著，因為它沒有任何徵兆。你跟它講好的那些約定，壓縮之後可能就不見了，而你不會收到通知，只會覺得「它怎麼突然不照做了」。所以重要的約定不要靠對話記憶撐著，要寫進檔案裡。那個檔案叫 `CLAUDE.md`，你在上一頁的 Git 那四格裡已經看過這個名字，後面會有一整段專門講它。

**這頁的教學意圖**：斜線指令只有四種用途，先會 `/help` 跟 `/clear`；並且知道 `/compact` 會掉細節，所以約定要落成檔案。
**預估時間**：4 分鐘

### 2.【矛盾】`.claude/commands/` 不是斜線指令，與這一頁的收錄原則衝突（已驗證）

> **結果**：已處理（2026-09-20）。改寫成一條真的斜線指令，`.claude/commands/` 退到說明裡，不再跟這一頁的收錄原則衝突。
