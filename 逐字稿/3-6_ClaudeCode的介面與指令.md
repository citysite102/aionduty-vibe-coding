## Slide 31｜Claude Code 桌面版：你只要動輸入框

**畫面**
左欄四段標註／右欄是桌面版 Code 頁籤的仿真畫面：問候列、統計面板、中間留白、底部的資料夾標籤、輸入框與模型設定。

**逐字稿**

> 第一次打開這個畫面，多數人會愣一下，因為上面一整片數字跟格子，看起來每一個都要懂。
>
> 我先把結論給你，這一頁只有一個地方需要你管。上面那一整片是它在跟你報告，不是在問你問題，看過就好。
>
> 從上面這一大塊開始。Sessions 是你開過幾場對話，Messages 是講過幾句，Total tokens 是花掉多少 token，token 就是它算錢的單位。再來是你用了幾天、連續幾天、最常在幾點用、最常用哪個模型。下面那塊格子是每天的活動量，深一點代表那天做得多。這一整塊跟你要做的事沒有關係，看過就好，不用去調它。
>
> 要看的是下面這一塊。輸入框上面有兩個小標籤，左邊寫著它現在打開的是哪個資料夾。這一格要養成開工前先看一眼的習慣，因為它只會在那個範圍裡讀寫，你如果開錯資料夾，它做出來的東西會跑到別的地方去。輸入框右邊那一排是它現在用哪個模型。
>
> 然後就是最下面那一條。整個畫面只有這裡要你輸入，上面那一整片都可以先跳過。
>
> 那一條的提示字寫的是 Describe a task or ask a question，描述一個任務，或問一個問題。它在等你講話，不是在等程式碼。你可以直接打中文。你在章節二練過的那幾個檢查點，對象、動作、格式、邊界，講的就是這一條要打什麼。

**這頁的教學意圖**：桌面版畫面上絕大多數是資訊，只有輸入框跟它旁邊的資料夾標籤需要你管。
**預估時間**：3 分鐘

## Slide 32｜Claude Code 指令的四種類型

**畫面**
2x2 四格：查現況／設定與權限／會話控制／自訂與擴充。接著是「自訂指令長什麼樣」的範例檔（`.claude/commands/check.md`）。最後是 sky 的收尾框。

**逐字稿**

> 打一個斜線會跳出一長串指令。第一次看到會想說這些是不是都要背，不用。
>
> 這一頁把它們照「你現在想幹嘛」分成四類，需要的時候回來查就好。天天會用到的其實只有兩三個。
>
> 這份清單會增減，Claude Code 更新蠻勤的，所以要記的是這四種用途，不是這份名單。當下有哪些，打一次 `/help` 最準。
>
> 第一類，查現況，用在你搞不清楚狀況的時候。`/help` 列出所有可用的指令。`/context` 告訴你這場對話還剩多少空間，以及它有沒有真的讀到你寫的那份規矩。`/usage` 是這次花了多少、額度什麼時候重置。
>
> 第二類，設定與權限，決定它能動到哪裡。`/permissions` 設定允許跟禁止的規則，`/model` 換模型，這是控制花費最直接的手段。
>
> 第三類，會話控制，用在對話變長、變貴的時候。`/clear` 開一段全新的對話。`/compact` 是把目前的對話壓縮成摘要再繼續。`/resume` 把先前的對話接回來。`/btw` 是問一句題外話，這一來一往不會進到上下文裡。
>
> 第四類，自訂與擴充，判斷的時機是同一段話你講到第三次。`/init` 會掃過你的專案，產出第一版的 `CLAUDE.md`。`.claude/commands/` 是一個資料夾，你在裡面放一個 `.md` 檔，那就是一個你自訂的指令。這一條我用下面那個例子講，因為光聽會沒有畫面。`/agents` 打下去不會列出什麼，它只印一段提示告訴你怎麼建子代理。子代理是什麼、要怎麼用，章節七有一整段在講，這裡先知道有這個東西就好。
>
> 往下這一塊就是那個例子。什麼時候你會想自己做一個？判準很白：同一段話你講到第三次。
>
> 比方說你每次做完一版，都要它跑同一輪檢查：本機開起來看畫面正不正常、Console 有沒有紅字、手機尺寸會不會被切掉、有沒有不該公開的東西。第一次講很甘願，第三次你就會懶得打了。
>
> 這時候把那段話存成一個檔案，就是畫面上這個 `.claude/commands/check.md`。裡面你看一下，沒有任何特殊語法，就是你平常會打的那幾句，條列出來而已。
>
> 檔名就是指令名。這個檔叫 `check.md`，所以之後你打 `/check`，就等於把這四句話重講一次。你要叫它 `deploy.md`、`review.md` 都可以，檔名取什麼，指令就叫什麼。
>
> 我要先講一件事免得你以為這裡有魔法：它不是一個新功能，它只是把你的話存起來。所以裡面寫得含糊，跑出來的結果一樣含糊。
>
> 最後那一塊。要打的指令，先有兩個就夠：`/help`，忘記的時候查；`/clear`，想重來的時候用。
>
> 其餘的不用記，但有一個的行為現在就要知道：`/compact`。它把對話壓成摘要再繼續，這個壓縮是有損的，細節會掉。
>
> 我特別提它，因為它沒有任何徵兆。你跟它講好的那些約定，壓縮之後可能就不見了，而你不會收到通知，只會覺得「它怎麼突然不照做了」。所以重要的約定不要靠對話記憶撐著，要寫進檔案裡。那個檔案叫 `CLAUDE.md`，你在 Git 那四格裡已經看過這個名字，後面會有一整段專門講它。

**這頁的教學意圖**：斜線指令只有四種用途，先會 `/help` 跟 `/clear`；看過一個真的自訂指令檔，知道它只是把自己的話存起來；並且知道 `/compact` 會掉細節，所以約定要落成檔案。
**預估時間**：6 分鐘

### 2.【矛盾】`.claude/commands/` 不是斜線指令，與這一頁的收錄原則衝突（已驗證）

> **結果**：已處理（2026-09-20）。改寫成一條真的斜線指令，`.claude/commands/` 退到說明裡，不再跟這一頁的收錄原則衝突。

- 檔頭註解寫得很明確：「只放打得出來的斜線指令」，並且為了這條把 `Shift + Tab` 移走，理由是「那是按鍵不是指令，打 `/` 找不到它」。
- 但「自訂與擴充」那一格的 `.claude/commands/` 是一個資料夾路徑，打 `/` 同樣找不到，跟被移走的那個是同一種情形。
- **建議**：移到章節五講零件存放位置的那幾頁，或放寬檔頭那條原則並註明理由。現在是規則寫了但自己有一個例外。

### 3.【缺漏】`11e:30` 的「手冊」在這一頁沒有對應

> **結果**：已處理（2026-09-20）。`/context` 的說明改成「它這一輪讀進了哪些檔案」，不再用章節五才定義的「手冊」。
