## Slide 36｜Claude Code 桌面版

**畫面**
左欄四段標註／右欄是桌面版 Code 頁籤的仿真畫面：問候列、統計面板、中間留白、底部的資料夾標籤、輸入框與模型設定。

**逐字稿**

> 第一次打開這個畫面，多數人會愣一下，因為上面一整片數字跟格子，看起來每一個都要懂。這一頁只有一個地方需要你管。
>
> 上面那一整片是它在跟你報告，不是在問你問題，看過就好。從上面這一大塊開始。Sessions 是你開過幾場對話，Messages 是講過幾句，Total tokens 是花掉多少 token，token 就是它算錢的單位。
>
> 再來是你用了幾天、連續幾天、最常在幾點用、最常用哪個模型。下面那塊格子是每天的活動量，深一點代表那天做得多。
>
> 這一整塊跟你要做的事沒有關係，看過就好，不用去調它。要看的是下面這一塊。輸入框上面有兩個小標籤，左邊寫著它現在打開的是哪個資料夾。
>
> 開工前先看一眼這一格，因為它只會在那個範圍裡讀寫，你如果開錯資料夾，它做出來的東西會跑到別的地方去。
>
> 輸入框右邊那一排是它現在用哪個模型。然後就是最下面那一條。整個畫面只有這裡要你輸入，上面那一整片都可以先跳過。
>
> 那一條的提示字寫的是 Describe a task or ask a question，描述一個任務，或問一個問題。
>
> 它在等你講話，不是在等程式碼。你可以直接打中文。你前面練過的那幾個檢查點，對象、動作、格式、邊界，講的就是這一條要打什麼。

**這頁的教學意圖**：桌面版畫面上絕大多數是資訊，只有輸入框跟它旁邊的資料夾標籤需要你管。
**預估時間**：3 分鐘

## Slide 37｜Claude Code 指令的四種類型

**畫面**
2x2 四格：查現況／設定與權限／會話控制／自訂與擴充。接著是「自訂指令長什麼樣」的範例檔（`.claude/commands/check.md`）。最後是 sky 的收尾框。

**逐字稿**

> 輸入框打一個斜線，會跳出幾十個指令。第一次看到會想說這些是不是都要背，不用。它們解決的狀況其實只有四種，就是畫面上這四格。天天會用到的只有兩三個。
>
> 這份清單會增減，Claude Code 更新蠻勤的，所以要記的是這四種用途，不是這份名單。
>
> 當下有哪些，打一次 `/help` 最準。
>
> 第一類，查現況，用在你搞不清楚狀況的時候。`/help` 列出所有可用的指令。`/context` 告訴你這場對話還剩多少空間，以及它有沒有真的讀到你寫的那份規則。
>
> `/usage` 是這次花了多少、額度什麼時候重置。
>
> 第二類，設定與權限，決定它能動到哪裡。`/permissions` 設定允許跟禁止的規則，`/model` 換模型，這是控制花費最直接的手段。
>
> 第三類，會話控制，用在對話變長、變貴的時候。`/clear` 開一段全新的對話。`/compact` 是把目前的對話壓縮成摘要再繼續。
>
> `/resume` 把先前的對話接回來。`/btw` 是問一句題外話，這一來一往不會進到上下文裡。
>
> 第四類，自訂與擴充，判斷的時機是同一段話你講到第三次。`/init` 會掃過你的專案，產出第一版的 `CLAUDE.md`。
>
> `.claude/commands/` 是一個資料夾，你在裡面放一個 `.md` 檔，那就是一個你自訂的指令。
>
> `/agents` 打下去不會列出什麼，它只印一段提示告訴你怎麼建子代理。子代理是什麼、要怎麼用，章節六有一整段在講，這裡先知道有這個東西就好。
>
> 往下這一塊就是那個例子。什麼時候你會想自己做一個？判斷標準很白：同一段話你講到第三次。
>
> 比方說你每次做完一版，都要它跑同一輪檢查：本機開起來看畫面正不正常、Console 有沒有紅字、手機尺寸會不會被切掉、有沒有不該公開的東西。第一次講很甘願，第三次你就會懶得打了。
>
> 這時候把那段話存成一個檔案，就是畫面上這個 `.claude/commands/check.md`。
>
> 裡面你看一下，沒有任何特殊語法，就是你平常會打的那幾句，條列出來而已。檔名就是指令名。
>
> 這個檔叫 `check.md`，所以之後你打 `/check`，就等於把這四句話重講一次。
>
> 你要叫它 `deploy.md`、`review.md` 都可以，檔名取什麼，指令就叫什麼。
>
> 這裡沒有魔法，它不是一個新功能，只是把你的話存起來。所以裡面寫得含糊，跑出來的結果一樣含糊。
>
> 要打的指令，先有兩個就夠：`/help`，忘記的時候查；`/clear`，想重來的時候用。
>
> 其餘的不用記，但有一個的行為現在就要知道：`/compact`。
>
> 它把對話壓成摘要再繼續，這個壓縮是有損的，細節會掉。它沒有任何徵兆。你跟它講好的那些約定，壓縮之後可能就不見了，而你不會收到通知，只會覺得「它怎麼突然不照做了」。
>
> 所以重要的約定不要靠對話記憶撐著，要寫進檔案裡。那個檔案叫 `CLAUDE.md`，你在 Git 那四格裡已經看過這個名字，後面會有一整段專門講它。

**這頁的教學意圖**：斜線指令只有四種用途，先會 `/help` 跟 `/clear`；看過一個真的自訂指令檔，知道它只是把自己的話存起來；並且知道 `/compact` 會掉細節，所以約定要落成檔案。
**預估時間**：6 分鐘

## Slide 38｜官方指南怎麼查，現在寫了什麼

**畫面**
開場兩句：前面講過有些做法會跟著版本一直換，下面這四條就是現在官方的說法；四條都會變，所以更該記的是底下那兩個網址。四張卡：思考深淺有一個總開關（effort，預設 medium，附怎麼實測）、「請仔細思考」可以拿掉了、不要叫它印出內部推理過程、做畫面不要說「不要很 AI」。最後一個 sky 框放兩個官方網址與查證日期。

**逐字稿**

> 前面講過，這堂課有些做法會跟著版本一直換。下面這四條就是現在官方的說法，我照文件抄的，不是我自己的經驗談。
>
> 第一條，思考深淺有一個總開關，它叫 effort。現在預設是 medium，官方特別講了一句：不要把上一代的設定搬過來用。
>
> 原因是同一個名字在不同版本代表的量不一樣，他們自己測過，現在的 medium 已經跟上一代的 high 差不多了。你照舊把它拉到最高，只會變慢、變貴。
>
> 那你怎麼知道自己該用哪一個？不要用猜的。挑一件你每週都在做的事，打斜線 effort 切 low、medium、high 各跑一次，自己看哪一個就夠用。多數時候你會發現不用開到最高。
>
> 第二條，「請仔細思考」這類句子可以拿掉了，就是前面講過的那個例子。它本來就會想，官方測過，拿掉之後回答開始得比較快，答案也沒有變差。
>
> 想要它想深一點，就去調上面那個開關，不要多寫一句話。
>
> 第三條，不要叫它把「內部推理過程」印出來。這種要求有機會直接被擋掉，你會收到一句拒絕。但要理由是可以的，你就直接講「用三句話解釋你為什麼這樣選」，這個問得到。
>
> 差別在你要的是一段說明，不是它腦袋裡的原始過程。
>
> 第四條跟做畫面有關，而且很實用。不要跟它說「不要做得很 AI」。官方的說法是，你這樣講它只會換成另外一套預設，換湯不換藥。
>
> 要講清楚不要什麼：不要米白背景、不要 01、02、03 那種編號、不要膠囊形狀的按鈕。
>
> 這三個是官方文件自己舉的例子。後面案例那一段，我會給你一份真的用過的清單，十一項。
>
> 最後，這四條過一陣子就會變，所以我更希望你記住的是底下那兩個網址。以後有人講得跟我不一樣，你自己去那邊對一下就知道了。
>
> 上面那四條是 2026 年 10 月查的，它出新版本的時候回來看一次，整頁可能都不一樣。

**這頁的教學意圖**：給一張現在的官方建議，但重點是那兩個網址與「它會過期」這件事；`/effort` 在這一頁第一次出現，因為學員剛看完斜線指令長什麼樣。
**預估時間**：5 分鐘
