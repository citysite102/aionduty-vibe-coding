## Slide 33｜探索、計畫、執行、驗證：驗證歸你

**畫面**
頂部紅字「許多初學者會犯的錯誤：一開口就要求馬上產出最終結果」／四格流程卡／收尾框「Agent 接手的是中間的執行，而驗證是你的」／Callout「執行這一步，它會先問你」。

**逐字稿**

> 從這裡開始，它要真的去動你電腦裡的檔案。所以先講一個順序的問題。
>
> 最上面那句話是這樣寫的：許多初學者會犯的錯誤，是一開口就要求馬上產出最終結果。
>
> 這個直覺很合理，你想要的本來就是最後那個東西，幹嘛不直接講。問題是它會照做，而且會做得很快，然後你拿到一個八成對、兩成不對的東西，而你分不出來哪兩成不對。
>
> 中間這四格是另一種走法。第一步探索，釐清現況、讀取檔案、確認需求。第二步計畫，要改什麼、分幾步做，先提出來。第三步執行，寫程式、裝需要的東西。第四步驗證，跑一次，看結果對不對，不對就回頭修。
>
> 四格底下那顆膠囊要看一眼：遇到錯誤或新需求，回到第一步重新探索。所以這不是一條走完就結束的直線，是一個會轉回去的圈。
>
> 這四步裡面，前兩步你跟它一起做，執行由它動手，驗證回到你手上。
>
> 驗證這兩個字我要特別講，因為它不是「打開來看一眼，覺得好像可以就算過」。順序是：先寫下什麼情況該出現什麼結果，再照著跑一次看對不對。先寫，再跑。
>
> 反過來會怎樣？你看到什麼就會接受什麼。人看到一個能動的東西，很難不覺得它是對的。
>
> 最下面這個框，是你翻到下一頁馬上會遇到的事。執行這一步，它會先停下來問你。它要改哪個檔案、要裝什麼東西，動手之前會等你按同意。按之前先看清楚它說要改的是哪一個檔案，對不上就選不同意，把你想改的講清楚，再讓它跑一次。
>
> 一路按同意，等於沒有這道關卡。這個詢問可以整段關掉，也可以只放行一部分，怎麼設定後面會專門講。

**這頁的教學意圖**：四步是一個會轉回去的圈，而驗證是「先寫規格再跑」，不是「打開看一眼」。
**預估時間**：3 分鐘

## Slide 34｜做出你的第一個作品

**畫面**
左欄：說明段（番茄鐘換成太空任務、mission-timer 另開一個資料夾）／Prompt 卡（畫面三條、背景四條、最後一句「不要引用任何外部圖片」）／「別期待一次就長成右邊那樣」。
右欄：成品示意（粒子星球、17:42、進度條上一艘小火箭、發射／待機／返航）。

**逐字稿**

> 第一個作品是一個任務計時器。說穿了就是番茄鐘，只是換成太空任務的樣子。
>
> 我先把門檻講清楚：你不用看得懂 HTML 或 CSS，一行都不用。這一頁要你做的事情只有一件，把想要什麼講清楚。
>
> 先講資料夾。前面試跑那個五分鐘計時器可以放著不管，它的任務已經結束了。正式的作品另外開一個資料夾，叫 mission-timer，它會建在你安裝那一頁選的那個資料夾裡面。這個作品不是做完就丟，接下來整門課都會回頭改它，最後會把它放上網路。
>
> 中間這段 prompt 可以直接複製，不過花一點時間看它寫了什麼。第一句先講範圍：開一個 mission-timer 資料夾，一個 index.html 就好。接著分成兩組。畫面那一組講倒數幾分鐘、用等寬字體、三顆按鈕各叫什麼名字、哪一顆是實心主色，還有進度條上那艘會往前移動的小火箭。背景那一組更細：星球用 canvas 畫成經緯排列的粒子點陣、只露出畫面下方一道弧、光源在左上、越靠近輪廓的粒子要越亮。最後一句是邊界：不要引用任何外部圖片。
>
> 這些細節看起來很囉唆，但它們不是裝飾。每一條都在堵掉一個它本來會自己決定的地方，而它自己決定的那些，通常就是你之後要來回五六次才改掉的那些。最能看出差別的是星星那一條：它寫的是「星星座標固定寫死，重繪時不可以跳動」。前半講做法，後半講你要的結果，兩個都給了。
>
> 那上一頁說一開口就要最終結果是錯的，這一段算不算？差別在範圍跟驗收。這個作品是一個檔案、一個畫面，而且每一條你都講得出做完長什麼樣。「幫我做一個 Facebook」兩個都沒有。
>
> 右邊是成品的樣子。不過左下角那段話先看一下：右邊那張圖不是第一次就長這樣的。第一版星球太亮，蓋住按鈕；第二版粒子排太密，疊出一圈一圈的干擾波紋；第三版才換成經緯排列。寫得越具體，需要的來回就越少，但不會變成零。
>
> 做完打開來看。在 Finder 或檔案總管找到 mission-timer，對裡面的 index.html 按兩下，它會用你平常的瀏覽器打開。看一下網址列，那是一串本機路徑，不是網站網址。這就是前面說的「在本機跑」，只有你這台電腦看得到。
>
> 還有一件事：心裡已經有畫面的話，把參考圖一起拖進輸入框貼給它。

**這頁的教學意圖**：第一個真的作品，並且看到 prompt 的每一條都在堵掉一個它本來要自己決定的地方。
**預估時間**：8 分鐘（含實機）

## Slide 35｜換你寫一次

**畫面**
膠囊「現在開 Claude Code」／題目卡「讓計時器在最後一段時間，一眼就看得出『快來不及了』」／模糊版會拿到的四種結果／四張陷阱卡／amber「加一句不要做什麼」／sky 驗收區。

**逐字稿**

> 題目只有一句：讓計時器在最後一段時間，一眼就看得出快來不及了。
>
> 要什麼效果、怎麼做到，是你要自己寫進 prompt 的部分。這一題沒有標準答案，但有標準的驗收方式，等一下會講。
>
> 先看如果你只打「時間快到的時候提醒我一下」會拿到什麼。大概是這四種其中一種：跳一個 alert 擋住整個畫面、整頁變紅、加一個閃爍動畫，或者它覺得進度條已經夠明顯了，什麼都沒改。
>
> 這四種都不算它做錯。回想一下章節二那個 0.31：這句話落下去，四個答案的分數差不多高，它只能挑一個。
>
> 中間這四題，是你沒寫進去它就會自己選一個答案的地方。
>
> 第一題，什麼時候算最後一段？剩 60 秒，還是剩一成？先想清楚再往下，因為如果有人把整場設成 30 秒，那一開始就該是警示狀態嗎。
>
> 第二題，要變的那一塊會不會撞到舊規則？上一頁的 prompt 裡有一條「只有發射是實心主色，其他保持灰階」。現在你要某個東西變顯眼，這兩條直接衝突。你要它讓哪一邊？
>
> 第三題跟第四題是同一類，都是狀態互相影響。按下待機的時候呢？暫停在剩 30 秒，警示要留著還是解除。按下返航歸零之後呢？畫面要回到原樣，還是停在警示狀態？沒講的話，它多半只處理倒數那一條路。
>
> 旁邊那一條也寫進去：加一句不要做什麼。例如不要跳 alert、不要用閃爍。不寫的話它會自己挑一個，而閃爍實際跑起來會比你想的刺眼很多。
>
> 最後是驗收。上面那四題，你寫進去幾條就按幾條，不是看它有沒有變好看，是一條一條對你自己寫的規格。25 分鐘等一次太慢，所以先叫它把倒數改成從 65 秒開始跑，驗完再改回原本的分鐘數。
>
> 然後按三下。第一下，倒數跑到你寫的那個門檻，畫面有沒有照你寫的那樣變。第二下，在警示狀態下按待機，再按發射，跟你寫的一樣嗎。第三下，按返航歸零，畫面有沒有回到你寫的那個樣子。
>
> 壞掉通常是壞在後面兩下，不是壞在倒數。倒數是它多半會做到的部分，狀態怎麼互相影響才是沒講就會漏的地方。
>
> 這件事之後你會一直遇到：它把你說的那條路做得很好，沒說的那幾條路就空著。所以驗收的時候不要只走主線，要去按那些你沒講的按鈕。
>
> 還有一個你這一題很可能用得到的：改到一半覺得越改越亂、想回到還沒動之前，打 `/rewind`。它會列出你這次對話送出過的每一句話，選一個時間點就退回去，程式碼跟對話可以分開退。有一條限制要記住，它只管得到 Claude 自己改的檔案，用指令刪掉或搬走的救不回來，所以動工前先存一次檔還是最保險的做法。

**這頁的教學意圖**：沒有標準答案的一題，學員自己定規格、自己驗收。
**預估時間**：8 分鐘（含實機）

## Slide 36｜讓計時器去外面拿一筆資料

**畫面**
膠囊「現在開 Claude Code」／左欄 prompt（三點需求加一句「這個 API 不用金鑰」）／右欄它拿回來的 JSON 與 warn Callout「第 3 點不要拿掉」。

**逐字稿**

> 你的計時器目前所有東西都寫在 index.html 裡面，它不會去外面拿任何資料。這一步讓它在載入的時候，去一個公開的天氣服務，要今天台北的日出與日落時間。
>
> 左邊這段 prompt 用複製的，不要自己打，那個網址很長。
>
> 它寫了三點。第一點是什麼時候去拿：頁面載入的時候。第二點是拿回來之後放哪裡、長什麼樣。第三點是拿不到的時候怎麼辦：不要讓畫面壞掉，那一行顯示「離線」就好。
>
> 為什麼挑這一個服務？因為它不用金鑰、不用註冊，網址貼上去就能打。前面看過的那些 API 多半要先申請一組金鑰，光是申請就會卡掉不少時間，所以先用打得通的這一個，把整條路走完一次。
>
> 右邊是它拿回來的東西。大括號包起來、一行一個欄位、左邊名字右邊值。前面餐廳點單那個比喻裡的出菜明細，長的就是這個樣子。
>
> 再回頭講第 3 點，那一點不要拿掉。
>
> 不寫那一句，它只會處理「拿到了要怎麼顯示」，不會處理「拿不到怎麼辦」。網路一斷，那一行就會一直停在載入中，而你會以為是自己哪裡寫錯了，回頭去翻程式碼翻半天。
>
> 這裡有一條原則值得帶走：只要是去外面拿資料，就有拿不到的時候。拿不到的時候畫面要長什麼樣，是你要先決定的，它不會幫你決定，它只會讓那一格空在那裡。
>
> 改完存檔，重新整理瀏覽器就看得到。如果那一行顯示的是「離線」，代表請求送出去了但沒拿回來，先檢查網路，再把那個網址貼進瀏覽器，確認它自己打得通。

**這頁的教學意圖**：第一次接外部資料，重點不是接得起來，是「拿不到的時候畫面長什麼樣」要先決定。
**預估時間**：5 分鐘（含實機）

## Slide 37｜叫它寫個小工具，幫你做雜事

**畫面**
左上角灰標籤「支線示範，跟你的任務計時器無關」／Prompt 卡（「副檔名保持原樣」與「先印出對照表給我確認」標成橘黃）／右欄執行前後的檔名對照。

**逐字稿**

> 先看左上角那個標籤：支線示範，跟你的任務計時器無關。這一頁不用改你的計時器，也沒有東西是你漏做的。它在這裡的作用，是讓你看到 AI 幫你做的不只有網頁。
>
> 情境是批次整理混亂的檔案。一堆命名亂七八糟的圖片，要重新命名成流水號，再分類進不同的資料夾。這種工作不需要麻煩工程師，Claude Code 寫個小腳本就處理得完。
>
> 右邊的對照很直白。執行前是三個檔名三種風格，執行後變成日期開頭接三位流水號，而副檔名各自保持原樣。
>
> prompt 裡有兩個地方標了色。第一個是「副檔名保持原樣不要改」，那是邊界。第二個是「先印出預計的新舊檔名對照表給我確認，我說 OK 之後你再實際執行」。
>
> 為什麼要先看對照表？這個理由值得記起來，它適用的場合比這一頁多很多：改檔名是覆蓋，不是新增。它把 100 個檔案改完，你才發現規則不是你要的，原本的檔名已經沒了。這跟改程式碼不一樣，程式碼有 Git 可以退回去，檔名沒有。凡是這種「做完就蓋掉原本那個」的動作，都值得先看一眼再放行。
>
> 底下那個提示是實務上會卡住的地方：腳本通常用 Node.js 或 Python 執行。走桌面版的話請它幫你裝；Python 要自己到 python.org 下載安裝。
>
> 最後這張卡回答一個常見的問題：這個用 Cowork 不是也可以？可以。差別在產出物。腳本留得下來，下次換一百張圖，再跑一次就好；Cowork 是這一次幫你做完，下次還要再講一遍。這一頁示範的是產出一個能重複用的工具，不是比誰改得快。

**這頁的教學意圖**：AI 的產出不只有網頁；而「做完就蓋掉原本那個」的動作要先確認再執行。
**預估時間**：4 分鐘

## Slide 38｜爬蟲：讓腳本自己開瀏覽器，抓成一張表

**畫面**
左上角灰標籤「支線示範」／情境：每週手動整理同一批網頁／「為什麼要開一個真的瀏覽器」／Prompt 卡（三行標成 sky）／amber 的「出去連別人的網站，有三條線要守」。右欄：網頁清單加「載入更多」按鈕，往下是抓完的 `news.csv`。

**逐字稿**

> 一樣是支線示範，左上角那個標籤還在。
>
> 情境你大概做過：每週把同一個頁面上的清單複製到 Excel，標題、日期、連結，一則一則貼。這件事每次都一樣，所以它可以變成一支腳本。
>
> 先講一個你可能會問的問題：為什麼要開一個真的瀏覽器，不能直接把網頁抓下來就好？
>
> 因為現在多數網站的內容，是你打開之後才由程式算出來的。你直接去抓網頁原始碼，拿到的是一個空殼，裡面沒有你看到的那些字。Playwright 這個工具是真的開一個瀏覽器、等畫面長出來再抓，而且它能點、能填、能捲。
>
> 右邊那個「載入更多」按鈕就是最好的例子。那後面那幾十則，非得有人去按才會出現，不按就抓不到。以前這個「有人」是你，現在是腳本。
>
> Prompt 我標亮了三行。
>
> 第一行是邊界：只動這一個公開頁面，不要登入，不要跳到別的網域。不講的話它很可能順著連結一路爬出去，那就不是你要的東西了。
>
> 第二行是每個動作之間停一秒。這一條等一下單獨講。
>
> 第三行是 headless: false。headless 的意思是不開視窗、在背後跑。第一次我要你關掉它，讓瀏覽器真的跳出來，你看著它自己打開網頁、自己按載入更多、自己捲下去。這個畫面用講的沒有用，你要自己看一次。看完之後再改成背後跑就好。
>
> 另外 Playwright 要另外裝，而且它會連自己那一份瀏覽器一起裝。你不用先去弄，跟它說「缺什麼就幫我裝」它會處理。
>
> 【等待 Agent 執行，不補旁白】
>
> 最後這一塊我一定要講完，因為這一頁跟前面每一頁都不一樣：前面那些東西壞掉，壞的是你自己的檔案；這一支腳本是出去碰別人的伺服器。
>
> 第一條，只抓不用登入就看得到的東西。要登入才看得到的，那是別人給你的帳號權限，不是公開資料，用程式去撈跟你自己點進去看是兩回事。
>
> 第二條，抓之前先問它一句：「這個網站的 robots.txt 跟服務條款怎麼寫？」多數網站會寫明哪些路徑不給抓。這份東西它讀得懂，你不用自己去找。
>
> 第三條，剛才那個停一秒。那不是客氣，是你一秒鐘打人家一百次，對伺服器來說跟攻擊沒有分別。輕的結果是你的 IP 被擋掉，重的就是另一回事了。
>
> 這三條我不是在嚇你，是因為這件事很好用，好用到很容易一路往下做。多停一秒、少抓一個需要登入的頁面，成本幾乎是零。
