## Slide 39｜哪些事它做得好，哪些你得自己來

**畫面**
兩張並排的大卡。左「它的強項」四條，右「你得自己補的地方」四條。

**逐字稿**

> 你到這裡已經讓它做過三件事了，所以現在可以講一件比較誠實的話：它有它做得好的地方，也有它做不好的地方，而且做不好的那幾種很有規律。
>
> 這一頁把兩邊擺在一起看。
>
> 左邊第一條是目標很明確的單一任務。計時器、單位換算、批次改檔名、把一份資料整理成另一種格式。判斷標準寫在後面：講得出「做完長什麼樣」的，它做得又快又好。你前面做的那個計時器就落在這一條。
>
> 第二條，照著錯誤訊息找原因。把整段紅字丟給它，它會自己翻遍整個資料夾找出哪一行有問題，這件事它比人快得多。
>
> 第三條，讀懂一個你沒看過的專案。請它把別人的專案讀一遍，用白話講這東西是怎麼跑起來的、哪個檔案負責什麼。
>
> 左邊第四條剛好是你這一章最後兩頁做過的事：把重複在做的事變成一支腳本。判斷標準很白，同一件事你做過兩次，就問一句「這個能不能寫成腳本」。
>
> 右邊那一欄的標題是「你得自己補的地方」，不是「它不會的事」。這個差別值得停一下。前三條讀起來很像它的缺陷，但它們其實是你的工作清單，三條都是你補得上的。
>
> 第四條不一樣，那一條你補不上，也不該補：要用你的身分才成立的事。登入、按同意、付款、把權限交出去。它可以把前後每一步都做完，然後停在那一下等你。部署那一段講過同一件事，那不是工具還沒做到，是它本來就不該替你做。
>
> 第一條，一句話就要一個大系統。「幫我做一個 Facebook」這種。範圍太大，它會自己決定一堆你沒同意的做法，等你發現的時候已經改到看不懂了。
>
> 第二條，它不會主動說「我不確定」。這一條是三條裡面最危險的。
>
> 它沒把握的時候，答案看起來跟有把握的時候沒兩樣，一樣流暢、一樣肯定。所以你不能從它的語氣判斷這件事對不對，你得自己查，或是叫它實際跑一次給你看。前面說驗證歸你，理由就在這一條，不在它笨不笨。
>
> 第三條，你沒說出口的偏好。你說「再大器一點」，它可能把所有字放大兩倍。腦子裡的畫面它拿不到，你得講到具體。講不出來就貼一張圖給它看。你在「換你寫一次」那一頁如果只打了「時間快到提醒我一下」，拿到的那個結果就是這一條。

**這頁的教學意圖**：右欄不是「它不會的事」，是「你補得上的事」，三條各對應一個前面撞過的具體經驗。
**預估時間**：3 分鐘

## Slide 40｜該用什麼工具？

**畫面**
分界一行：這件事需不需要讀寫你電腦裡的真實檔案／五張情境卡／膠囊「先自己想，再往下」／五個建議做法一起出現／收尾「這一頁分的是工具，不是分方法」。

**逐字稿**

> 學完一個工具之後，最容易發生的事是拿它去做所有事情。所以這一頁反過來練：什麼時候不該用它。
>
> 五個情境，每一題只問一件事：這件事需不需要讀寫你電腦裡的真實檔案。不需要的，對話框或現成的無程式碼工具就夠；需要的，才輪到 Claude Code。顏色標的是這條分界，不是哪一題比較高級。
>
> 情境一，每週一從系統匯出報表寄給主管。情境二，短期活動網頁，下週上線，只收集與顯示資訊。情境三，舊有系統要新增忘記密碼，要讀懂舊資料庫的結構，還要接上目前在用的信件服務。情境四，高度客製化的個人記帳工具，你想自己掌控每一個畫面細節與資料存放方式。情境五，你想了解目前實作的爬蟲邏輯，不需要改程式碼，只要看懂架構並規劃下一步。
>
> 畫面上出現「先自己想，再往下」的時候就停在這裡，把五題各自歸到一邊去。
>
> ⋯⋯答案。情境一，如果那份報表本來就在 Google 試算表裡，用對話框請它寫一段 Google Apps Script，那是試算表內建的自動化腳本，從「擴充功能」那裡開啟 Apps Script 貼進去，再設定每週自動跑。情境二用 AI App Builder 直接生成並上線，Lovable、Base44、v0 都是這一類。要提醒一件事：這類平台本身就做得出表單跟後台，多數情況不用再外接一個表單工具。這兩題都不需要碰你電腦裡的檔案。
>
> 剩下三題要 Claude Code。
>
> 情境三，用它打開現有專案，但先請它讀一遍、講出打算怎麼改，你看過那個做法再讓它動手。舊系統不要讓它邊讀邊改，理由就是上一頁那條「範圍太大它會自己決定一堆你沒同意的做法」。
>
> 情境四，先在 Claude 的 Design 把畫面設計出一版，版面跟流程都確定了，再帶進 Claude Code 實作。這一題你要的是掌控每一個細節，所以草稿階段先不要讓它寫程式，畫面定了再動工。
>
> 情境五，用它打開那個專案，而且講明「只讀不改，先用白話講一遍架構」。這一題它做得到是因為它讀得到整個資料夾，所以答得出哪個檔案負責什麼。
>
> 第五題值得多看一眼。它一行程式碼都沒有要改，但還是落在 Claude Code 這一邊，因為它得讀得到那個專案。所以分界不是「要不要寫程式」，是「要不要讀寫你電腦裡的檔案」。
>
> 最後這一句：這一頁分的是工具，不是分方法。把需求講清楚的問法、把規矩寫下來的做法，上面五題選哪一邊都用得上。

**這頁的教學意圖**：選工具的分界只有一條，就是要不要讀寫你電腦裡的真實檔案，跟要不要寫程式無關。
**預估時間**：5 分鐘

## Slide 41｜目前為止的專案進度

**畫面**
三條驗收清單／「現在做一件事：存檔」含一句可複製的 prompt ／amber 的「存不起來的時候」。

**逐字稿**

> 接下來每一章都會回頭改它，所以這裡要對清楚。下面兩件事應該都成立。
>
> 第一，你有一個 mission-timer 資料夾，裡面有一個 index.html。整個計時器就是這一個檔案，不是一整包東西。
>
> 第二，對那個 index.html 按兩下，瀏覽器會打開，倒數會動，底下有一行日出與日落時間。那一行是它去外面的 API 拿回來的，不是你自己打上去的。
>
> 如果有一條對不上，不要卡在那裡自己翻程式碼找。把那個檔案打開，連同你原本寫的那段 prompt 一起貼回 Claude Code，跟它說「我要的是這樣，現在是這樣，幫我看哪裡沒做到」。
>
> 這個動作的形狀就是：拿你寫下的規格，去對它做出來的東西。整門課後面所有的驗收，都是這個動作的放大版。
>
> 然後現在做一件事：存檔。前面講過 Git 是可以回去的存檔點，但你還沒有實際存過一次。畫面上這句話複製過去就可以：幫我把這個資料夾建立成 Git repository，做第一次 commit，訊息寫「第一個作品完成」。
>
> 存完之後，Claude 改壞了這個資料夾裡的東西，你都回得到這一次的狀態。有一點要記著：存檔之後才新增的檔案不在裡面，那要再存一次才算。
>
> 這一步有兩種常見的卡法，先講在前面，免得你以為自己做錯什麼。
>
> 第一種，它回一段紅字，說 git 不知道你是誰，要你設定名字跟 email。那不是你做錯，是這台電腦第一次用 git。把整段紅字貼回去，跟它說「幫我設定好再重跑一次」，這件事就結束了。
>
> 第二種，它說找不到 git。那就跟它說「幫我確認這台電腦有沒有 git，沒有的話告訴我怎麼裝」，照它給的步驟走。Windows 比較常遇到這一種。
>
> 我要講清楚一件事：這一步從頭到尾沒有碰到 GitHub。你剛才那一次存檔只存在你自己的電腦裡，沒有上傳到任何地方，所以不會有帳號或授權的問題。真正要跟 GitHub 打交道是在章節八，那時候它會停下來要你到瀏覽器登入並按同意，跟前面講部署授權是同一回事，那一下它代不了你。


**這頁的教學意圖**：章節三的驗收點，兩條都指得出具體的東西；並且完成第一次 commit。
**預估時間**：4 分鐘（含實機）
