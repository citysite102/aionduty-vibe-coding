## Slide 38｜Agent 的一輪：探索、計畫、執行、驗證

**畫面**
頂部紅字「許多初學者會犯的錯誤：一開口就要求馬上產出最終結果」／四格流程卡（第 2 格寫著「並且現在就寫下做完長什麼樣」，第 4 格寫著「拿第 2 步那張清單逐條對」）／收尾框講完成條件的位置／灰底 Callout「它不一定每一步都問你」，裡面有一段核准畫面的示意。

**逐字稿**

> 接下來要做的是這門課的第一個作品。動手之前，先講一個順序的問題。最上面那句話是這樣寫的：許多初學者會犯的錯誤，是一開口就要求馬上產出最終結果。
>
> 這個直覺很合理，你想要的本來就是最後那個東西，幹嘛不直接講。問題是它會照做，而且會做得很快，然後你拿到一個八成對、兩成不對的東西，而你分不出來哪兩成不對。
>
> 中間這四格是另一種走法。第一步探索，釐清現況、讀取檔案、確認需求。
>
> 第二步計畫，要改什麼、分幾步做，先提出來。第三步執行，寫程式、裝需要的東西。第四步驗證，拿第二步那份清單逐條核對，不對就回頭修。
>
> 四格底下那顆膠囊要看一眼：遇到錯誤或新需求，回到第一步重新探索。
>
> 所以這不是一條走完就結束的直線，是一個會轉回去的圈。這四步裡面，前兩步你跟它一起做，執行由它動手，驗證回到你手上。
>
> 這裡有一個位置問題，它決定了驗收有沒有用。你看第二格跟第四格：那份「做完長什麼樣」的清單，寫在第二格，不是第四格。
>
> 也就是說，在它還沒開始動手之前，你就要把什麼情況該出現什麼結果一條一條列下來。
>
> 這份清單有個名字，叫完成條件。執行完之後，第四步就是拿它逐條核對。為什麼位置這麼重要？因為順序反過來的話，你是看著它做出來的東西回頭寫標準。
>
> 那不是驗收，那是找理由接受。人看到一個能動的東西，很難不覺得它是對的。完成條件怎麼寫得夠具體才驗得出來，章節七有一整段專門處理。
>
> 它動手的時候會不會先問你？這件事很多人有誤會，包括我一開始也以為它每一步都會問。實際上不會。
>
> Claude Pro 開起來預設是自動模式，多數動作它自己做完，背後有另一個模型在檢查這個動作跟你要求的對不對得上。
>
> 你想要每一步都自己看過再放行，那要自己切到手動模式。桌面版在輸入框旁邊的模式選單，終端機按 Shift 加 Tab 輪流切。
>
> 停下來的時候長什麼樣，畫面上那一段就是示意。
>
> 它會告訴你要動哪一個檔案，然後給你三個選項：同意、同意而且以後不要再問、不同意並且告訴它要改成什麼。
>
> 要看的是第二行，那是它要動的檔案。對不上就選第三個，把你想改的講清楚，再讓它跑一次。

**這頁的教學意圖**：四步是一個會轉回去的圈；完成條件寫在第二步不是第四步；它預設不會每一步都問你，想要就自己切手動模式。
**預估時間**：4 分鐘

## Slide 39｜正式版計時器：把畫面寫成一份規格

**畫面**
左欄：說明段（番茄鐘換成太空任務、mission-timer 另開一個資料夾）／Prompt 卡（畫面三條、背景四條、最後一句「不要引用任何外部圖片」，複製鈕拿到的是整段）／「別期待一次就長成右邊那樣」，底下附著那張點陣星球的參考圖。
右欄：成品示意（粒子星球、17:42、進度條上一艘小火箭、發射／待機／返航）。

**逐字稿**

> 第一個作品是一個任務計時器。說穿了就是番茄鐘，只是換成太空任務的樣子。門檻只有這樣：你不用看得懂 HTML 或 CSS，一行都不用。
>
> 這一頁要你做的事情只有一件，把想要什麼講清楚。先講資料夾。前面試跑那個五分鐘計時器可以放著不管，它的任務已經結束了。
>
> 正式的作品另外開一個資料夾，叫 mission-timer，它會建在你安裝那一頁選的那個資料夾裡面。
>
> 這個作品不是做完就丟，接下來整門課都會回頭改它，最後會把它放上網路。中間這段 prompt 可以直接複製，不過花一點時間看它寫了什麼。
>
> 第一句先講範圍：開一個 mission-timer 資料夾，一個 index.html 就好。
>
> 接著分成兩組。畫面那一組講倒數幾分鐘、用等寬字體、三顆按鈕各叫什麼名字、哪一顆是實心主色，還有進度條上那艘會往前移動的小火箭。
>
> 背景那一組更細：星球用 canvas 畫成經緯排列的粒子點陣、只露出畫面下方一道弧、光源在左上、越靠近輪廓的粒子要越亮。
>
> 最後一句是邊界：不要引用任何外部圖片。這些細節看起來很囉唆，但它們不是裝飾。每一條都在堵掉一個它本來會自己決定的地方，而它自己決定的那些，通常就是你之後要來回五六次才改掉的那些。
>
> 最能看出差別的是星星那一條：它寫的是「星星座標固定寫死，重繪時不可以跳動」。
>
> 前半講做法，後半講你要的結果，兩個都給了。那上一頁說一開口就要最終結果是錯的，這一段算不算？
>
> 差別在範圍跟驗收。這個作品是一個檔案、一個畫面，而且每一條你都講得出做完長什麼樣。「幫我做一個 Facebook」兩個都沒有。
>
> 右邊是成品的樣子，但它不是第一次就長這樣的。第一版星球太亮，蓋住按鈕；第二版粒子排太密，疊出一圈一圈的干擾波紋；第三版才換成經緯排列。
>
> 寫得越具體，需要的來回就越少，但不會變成零。做完打開來看。在 Finder 或檔案總管找到 mission-timer，對裡面的 index.html 按兩下，它會用你平常的瀏覽器打開。
>
> 看一下網址列，那是一串本機路徑，不是網站網址。這就是前面說的「在本機跑」，只有你這台電腦看得到。
>
> 還有一件事，而且這一次不是選配：把畫面上那張點陣星球的參考圖一起拖進輸入框。「經緯排列的粒子點陣」這句話，光用打的它多半會做成一顆漸層球，方向對但層級不對。
>
> 前面講過，講不清楚的直接給它看，當時用的就是這張圖。還有底下那顆複製鈕，它拿到的是整段，包含畫面三條跟背景四條，不是只有開頭那一句。

**這頁的教學意圖**：第一個真的作品，並且看到 prompt 的每一條都在堵掉一個它本來要自己決定的地方。
**預估時間**：8 分鐘（含實機）

## Slide 40｜四個沒講清楚就會被它自己決定的地方
**畫面**
膠囊「現在開 Claude Code」／題目卡「讓計時器在最後一段時間，一眼就看得出『快來不及了』」／模糊版會拿到的四種結果／四張陷阱卡／amber「加一句不要做什麼」／sky 驗收區。

**逐字稿**

> 題目只有一句：讓計時器在最後一段時間，一眼就看得出快來不及了。要什麼效果、怎麼做到，是你要自己寫進 prompt 的部分。
>
> 這一題沒有標準答案，但有標準的驗收方式，等一下會講。先看如果你只打「時間快到的時候提醒我一下」會拿到什麼。
>
> 它會自己挑一個做法：可能跳一個 alert 擋住畫面，可能整頁變紅，也可能它覺得進度條已經夠明顯，什麼都沒改。
>
> 你拿到哪一個，取決於它猜中沒有。回想一下前面那個 0.31：這句話落下去，幾個答案的分數差不多高，它只能挑一個。
>
> 中間這四題，是你沒寫進去它就會自己選一個答案的地方。
>
> 第一題，什麼時候算最後一段？剩 60 秒，還是剩一成？先想清楚再往下，因為如果有人把整場設成 30 秒，那一開始就該是警示狀態嗎。
>
> 第二題，要變的那一塊會不會撞到舊規則？上一頁的 prompt 裡有一條「只有發射是實心主色，其他保持灰階」。
>
> 現在你要某個東西變顯眼，這兩條直接衝突。
>
> 你要它讓哪一邊？第三題跟第四題是同一類，都是狀態互相影響。按下待機的時候呢？暫停在剩 30 秒，警示要留著還是解除。
>
> 按下返航歸零之後呢？畫面要回到原樣，還是停在警示狀態？沒講的話，它多半只處理倒數那一條路。旁邊那一條也寫進去：加一句不要做什麼。
>
> 例如不要跳 alert、不要用閃爍。不寫的話它會自己挑一個，而閃爍實際跑起來會比你想的刺眼很多。
>
> 最後是驗收。上面那四題，你寫進去幾條就按幾條，不是看它有沒有變好看，是一條一條對你自己寫的規格。
>
> 25 分鐘等一次太慢，所以先叫它把倒數改成從 65 秒開始跑，驗完再改回原本的分鐘數。然後按三下。
>
> 第一下，倒數跑到你寫的那個門檻，畫面有沒有照你寫的那樣變。
>
> 第二下，在警示狀態下按待機，再按發射，跟你寫的一樣嗎。第三下，按返航歸零，畫面有沒有回到你寫的那個樣子。
>
> 壞掉通常是壞在後面兩下，不是壞在倒數。倒數是它多半會做到的部分，狀態怎麼互相影響才是沒講就會漏的地方。
>
> 這件事之後你會一直遇到：它把你說的那條路做得很好，沒說的那幾條路就空著。所以驗收的時候不要只走主線，要去按那些你沒講的按鈕。
>
> 還有一個你這一題很可能用得到的：改到一半覺得越改越亂、想回到還沒動之前，打 `/rewind`。
>
> 它會列出你這次對話送出過的每一句話，選一個時間點就退回去，程式碼跟對話可以分開退。有一條限制要記住，它只管得到 Claude 自己改的檔案，用指令刪掉或搬走的救不回來，所以動工前先存一次檔還是最保險的做法。

**這頁的教學意圖**：沒有標準答案的一題，學員自己定規格、自己驗收。
**預估時間**：8 分鐘（含實機）

## Slide 41｜讓計時器使用 API 取得資料

**畫面**
膠囊「現在開 Claude Code」／左欄 prompt（三點需求加一句「這個 API 不用金鑰」）／右欄它拿回來的 JSON 與 warn Callout「第 3 點不要拿掉」。

**逐字稿**

> 你的計時器目前所有東西都寫在 index.html 裡面，它不會去外面拿任何資料。這一步讓它在載入的時候，去一個公開的天氣服務，要今天台北的日出與日落時間。
>
> 左邊這段 prompt 用複製的，不要自己打，那個網址很長。
>
> 它寫了三點。第一點是什麼時候去拿：頁面載入的時候。第二點是拿回來之後放哪裡、長什麼樣。第三點是拿不到的時候怎麼辦：不要讓畫面壞掉，那一行顯示「離線」就好。
>
> 為什麼挑這一個服務？因為它不用金鑰、不用註冊，網址貼上去就能打。前面看過的那些 API 多半要先申請一組金鑰，光是申請就會卡掉不少時間，所以先用打得通的這一個，把整條路走完一次。
>
> 右邊是它拿回來的東西。大括號包起來、一行一個欄位、左邊名字右邊值。
>
> 前面餐廳點單那個比喻裡的出菜明細，長的就是這個樣子。再回頭講第 3 點，那一點不要拿掉。不寫那一句，它只會處理「拿到了要怎麼顯示」，不會處理「拿不到怎麼辦」。
>
> 網路一斷，那一行就會一直停在載入中，而你會以為是自己哪裡寫錯了，回頭去翻程式碼翻半天。
>
> 這裡有一條原則：只要是去外面拿資料，就有拿不到的時候。拿不到的時候畫面要長什麼樣，是你要先決定的，它不會幫你決定，它只會讓那一格空在那裡。改完存檔，重新整理瀏覽器就看得到。
>
> 如果那一行顯示的是「離線」，代表請求送出去了但沒拿回來，先檢查網路，再把那個網址貼進瀏覽器，確認它自己打得通。

**這頁的教學意圖**：第一次接外部資料，重點不是接得起來，是「拿不到的時候畫面長什麼樣」要先決定。
**預估時間**：5 分鐘（含實機）

> 接下來換一種產出，不是網頁。
