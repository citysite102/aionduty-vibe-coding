## Slide 43｜叫它寫一個批次改檔名的 Node.js 腳本

**畫面**
左上角灰標籤「補充範例」／Prompt 卡（「副檔名保持原樣」與「先印出對照表給我確認」標成橘黃）／右欄執行前後的檔名對照。

**逐字稿**

> 先看左上角那個標籤：補充範例。這一頁不用改你的計時器，也沒有東西是你漏做的。它在這裡的作用，是讓你看到 AI 幫你做的不只有網頁。
>
> 情境是批次整理混亂的檔案。一堆命名亂七八糟的圖片，要重新命名成流水號，再分類進不同的資料夾。
>
> 這種工作不需要麻煩工程師，Claude Code 寫個小腳本就處理得完。右邊的對照很直白。
>
> 執行前是三個檔名三種風格，執行後變成日期開頭接三位流水號，而副檔名各自保持原樣。prompt 裡有兩個地方標了色。
>
> 第一個是「副檔名保持原樣不要改」，那是邊界。
>
> 第二個是「先印出預計的新舊檔名對照表給我確認，我說 OK 之後你再實際執行」。為什麼要先看對照表？因為改檔名是覆蓋，不是新增。
>
> 它把 100 個檔案改完，你才發現規則不是你要的，原本的檔名已經沒了。這跟改程式碼不一樣，程式碼有 Git 可以退回去，檔名沒有。
>
> 凡是這種「做完就蓋掉原本那個」的動作，都要先看一眼再放行。底下那個提示是實務上會卡住的地方：腳本通常用 Node.js 或 Python 執行。
>
> 走桌面版的話請它幫你裝；Python 要自己到 python.org 下載安裝。還有一個常見的問題：這個用 Cowork 不是也可以？
>
> 可以。差別在產出物。腳本留得下來，下次換一百張圖，再跑一次就好；Cowork 是這一次幫你做完，下次還要再講一遍。
>
> 這一頁示範的是產出一個能重複用的工具，不是比誰改得快。

**這頁的教學意圖**：AI 的產出不只有網頁；而「做完就蓋掉原本那個」的動作要先確認再執行。
**預估時間**：4 分鐘

## Slide 44｜爬蟲：讓腳本自己開瀏覽器，抓成一張表

**畫面**
左上角灰標籤「補充範例」／情境：每週手動整理同一批網頁／「為什麼要開一個真的瀏覽器」／「先找有沒有不用爬的路」（拿 HN 的 `robots.txt` 當證據）／Prompt 卡分兩段，三行標成 sky／amber 的「出去連別人的網站，有三條線要守」。右欄跟「為什麼要開一個真的瀏覽器」同一個 step 出現：HN 的清單（含一則沒有外連網址的 Ask HN），往下是跑完的 `hn-digest/`。

**逐字稿**

> 一樣是補充範例，左上角那個標籤還在。情境你大概做過：每週把同一個頁面上的清單複製到 Excel，標題、日期、連結，一則一則貼。
>
> 這件事每次都一樣，所以它可以變成一支腳本。先講一個你可能會問的問題：為什麼要開一個真的瀏覽器，不能直接把網頁抓下來就好？
>
> 因為現在多數網站的內容，是你打開之後才由程式算出來的。你直接去抓網頁原始碼，拿到的是一個空殼，裡面沒有你看到的那些字。
>
> Playwright 這個工具是真的開一個瀏覽器、等畫面長出來再抓，而且它能點、能填、能捲。
>
> Hacker News 連出去的那些文章什麼寫法都有，靠猜不如直接開一個瀏覽器，把畫面上的字拿下來。
>
> 不過在寫爬蟲之前，先做一件事。你在網址後面接一個 robots.txt 打開來看。Hacker News 那份的第一行寫著 Crawl-delay 冒號 30，意思是它請你每 30 秒才抓一次。
>
> 你要抓 20 篇，光等就要 10 分鐘。但它有官方 API，那條路沒有這個限制。所以這一頁的腳本分成兩段。
>
> 第一段拿清單，走官方 API，不爬網頁。第二段才是爬蟲：那 20 篇連出去的文章，有的是部落格、有的是 GitHub、有的是新聞站，各是各的，沒有共通的出口，那一段才輪到瀏覽器。
>
> 這個順序比這支腳本本身重要：先找有沒有不用爬的路，沒有才爬。換成別的網站也一樣，先看 RSS，網址後面接一個 slash feed，再看有沒有 API，都沒有才爬。
>
> 而且這件事你不用自己查，直接問它就好。你看右邊那個清單，第三則是 Ask HN，那種是純討論，沒有外連網址。
>
> prompt 裡我寫了「沒有外連網址的就跳過」，就是為了它。不寫的話整支腳本會在那裡掛掉。Prompt 我標亮了三行。
>
> 第一行是邊界：只動這一個公開頁面，不要登入，不要跳到別的網域。不講的話它很可能順著連結一路爬出去，那就不是你要的東西了。第二行是每個動作之間停一秒。
>
> 這一條等一下單獨講。第三行是 headless: false。headless 的意思是不開視窗、在背後跑。
>
> 第一次我要你關掉它，讓瀏覽器真的跳出來，你看著它自己打開網頁、自己按載入更多、自己捲下去。看完之後再改成背後跑就好。
>
> 另外 Playwright 要另外裝，而且它會連自己那一份瀏覽器一起裝。你不用先去弄，跟它說「缺什麼就幫我裝」它會處理。
>
> 【等待 Agent 執行，不補旁白】這一頁跟前面每一頁都不一樣：前面那些東西壞掉，壞的是你自己的檔案；這一支腳本是出去碰別人的伺服器。
>
> 第一條，只抓不用登入就看得到的東西。要登入才看得到的，那是別人給你的帳號權限，不是公開資料，用程式去撈跟你自己點進去看是兩回事。
>
> 第二條，抓之前先問它一句：「這個網站的 robots.txt 跟服務條款怎麼寫？」多數網站會寫明哪些路徑不給抓。
>
> 這份東西它讀得懂，你不用自己去找。第三條，剛才那個停一秒。那不是客氣，是你一秒鐘打人家一百次，對伺服器來說跟攻擊沒有分別。
>
> 輕的結果是你的 IP 被擋掉，重的就是另一回事了。
>
> 我講這三條不是為了嚇你。這件事很好用，好用到你會順手一路往下做，所以界線要先講在前面。多停一秒、少抓一個需要登入的頁面，成本幾乎是零。
>
> 這一頁真正的產物在 prompt 的最後一段：腳本跑完之後，你直接讀 articles 裡的內容，幫我寫一份 digest.md，每一篇用中文三句話，附原始連結，按熱度排。
>
> 所以你最後打開的是一份中文摘要：二十篇今天最熱的討論，照熱度排好。這才是你一開始想要的東西。
>
> 這裡的分工要注意：摘要這件事沒有寫進程式，也沒有另外接一支 API，是它讀完檔案直接寫給你的。
>
> 腳本只負責把東西搬回來，那件事它做得又快又穩；讀懂內容是它在對話裡做的。
>
> 兩邊混在一起，你會得到一支又慢又難改的腳本。還有一條我寫在 prompt 裡：抓壞的那幾篇直接標「抓失敗」，不要自己編。
>
> 不講這一句，它可能會從標題猜一段內容給你，而那段話看起來跟真的一模一樣。

**這頁的教學意圖**：重複的網頁整理可以變成一支腳本；要真的開瀏覽器才抓得到算出來的內容；出去碰別人的網站有三條線要守。
**預估時間**：6 分鐘（含實機）

## Slide 45｜Claude Code 做得好與做不好的事

**畫面**
兩張並排的大卡。左「它的強項」四條，右「你得自己補的地方」四條。

**逐字稿**

> 計時器、警示功能、接一支天氣 API，你到這裡已經讓它動手做過這幾件了，所以現在可以講一件比較誠實的話：它有它做得好的地方，也有它做不好的地方，而且做不好的那幾種很有規律。
>
> 左邊第一條是目標很明確的單一任務。計時器、單位換算、批次改檔名、把一份資料整理成另一種格式。
>
> 判斷標準寫在後面：講得出「做完長什麼樣」的，它做得又快又好。你前面做的那個計時器就落在這一條。
>
> 第二條，照著錯誤訊息找原因。把整段紅字丟給它，它會自己翻遍整個資料夾找出哪一行有問題，這件事它比人快得多。
>
> 第三條，讀懂一個你沒看過的專案。請它把別人的專案讀一遍，用白話講這東西是怎麼跑起來的、哪個檔案負責什麼。
>
> 左邊第四條就是前面那兩支腳本在做的事：把重複在做的事變成一支腳本。判斷標準很白，同一件事你做過兩次，就問一句「這個能不能寫成腳本」。
>
> 右邊那一欄的標題是「你得自己補的地方」，不是「它不會的事」。前三條讀起來很像它的缺陷，但它們其實是你的工作清單，三條都是你補得上的。
>
> 第四條不一樣，那一條你補不上，也不該補：要用你的身分才成立的事。登入、按同意、付款、把權限交出去。
>
> 它可以把前後每一步都做完，然後停在那一下等你。部署那一段講過同一件事，那不是工具還沒做到，是它本來就不該替你做。
>
> 第一條，一句話就要一個大系統。「幫我做一個 Facebook」這種。範圍太大，它會自己決定一堆你沒同意的做法，等你發現的時候已經改到看不懂了。
>
> 第二條，它不會主動說「我不確定」。這一條是三條裡面最危險的。它沒把握的時候，答案看起來跟有把握的時候沒兩樣，一樣流暢、一樣肯定。
>
> 所以你不能從它的語氣判斷這件事對不對，你得自己查，或是叫它實際跑一次給你看。前面說驗證歸你，理由就在這一條，不在它笨不笨。
>
> 第三條，你沒說出口的偏好。你說「再大器一點」，它可能把所有字放大兩倍。腦子裡的畫面它拿不到，你得講到具體。講不出來就貼一張圖給它看。
>
> 你自己寫警示那一題，如果只打了「時間快到提醒我一下」，拿到的那個結果就是這一條。

**這頁的教學意圖**：右欄不是「它不會的事」，是「你補得上的事」，三條各對應一個前面撞過的具體經驗。
**預估時間**：3 分鐘

## Slide 46｜該用對話框還是 Claude Code？五個情境
**畫面**
分界一行：這件事需不需要讀寫你電腦裡的真實檔案／五張情境卡／膠囊「先自己想，再往下」／五個建議做法一起出現／收尾「這一頁分的是工具，不是分方法」。

**逐字稿**

> 學完一個工具之後，最容易發生的事是拿它去做所有事情。所以這一頁反過來練：什麼時候不該用它。
>
> 五個情境，每一題只問一件事：這件事需不需要讀寫你電腦裡的真實檔案。不需要的，對話框或現成的無程式碼工具就夠；需要的，才輪到 Claude Code。
>
> 顏色標的是這條分界，不是哪一題比較高級。情境一，每週一從系統匯出報表寄給主管。情境二，短期活動網頁，下週上線，只收集與顯示資訊。
>
> 情境三，舊有系統要新增忘記密碼，要讀懂舊資料庫的結構，還要接上目前在用的信件服務。情境四，高度客製化的個人記帳工具，你想自己掌控每一個畫面細節與資料存放方式。
>
> 情境五，你想了解目前實作的爬蟲邏輯，不需要改程式碼，只要看懂架構並規劃下一步。畫面上出現「先自己想，再往下」的時候就停在這裡，把五題各自歸到一邊去。
>
> ⋯⋯答案。情境一，如果那份報表本來就在 Google 試算表裡，用對話框請它寫一段 Google Apps Script，那是試算表內建的自動化腳本，從「擴充功能」那裡開啟 Apps Script 貼進去，再設定每週自動跑。
>
> 情境二用 AI App Builder 直接生成並上線，Lovable、Base44、v0 都是這一類。
>
> 要提醒一件事：這類平台本身就做得出表單跟後台，多數情況不用再外接一個表單工具。
>
> 這兩題都不需要碰你電腦裡的檔案。剩下三題要 Claude Code。情境三，用它打開現有專案，但先請它讀一遍、講出打算怎麼改，你看過那個做法再讓它動手。
>
> 舊系統不要讓它邊讀邊改，理由就是上一頁那條「範圍太大它會自己決定一堆你沒同意的做法」。
>
> 情境四，先在 Claude 的 Design 把畫面設計出一版，版面跟流程都確定了，再帶進 Claude Code 實作。
>
> 這一題你要的是掌控每一個細節，所以草稿階段先不要讓它寫程式，畫面定了再動工。情境五，用它打開那個專案，而且講明「只讀不改，先用白話講一遍架構」。
>
> 這一題它做得到是因為它讀得到整個資料夾，所以答得出哪個檔案負責什麼。第五題再看一眼。它一行程式碼都沒有要改，但還是落在 Claude Code 這一邊，因為它得讀得到那個專案。
>
> 所以分界不是「要不要寫程式」，是「要不要讀寫你電腦裡的檔案」。最後，這一頁分的是工具，不是分方法。
>
> 把需求講清楚的問法、把規則寫下來的做法，上面五題選哪一邊都用得上。

**這頁的教學意圖**：選工具的分界只有一條，就是要不要讀寫你電腦裡的真實檔案，跟要不要寫程式無關。
**預估時間**：5 分鐘

## Slide 47｜你手上現在有的三樣東西

**畫面**
三條驗收清單／「現在做一件事：存檔」含一句可複製的 prompt ／amber 的「存不起來的時候」。

**逐字稿**

> 這個計時器接下來每一章都會回頭改，所以這裡要對清楚。下面兩件事應該都成立。
>
> 第一，你有一個 mission-timer 資料夾，裡面有一個 index.html。整個計時器就是這一個檔案，不是一整包東西。
>
> 第二，對那個 index.html 按兩下，瀏覽器會打開，倒數會動，底下有一行日出與日落時間。
>
> 那一行是它去外面的 API 拿回來的，不是你自己打上去的。
>
> 如果有一條對不上，不要卡在那裡自己翻程式碼找。把那個檔案打開，連同你原本寫的那段 prompt 一起貼回 Claude Code，跟它說「我要的是這樣，現在是這樣，幫我看哪裡沒做到」。
>
> 這個動作的形狀就是：拿你寫下的規格，去對它做出來的東西。整門課後面所有的驗收，都是這個動作的放大版。
>
> 然後現在做一件事：存檔。前面講過 Git 是可以回去的存檔點，但你還沒有實際存過一次。畫面上這句話複製過去就可以：幫我把這個資料夾建立成 Git repository，做第一次 commit，訊息寫「第一個作品完成」。
>
> 存完之後，Claude 改壞了這個資料夾裡的東西，你都回得到這一次的狀態。有一點要記著：存檔之後才新增的檔案不在裡面，那要再存一次才算。
>
> 這一步有兩種常見的卡法，撞到的話不是你做錯什麼。第一種，它回一段紅字，說 git 不知道你是誰，要你設定名字跟 email。
>
> 那不是你做錯，是這台電腦第一次用 git。把整段紅字貼回去，跟它說「幫我設定好再重跑一次」，這件事就結束了。
>
> 第二種，它說找不到 git。那就跟它說「幫我確認這台電腦有沒有 git，沒有的話告訴我怎麼裝」，照它給的步驟走。Windows 比較常遇到這一種。
>
> 這一步從頭到尾沒有碰到 GitHub。你剛才那一次存檔只存在你自己的電腦裡，沒有上傳到任何地方，所以不會有帳號或授權的問題。
>
> 真正要跟 GitHub 打交道是在章節七，那時候它會停下來要你到瀏覽器登入並按同意，跟前面講部署授權是同一回事，那一下它代不了你。


**這頁的教學意圖**：章節三的驗收點，兩條都指得出具體的東西；並且完成第一次 commit。
**預估時間**：4 分鐘（含實機）
