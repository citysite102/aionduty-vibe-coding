## Slide 51｜兩種花錢的方式：邊做邊花，還是先花再省

**畫面**
開場一句接上一頁的帳。左右兩張卡：邊做邊花（Opex），下面三筆延後的帳；先花再省（Capex）。

**逐字稿**

> 先把計價講完整，因為這裡有一個地方多數人第一次聽會意外：你送進去的字跟它吐回來的字，兩邊都計價。
>
> 不是只有它的回答要錢。你貼進去的那份文件也要錢，而且你貼得越多越貴。
>
> 知道這件事之後，同樣一件事的花費會落在下面兩種形狀的其中一種。
>
> 左邊是邊做邊花。這是你目前為止做計時器的方式：一開始不用準備什麼，想到就開工。這個做法沒有錯，前期它確實最快。
>
> 但它有三筆帳是當下不痛、會拖到後面一次還的。
>
> 第一筆，額度燒得快。沒有規矩也沒有檢查，它做錯了你只能一輪一輪叫它重做，而每一輪都要把前面的來回重讀一次。你付的不是一次的錢，是同一件事付了五次。
>
> 第二筆，之後改不動。半年後回來看，是一堆沒有結構、連你自己都看不懂的程式碼。這一筆的麻煩在於它沒有帳單，你只會覺得「這個東西不想碰」。
>
> 第三筆，安全性要重補。金鑰寫死在程式裡、誰都讀得到的資料，前期沒管，後期要拆開重來。這一筆你後面在章節八會親手處理一次。
>
> 右邊是先花再省。一開始要先花時間：想清楚東西怎麼組起來、寫下規矩、加上會自己跑的檢查。這一段很難熬，因為它是純付出，畫面上什麼都還沒有。
>
> 架好之後，每次生成新功能的成本會降下來，因為架構、測試跟規則都在，它比較常一次就寫對，來回修改的次數變少。
>
> 我要特別說一件事，免得你聽完覺得自己一直都做錯：這兩邊不是對錯，是時機。
>
> 你第一天試一個點子，右邊那一套是浪費，你會花一個下午準備一個隔天就丟掉的東西；你一個東西打算用半年，左邊那一套會把你吃掉。
>
> 判準是這樣：問自己這東西你打不打算再回來改。答案是會，就值得先花那一段。這一章接下來在做的，就是把右邊那一欄的門檻降到你一個人也做得起來的程度。

**這頁的教學意圖**：前期省下的準備時間是借的，三筆帳會在後面一次還；兩種做法的差別是時機不是對錯。
**預估時間**：4 分鐘

## Slide 52｜AI 程式工具的付費模式：訂閱制與計量付費

**畫面**
開場提問。中段兩大塊：官方終端機工具（Claude Code 的兩種計費來源）、AI 輔助編輯器（月租與自備金鑰）。最後一個 amber 的 Callout，講額度燒完的時候怎麼辦。

**逐字稿**

> 先回答標題那個問題，因為這是我最常被問的一題：多數情況下不用另外付。
>
> 現在主流的 AI 開發工具大多支援兩種模式，一種是拿你已經有的訂閱帳號直接登入，一種是走 API 按用量計費。你要知道自己該走哪一種，得先知道這兩種差在哪。
>
> 先看 Claude Code。第一次打 `claude` 啟動的時候，它會問你要用哪一種。
>
> 第一種是訂閱制。你有網頁版的 Pro 或 Max，直接登入個人帳號就好，額度共用，不用另外付錢。這裡有一個很多人會撞到的但書：Pro 的額度拿來跑 Claude Code 會用得比你想像中快。它有一個五小時的滾動區間，還有每週的上限。如果你是每天重度使用，Pro 大概撐不住，得升級 Max 或改走 API。
>
> 想知道自己用到哪了，在對話裡打 `/usage`。訂閱方案會看到一張額度用掉多少的長條圖，按 d 或 w 可以切換看最近一天或一週。這個指令你現在就可以記起來，下一頁還會再用到它。
>
> 第二種是 Anthropic API 計量付費。不用月租，去 Console 註冊並儲值，最低五美金就能開通，之後按實際用量扣。
>
> 怎麼選，判準很簡單：偶爾用就走 API，用多少算多少；每天都用，訂閱制通常便宜得多。先從便宜的開始，撞到上限再升級。
>
> 下面那一塊是 AI 輔助編輯器，Cursor 那一類。它們也是兩種：月租訂閱，大概二十美金起；或者自備金鑰，在軟體裡填入你自己的 API key，免月租。自備金鑰的好處是同一個介面裡可以切換不同廠牌的模型。
>
> 最後這個橘框是這一頁最實用的部分，講額度突然不夠用的時候。
>
> 第一句要先聽進去，因為額度突然歸零的時候，人的第一個念頭通常是「我是不是搞砸了什麼」：額度是按它讀了多少、寫了多少字在算，跟你做得對不對無關。
>
> 你不是因為做錯才被扣光的。做對也一樣扣。
>
> 成果還沒出來就先燒完，多半是這三件事之一。第一，一次交代太大的事，它會把整個資料夾翻過一遍才動手，光讀就花掉很多。第二，卡在同一個錯誤反覆重試，每一輪都要把前面的來回重讀，越後面越貴。第三，整場開著同一個對話，對話越長，每句話要帶的前文就越多。
>
> 當下可以做的有三個。打 `/usage` 看還剩多少，訂閱制是五小時一個區間，等它重置就會回來。不想等，就去 Console 儲值走 API，兩種登入方式可以隨時切換。還有一個習慣現在就可以養成：換一個新題目之前先打 `/clear` 開一段新對話，這一個動作省下來的比你想的多。
>
> 最後，畫面上那行小字也要當真：這些費用是 2026 年中的資訊，各家改價很頻繁，Cursor 尤其改過很多次。你要做決定之前，去官方頁面看當下的數字。

**這頁的教學意圖**：有訂閱就直接登入，不用另外付；額度燒完不是你做錯，而是三個特定行為造成的。
**預估時間**：6 分鐘

## Slide 53｜自己做跟外包，成本與交期差多少

**畫面**
上方一句主張。中間三個情境的分頁切換。下面兩大塊：花的錢（外包報價 vs token 費用），花的時間（交期與你的工時分開列）。最後一個但書框。

**逐字稿**

> 這一頁的主張先講，而且它跟多數人的預期不一樣：花這筆錢，換到的不是省下工程師的薪水，是把「驗證一個點子行不行」從排隊等外包壓到當天。
>
> 外包最貴的往往不是報價。是你得先把需求寫清楚、等對方排程、來回改幾輪，然後才知道這個點子根本不行。那個流程的成本是時間，而時間不在報價單上。
>
> 上面這三個標籤是三種情境，數字會跟著換。我先停在內部管理工具這一個：有前台畫面、後端 API、還有資料儲存的訂單管理系統。
>
> 花的錢這一塊。找人外包大概七萬五，自己指揮 AI 做，token 費用大概四百五十元。
>
> 這個對比很誇張，誇張到我自己看到都會想確認一下。所以我把前提講清楚，不然你會拿它去做錯誤的決定。
>
> 第一，這四百五十元是走 API 計量的人實際會被扣的錢。你走訂閱制的話根本看不到這筆扣款，你付的是月費。這個數字對訂閱制的人的意義是「這件事會吃掉多少額度」：五小時的來回，Pro 的五小時額度大概就用在這裡了。
>
> 第二，單價是公告的，輸入五美金、輸出二十五美金，每百萬 token，快取讀取大概是輸入的十分之一，匯率抓三十二。這幾個數字你查得到。但用量是估的，那是抓一個常見的來回次數推算出來的，你自己做同一件事可能差兩倍。
>
> 下面是時間，這一塊請特別注意它的排版：交期跟工時是分開列的，而且旁邊寫著「這是兩件不同的事，不要放在一起相減」。
>
> 交期是從你開口到拿到東西。外包三週，你自己做當天。但外包那三週大多在等，不是在做，所以那不是三週的人力。
>
> 工時是你實際坐在電腦前的時間。外包你也要花數小時：寫需求、驗收、來回。自己做是五小時。所以自己做並沒有讓你的時間變成零，只是把時間換成花在你自己的東西上。
>
> 我切到自動化小腳本這一個。這一筆的數字你剛才在這一章開頭看過：外包一萬、五天，自己做七十元、一小時。
>
> 再切到修一個環境問題：套件版本衝突，專案跑不起來。外包八千、兩天，自己做三十元、半小時。這一格其實是最貼近你日常的，因為它不是做新東西，是把卡住的東西弄通。
>
> 最後這個但書是整頁最重要的一句：這筆帳裡有一項不是零，就是你的時間跟判斷力。
>
> token 很便宜，便宜到可以忽略。但你得看得懂它做了什麼、抓得出它哪裡做錯，而那個能力不會自己長出來，也不在報價單上。
>
> 講白一點：這門課大部分的時間其實是在長那個能力，不是在教你省錢。省錢只是順便。

**這頁的教學意圖**：自己做省下的是交期不是工時；金額的量級差很多，但判斷力那一項不是零。
**預估時間**：6 分鐘

## Slide 54｜怎麼少花一點：兩個指令與三個常見的浪費

**畫面**
開場一句。兩張卡：`/usage` 看用量、`/effort` 調深淺。最後一個 sky 的 Callout 列三個浪費。

**逐字稿**

> 額度不夠用的時候，多數人第一個動作是換成小一點的模型，然後覺得它變笨了，然後又換回來。
>
> 我的建議是：先看帳，多半不用換。
>
> 第一個指令你剛才已經看過，`/usage`。跑過一次之後打它，看得到這次花了多少、額度什麼時候重置。這個動作要養成習慣，因為沒有這個數字，你後面調什麼都是憑感覺。
>
> 第二個指令是 `/effort`，調它每次要想多久。想得越久越貴。預設是 high，事情簡單的時候調到 low 或 medium，省下來的是實打實的 token。
>
> 這裡要分清楚兩個指令：`/model` 換的是模型等級，`/effort` 是在同一個等級裡調深淺。兩個可以分開用，你不需要為了省錢就降級模型。
>
> 底下那句附註是最容易踩的坑，而且它沒有任何提示：它會記住你設的等級，下次開新對話還是同一個。所以你某天調低之後，過幾天遇到難題覺得它變笨了，先打一次 `/effort` 看它現在停在哪一級，不要急著換模型或換工具。
>
> 最後這個框是這一頁真正的重點：真正省下來的通常不是旋鈕。
>
> token 最容易被浪費的地方有三個。它手上沒有對的工具，所以只能用猜的，猜錯再重做。你丟了一堆它用不到的資料給它，每一輪都在重讀。或者一個題目一次交代太大，它得把整個專案翻過一遍才動得了手。
>
> 這三個聽起來像省錢的技巧，其實不是。它們是下一段要做的事的骨架，而省錢只是它的副作用。
>
> 順序記一下：先看帳，再調深淺，最後才去動那三個浪費。前兩個花你三十秒，第三個才是真正把數字壓下來的地方。

**這頁的教學意圖**：省錢的順序是先看帳、再調深淺，而真正的大頭是工具、資料量與題目大小。
**預估時間**：4 分鐘

## Slide 55｜Agent 的工具、規則文件與任務拆解

**畫面**
開場一段說明這三塊跟六個零件的關係，以及權限會先插一段。下面三格：讓它有工具可用（MCP／Skills）、只給它需要的資料（CLAUDE.md／壓縮清理）、把大題目切小（一個需求拆成三條待辦）。

**逐字稿**

> 那三個浪費，對應到三件你要建的東西。六個零件裡，前兩塊是你真的要建出檔案的；第三塊零件表沒有列，但你每次交代工作都會用到。
>
> 這三塊有一個共同點值得先講：模型換成更新的版本，這三塊照樣要做。它們不是在彌補模型的不足，是在給它一個可以工作的環境。
>
> 第一格，讓它有工具可用。原則只有一句：查不到的東西它就會用猜的。這裡只先給兩個名字，系統擴充叫 MCP，讓它碰得到你電腦以外的東西；專屬技能叫 Skills，把你重複交代的那套流程包起來。定義下一頁整頁在講，這裡先知道有這兩樣。
>
> 第二格，只給它需要的資料。這一格的難處是兩邊都會出事：該給的沒給，它用猜的；塞太多，它抓不到重點。專案手冊就是在管該給的那一批。
>
> 這一格底下還有一個東西你遲早會遇到，叫壓縮。對話快滿的時候，系統會把先前的內容摘要一次然後重開，你也可以自己打 `/compact` 主動做。這件事要記的是它的代價：這個過程會掉細節。所以重要的東西不要只存在對話裡，那正是手冊存在的理由。
>
> 第三格，把大題目切小。一次交代太大，出錯的機會就變高。畫面上這個例子你等一下會一直用到：「我想知道自己今天完成幾趟任務」這一句是願望，不是指令。把它轉成待辦清單，變成三條：一趟任務要記下哪些欄位、這些紀錄存在哪裡、畫面上要怎麼呈現。三條各自都小到可以驗收。
>
> 最後講一下接下來的順序，因為它不是照三格排的，我怕你等一下覺得跳掉了。
>
> 工具講完，會先插一段權限與邊界，那是六個零件裡的第四塊。理由很單純：你已經把手交出去了，得先知道怎麼收緊它碰得到的範圍，再往下動手才安全。先給工具再給邊界，順序反過來會出事。

**這頁的教學意圖**：三個浪費對應三塊要建的東西；權限會插在工具之後、動手之前，這個順序是刻意的。
**預估時間**：4 分鐘

### 2.【矛盾】`/usage` 的說明在 Slide 52 與 Slide 54 講的不是同一件事

- Slide 52 寫「訂閱方案會看到額度用掉多少的長條圖，按 d 或 w 切換」。Slide 54 寫「跑過一次之後打它，看得到這次花了多少、額度什麼時候重置」。
- 「這次花了多少」跟「本期額度用掉多少」是兩個不同的數字，走 API 計量的人看到的畫面跟訂閱制也不一樣。兩頁相隔兩頁，學員讀完會以為自己漏掉了什麼。
- **建議**：以 Slide 52 的描述為準（它先出現，而且有區分訂閱制），Slide 54 那張卡改成「打它看本期額度用掉多少、什麼時候重置」，把「這次花了多少」拿掉。

### 3.【缺漏】Slide 53 的「快取讀取約輸入的十分之一」沒有解釋快取是什麼

- 這是頁面上唯一一個沒有被定義就拿去算錢的名詞，而它就寫在單價旁邊，讀者會停在那裡。token 在同一頁有定義，匯率不用解釋，只有這一個懸著。
- 這一頁的取捨是對的（不該在講錢的地方展開快取機制），但完全不給線索也不行。
- **建議**：那行小字補一個括號，例如「快取讀取（同一份東西第二次讀進去會便宜很多）約輸入的十分之一」。一句就夠。

### 4.【B-4】Slide 54 收尾說「下一段要做的事的骨架」，這一點是對的，但 Slide 55 沒有把這條線接起來

- `11c3` 的檔頭註解寫明了設計意圖：三個浪費對應下一頁的三格（工具、只給需要的資料、把題目切小），「順序不要動」。但 Slide 55 的畫面上完全沒有提到這個對應，三格就只是三格。
- 結果是這條設計只有維護的人知道，學員讀不到。逐字稿這邊口頭接了一句，但講義上是斷的。
- **建議**：`21_M2_Pillars` 開頭那段補半句點名它接的是什麼，例如「這三塊對的就是上一頁那三個浪費」。不用逐條對照，一句就把線接起來。
