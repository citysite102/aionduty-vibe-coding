## Slide 59｜監督與邊界

**畫面**
開場一問。兩欄並列：「監督程度」（sky）與「邊界大小」（indigo），各附一個問句、兩端的文字、以及它決定什麼的一句話。下面一塊講兩個分開調，再一個 sky 的 Callout 講判斷標準、怎麼調，以及邊界要怎麼縮。

**逐字稿**

> 把工具交給 AI 之後，心裡大概會冒出一個疑問：放手讓它跑，會不會把我的東西改壞？
>
> 這個擔心是對的，它確實改得動你的檔案，課程前面就特別提過這件事。
>
> 但這件事情是可以調整的，而且有兩個地方可以調：一個是它要不要先問過你，另一個是它碰得到多大範圍。
>
> 先看左邊，監督程度。它問的是：它每做一件事，要不要先問過你？一端是每一步都停下來等你按同意，另一端是整段做完才回報。
>
> 監督程度管的是你要花多少時間盯著它。安全不是這一欄在管的，是另一欄那個邊界大小。
>
> 右邊是邊界大小。它問的是：它碰得到的範圍有多大？一端是只能讀、不能改任何東西，另一端是能改整台電腦、還能裝東西。
>
> 邊界大小決定的才是安全：它做錯的時候，最壞會壞到什麼程度。
>
> 這裡要記住的是：這兩個各調各的。調鬆了監督，不代表邊界也跟著變大；把邊界縮小，也不影響它要不要先問你。
>
> 兩種組合都成立：一種是它碰得到很多，但每一步都先問你；另一種是它只碰得到一個資料夾，然後你完全放手。兩種都合理，適合的情境不一樣。
>
> 還不熟的時候，我建議選後面那一種：把邊界縮到最小，然後放手。
>
> 理由是就算它整段跑歪，能壞的也就那一個資料夾。這比「每一步都盯著」實際得多，因為盯這件事撐不久。你盯到第二十次，大概就會開始無意識地按同意，那時候等於沒有在監督，但你以為自己有。
>
> 真正危險的只有一種組合：兩個都放到最寬。它碰得到全部，而你又沒在看它做了什麼。
>
> 那監督程度要怎麼調？邊界大小又要怎麼調？
>
> 調的方法不是兩根滑桿。Claude Code 把常用的組合做成了幾個模式，按 `Shift + Tab` 換，等一下會一個一個講。
>
> 還記得前面提到的那條判斷標準嗎：你驗得動多少，就放多少。看得懂它改了什麼，監督程度就可以放寬。不會檢查的話，就把邊界縮小，讓它做錯了你也賠得起。
>
> 邊界要怎麼縮，有兩個做法：限制它能用哪些工具，以及讓它只在一個資料夾裡工作。

**這頁的教學意圖**：監督程度管你的時間，邊界大小管風險；兩者獨立，不熟的時候先縮邊界而不是狂盯。
**預估時間**：4 分鐘

## Slide 60｜Claude Code 的六個權限模式

**畫面**
左欄是速查表，六張模式卡（手動 manual／設定值 default、acceptEdits、plan、auto、dontAsk、bypassPermissions），每一格最後一行標它調的是監督程度還是邊界大小。右欄是模擬器，三個分頁：終端機（一顆模擬 `Shift + Tab` 的按鈕加狀態列）、桌面版（輸入框左下角那個 Mode 下拉，Auto／Manual／Accept edits／Plan 加一列 Bypass permissions）、網頁版（`claude.ai/code` 輸入框旁的模式下拉，只有 Auto／Accept edits／Plan）。模擬器下面一段文字講當下那一邊怎麼切，整頁最底下一句收尾。

**逐字稿**

> 就是這六個模式。每一格最後一行標的，是它調的是監督程度還是邊界大小，你看那一行就知道它在管你的時間還是管風險。
>
> 名字跟循環順序改過好幾次，之後大概還會改。你要認的是每一格調的是監督程度還是邊界大小，那個不會變。
>
> 第一個是手動模式。它在畫面上叫 Manual，但設定檔裡的值是 `default`，兩個名字指的是同一個，看到哪一個都不要慌。
>
> 它是最安全的那一個：修改檔案、執行終端機指令之前會停下來徵求同意；純讀取不打擾，所以它不是每一步都問你，是動手之前都問你。它調的是監督程度，邊界沒有變。
>
> 這裡要澄清一件事，因為名字很容易誤導：設定值雖然叫 `default`，但它不一定是你開起來的那一個。Pro、Max 與 Team 方案在終端機跟 VS Code 開機在 auto，你要按第一下 `Shift + Tab` 才會進到手動。
>
> 但這一條有前提，我講清楚免得你打開發現對不上：桌面版不吃這一條，它記的是你上次在那個資料夾選過的模式。另外，剛裝好或剛升級的第一次、用 Enterprise 方案或 Console 的 API key、還有舊版本，開起來都會是手動。所以你自己開起來看到的是什麼，以輸入框那個下拉為準。
>
> 什麼時候用：金流、認證設定，或者你剛接手一個陌生專案的時候。
>
> 第二個，`acceptEdits`。它的名字比它實際放行的範圍窄，這一點要特別小心。
>
> 名字寫的是「自動接受編輯」，你會以為它只放行改檔案。實際上它連 `mkdir`、`mv`、`cp` 這一類搬檔案的指令也一起放行。而 `mv` 會搬走東西、會覆蓋東西。
>
> 所以它比你從名字猜到的鬆。它調的還是監督程度，改檔案不問，跑別的指令還是會問。
>
> 什麼時候用：你正在盯著看的那種連續小修改。
>
> 第三個，`plan`。它會翻專案、提出方案給你看，但不動任何檔案。注意這一格調的是邊界大小，不是監督程度：它把邊界縮到只能讀。
>
> 這一個是這六個裡面最被低估的。大改動之前先用它聽一遍方向，比你改完再回頭吵便宜很多。
>
> 第四個是 `auto`，也就是終端機開起來多半會在的那一個。它多數動作不問你，改由另一個模型在背後檢查這個動作跟你的要求對不對得上。方便，但那一道檢查不是你，所以動到重要的東西之前，自己切回手動比較實在。
>
> 第五個是 `dontAsk`，它只放行三種東西：本來就不用問的，例如讀你資料夾裡的檔案；你在設定檔的 `permissions.allow` 裡自己寫好的那幾條；還有 Hook 放行的。除此之外一律直接擋掉，而且不會停下來問你。
>
> 所以用它之前，你要先去設定檔裡寫清楚哪些指令可以跑，它才跑得了，沒寫就是不能跑。這也是為什麼它適合沒有人在旁邊看的場合，例如掛在自動化流程裡。
>
> 它調的也是邊界大小，但縮的方式跟 `plan` 不一樣：`plan` 整個鎖成唯讀，連該做的事都做不了；`dontAsk` 是留下你允許的那幾樣，其餘關掉。你要把邊界縮小的時候，它是最實際的做法，不過它只能在啟動的時候用參數指定，`Shift + Tab` 的循環跟桌面版的選單裡都按不到它。
>
> 最後是 `bypassPermissions`，無條件放行所有層級的操作。高危險的指令也一樣會過，例如刪掉檔案、把你現有的程式碼整份覆寫掉。它是兩個都放到最寬，也就是上一頁說唯一要小心的那一種組合，所以它只適合與外部隔離的 Docker 容器。
>
> 如果你不知道 Docker 容器是什麼，那就代表你現在不該用這個模式。
>
> 右欄那個模擬器分三邊。第一個分頁是終端機。我按一下這顆按鈕模擬 `Shift + Tab`，狀態列就換一個模式，每一個模式下面那行寫著它實際會放行什麼。你在真的終端機裡看到的狀態列就是這個東西。
>
> 第二個分頁是桌面版，這也是我們這門課主要在用的。桌面版不用背快捷鍵：點輸入框左下角那個顯示 `Auto` 的地方，選單就直接列出來了，Auto、Manual、Accept edits、Plan，右邊還有 1 到 4 的數字鍵可以按。
>
> 有兩件事要注意。第一，最下面那一列 Bypass permissions 沒有編號，它右邊是一個 Enable，要另外啟用，這個設計本身就是在提醒你它不一樣。第二，剛才說的 `dontAsk` 也不在這個選單裡。
>
> 桌面版跟終端機是同一個 Claude Code，模式的行為完全一樣，差別只在這裡用選的、那裡用 `Shift + Tab` 循環。
>
> 第三個分頁是網頁版，也就是 `claude.ai/code`。位置一樣在輸入框旁邊，但選單裡的東西更少，只有三個：Auto、Accept edits、Plan。
>
> 少掉的那兩個各有理由。沒有 Manual，是因為跑在雲端的工作階段不管你選哪一個，改檔案本來就先放行了，所以那一格直接顯示成 Accept edits。Bypass 則是完全不給用。
>
> 還有一種情況要分清楚：如果那個網頁其實是在遠端遙控你自己這台電腦，選單就會換成 Manual、Accept edits、Plan，因為檔案是真的在你的硬碟上。
>
> 最後補兩件事，都是你真的在操作的時候會撞到的。
>
> 第一件是 `Shift + Tab` 這顆鍵按下去會發生什麼。它是一個固定的循環，按一下換下一個，走完再回到頭。
>
> 終端機開起來多半停在 auto。按第一下切到 Manual，再按一下是 `acceptEdits`，再按是 `plan`。如果你的方案能用 auto，再按一下就繞回 auto，然後又從 Manual 開始。所以這四個就是轉一圈。方案不能用 auto 的話，循環就只剩 Manual、`acceptEdits`、`plan` 三個。
>
> 這裡還有一個會害你查不到資料的小陷阱：你拿 Manual 去搜官方文件可能搜不到，要搜設定檔裡那個值 `default`。
>
> 第二件是六個模式不會全部出現在循環裡。`bypassPermissions` 要你自己先啟用才會插進來，位置也在 `plan` 後面；`dontAsk` 永遠不在循環裡。
>
> 沒有哪一種模式永遠正確，所以不要挑一個然後一直用。
>
> 順序大概是這樣：陌生專案用 `default`，摸熟了切 `acceptEdits`，大改動之前先 `plan` 聽它講一遍。

**這頁的教學意圖**：認得出各模式調的是監督程度還是邊界大小，尤其 `acceptEdits` 比名字聽起來鬆、`plan` 管的是邊界不是監督。
**預估時間**：7 分鐘

> **狀態：已於 2026-09-20 逐條確認並套用。** 逐條決議（含不改的項目、查證結果與變體做法）記在

### 1.【矛盾】標題寫「六個權限模式」，速查表只有四格，內文第一句還說「就是下面這四個模式」

- 同一頁三處數字不一致：`SlideLayout` 的 `title` 是六個，速查表的引言寫「就是下面這四個模式」，卡片實際是四張。另外兩個（`auto`、`dontAsk`）只出現在底下那段文字裡，`bypassPermissions` 則同時在卡片與文字裡。
- 學員讀到標題會先數格子，數出四個，然後停在那裡。這正是 D-2 那條「特別注意跟自己矛盾的」：反駁標題的句子就在同一頁。
- **建議**：兩種改法選一種。標題改成「Claude Code 的權限模式速查表」（不帶數字，也符合 D-5 那條「數量詞不是內容」）；或者把 `auto` 與 `dontAsk` 也做成卡片，補成六格。前者省事，而且六格會讓速查表變得太滿。
- 改標題的話記得同步 `src/App.tsx` 的 `LIVE_TITLES`（D-5 最後一節）。

### 2.【矛盾】模擬器只演三格，但旁邊的文字說循環有更多格

- 檔案第 1 行的註解自己寫著：「這個模擬器只演 default → acceptEdits → plan 這三格。實際上 Pro/Max 開機在 auto，按第一下才進 manual，而且啟用的選用模式會插在 plan 後面。」
- 也就是說，學員按那顆模擬鈕看到的循環，跟底下文字描述的循環對不起來，而且畫面上沒有任何一句話說明模擬器是簡化過的。
- **建議**：模擬器的狀態列旁邊補一個小標，例如「示意：只演常用的三格」。旁邊已經有一個「介面為示意」的標籤，但那指的是外觀，不是循環格數。
- 不建議把 `auto` 加進模擬器：那會讓預設起始狀態變成全放行，第一眼的印象反了。

### 3.【會過期】這一頁與 `11d2_M1_TerminalKeys`（Slide 46）是同一批資料，兩頁都缺 C-1 註解

- 模式名稱、循環順序、Pro/Max 的預設值，這三樣全部是 C-3 點名最會過期的項目，而這兩頁的內容目前是一致的，代表有人同步過。沒有查證日期的話，下一個人只能整段重查。
- **建議**：兩個檔案各補 C-1 的三行，並互相點名對方（「這一組數值與 `30_Cheat_Perms` 同步，改一邊要改兩邊」）。這一條跟 5-2 那個「`11c2` 的數字是 `19a` 的複本」是同一種病。

### 4.【缺漏】`31_Cheat_Dials` 的「邊界大小」沒有告訴學員怎麼縮

- 旋鈕一有明確的操作（`Shift + Tab`），下一頁四個模式裡有三個都標著旋鈕一。旋鈕二在下一頁只對到 `plan` 一格，而 `plan` 是整個鎖成唯讀，不是「縮小」。
- 真正對應「縮小邊界」的是 `dontAsk`，但它被寫在最底下那段密集的文字裡，而且標明不在循環中。
- 結果是：整頁花一半篇幅建立的旋鈕二，學員讀完不知道實際要怎麼轉。
- **建議**：`31_Cheat_Dials` 最後那個 Callout 已經在講「怎麼轉」，在那裡補一句旋鈕二的答案，例如「邊界則是靠限制它能用哪些工具、以及讓它只在一個資料夾裡工作」。這一句也接得上章節八「放手之前，先設好四道邊界」那一頁。
