## Slide 61｜監督與邊界

**畫面**
開場一問。兩欄並列：旋鈕一「監督程度」（sky）、旋鈕二「邊界大小」（indigo），各附一個問句、兩端的文字、以及它決定什麼的一句話。下面一塊講兩個旋鈕分開動，最後一個 sky 的 Callout 講實際怎麼轉。

**逐字稿**

> 把工具給出去之後，第一個會冒出來的問題大概是這個：放手讓它跑，會不會把我的東西改壞？
>
> 這個擔心是對的，不要壓下去。它確實改得動你的檔案，這件事從章節三開始就是真的。
>
> 這件事你可以調。而且有兩個旋鈕可以轉，它們各自獨立。這一頁記住「兩個」跟「獨立」就夠了。
>
> 旋鈕一，監督程度。它問的是：它每做一件事，要不要先問過你？一端是每一步都停下來等你按同意，另一端是整段做完才回報。
>
> 這個旋鈕決定的是你要花多少時間盯著它。注意它決定的不是安全，是你的時間。
>
> 旋鈕二，邊界大小。它問的是：它碰得到的範圍有多大？一端是只能讀、不能改任何東西，另一端是能改整台電腦、還能裝東西。
>
> 這個旋鈕決定的才是安全：它做錯的時候，最壞會壞到什麼程度。
>
> 兩端我只標了文字，沒有給刻度也沒有給數字，因為中間有幾格是下一頁的事。
>
> 下面這一塊是重點：兩個是分開的，不會一起動。
>
> 權限開很大、但每一步都問你，這樣可以。權限縮到最小、然後完全放手，這樣也可以。這兩種組合都合理，而且它們適合的情境不一樣。
>
> 還不熟的時候，我建議選後面那一種：把邊界縮到最小，然後放手。
>
> 理由是就算它整段跑歪，能壞的也就那一個資料夾。這比「每一步都盯著」實際得多，因為盯這件事撐不久。你盯到第二十次，大概就會開始無意識地按同意，那時候等於沒有在監督，但你以為自己有。
>
> 要小心的只有一種組合：兩個旋鈕都轉到底。權限全開，又懶得看它做了什麼。
>
> 最後這個框講怎麼轉。轉的方法不是兩根滑桿，Claude Code 把常用的組合做成幾個模式，按 `Shift + Tab` 換，下一頁會逐個講。
>
> 這裡先給一條判準，它會跟著你整門課：你驗得動多少，就放多少。看得懂它改了什麼，監督那個旋鈕就可以往右轉。不會檢查的話，就把邊界縮小，讓它做錯了你也賠得起。

**這頁的教學意圖**：監督程度管你的時間，邊界大小管風險；兩者獨立，不熟的時候先縮邊界而不是狂盯。
**預估時間**：4 分鐘

## Slide 62｜Claude Code 的六個權限模式

**畫面**
上半是速查表，六張模式卡（default、acceptEdits、plan、auto、dontAsk、bypassPermissions），每一格最後一行標它轉的是哪一個旋鈕。下半是模擬器，兩個分頁：Terminal 版（一顆模擬 `Shift + Tab` 的按鈕加狀態列）與網頁版（三個開關加三顆預設鈕與一條安全性評估）。底下一段文字講兩邊怎麼切，最後一句收尾。

**逐字稿**

> 就是下面這六個模式。每一格最後一行標的，是它轉的哪一個，你看那一行就知道它在管你的時間還是管風險。
>
> 名字跟循環順序我先講在前面，它們改過好幾次，之後大概還會改。你要認的是每一格轉的是哪一個旋鈕，那個不會變。
>
> 第一個，`default`，最安全的那一個。修改檔案、執行終端機指令之前會停下來徵求同意；純讀取不打擾。它轉的是旋鈕一，每一步都先問。
>
> 什麼時候用：金流、認證設定，或者你剛接手一個陌生專案的時候。
>
> 第二個，`acceptEdits`。這一格請特別聽清楚，因為它的名字會誤導你，而且是那種會害你出事的誤導。
>
> 名字寫的是「自動接受編輯」，你會以為它只放行改檔案。實際上它連 `mkdir`、`mv`、`cp` 這一類搬檔案的指令也一起放行。而 `mv` 會搬走東西、會覆蓋東西。
>
> 所以它比你從名字猜到的鬆。它轉的還是旋鈕一，改檔案不問，跑別的指令還是會問。
>
> 什麼時候用：你正在盯著看的那種連續小修改。
>
> 第三個，`plan`。它會翻專案、提出方案給你看，但不動任何檔案。注意這一格轉的是旋鈕二，不是旋鈕一，它是把邊界縮到只能讀。
>
> 這一個是這四個裡面最被低估的。大改動之前先用它聽一遍方向，比你改完再回頭吵便宜很多。
>
> 第四個，`bypassPermissions`，無條件放行所有層級的操作，包含高危指令跟檔案覆寫。它是兩個旋鈕都轉到底，也就是上一頁說唯一要小心的那一種組合。
>
> 畫面上寫的是「僅限與外部隔離的 Docker 容器」。
>
> 這句話怎麼用？很簡單：如果你不知道 Docker 容器是什麼，那就代表你現在不該用這個模式。不用再多想，這個判準夠用了。
>
> 下面這個模擬器分兩邊。左邊這個分頁是終端機版。我按一下這顆按鈕模擬 `Shift + Tab`，狀態列就換一個模式，每一個模式下面那行寫著它實際會放行什麼。你在真的終端機裡看到的狀態列就是這個東西。
>
> 我切到網頁版這個分頁。這邊的邏輯完全不一樣，要分清楚：它不是四選一，是三個開關各自開關。讀取本機檔案、自動寫入、執行指令。
>
> 我按「嚴格安全」，三個開關變成只剩讀取，底下的評估是藍色，唯讀觀察。按「自動核可」，寫入也開了，評估變成綠色，可寫檔但不能下指令，這個是多數人的日常設定。
>
> 我現在把「執行 Bash 終端機指令無需詢問」也打開，評估直接跳成紅色警告：防護已全面解除。這個對照可以記一下，讓風險跳級的是第三個開關，不是第二個。
>
> 下面這段文字有三件事要補。
>
> 第一，`Shift + Tab` 的循環順序。Pro 跟 Max 方案開起來預設在 auto，按第一下切到 Manual，也就是設定檔裡那個叫 `default` 的值，之後是 `acceptEdits`、`plan`，再按回到 Manual。介面上的名字跟設定檔裡的名字不一樣，這件事知道就好，不然你查文件會找不到。
>
> 第二，除了速查表那四個，還有兩個。`auto` 是全放行但有背景檢查，`bypassPermissions` 就是剛才那個，這兩個要啟用之後才會插進循環，排在 `plan` 後面。
>
> 第三個要特別記，它叫 `dontAsk`：只放行你事先核准的工具。它不在 `Shift + Tab` 的循環裡，要用啟動參數進去。它值得記的理由是，它是把邊界縮小最實際的做法，而不是像 `plan` 那樣整個鎖成唯讀。
>
> 最後這句收尾：沒有哪一種模式永遠正確，所以不要挑一個然後一直用。
>
> 順序大概是這樣：陌生專案用 `default`，摸熟了切 `acceptEdits`，大改動之前先 `plan` 聽它講一遍。轉旋鈕本來就是每天在做的事，不是設定一次就不管了。

**這頁的教學意圖**：認得出各模式轉的是哪一個旋鈕，尤其 `acceptEdits` 比名字聽起來鬆、`plan` 管的是邊界不是監督。
**預估時間**：7 分鐘

## 待處理

> **狀態：已於 2026-09-20 逐條確認並套用。** 逐條決議（含不改的項目、查證結果與變體做法）記在
> `待處理_決議.md`。下面保留的是當初發現問題時的描述，作為「這一頁為什麼長這樣」的紀錄，不是待辦。

### 1.【矛盾】標題寫「六個權限模式」，速查表只有四格，內文第一句還說「就是下面這四個模式」

- 同一頁三處數字不一致：`SlideLayout` 的 `title` 是六個，速查表的引言寫「就是下面這四個模式」，卡片實際是四張。另外兩個（`auto`、`dontAsk`）只出現在底下那段文字裡，`bypassPermissions` 則同時在卡片與文字裡。
- 學員讀到標題會先數格子，數出四個，然後停在那裡。這正是 D-2 那條「特別注意跟自己矛盾的」：反駁標題的句子就在同一頁。
- **建議**：兩種改法選一種。標題改成「Claude Code 的權限模式速查表」（不帶數字，也符合 D-5 那條「數量詞不是內容」）；或者把 `auto` 與 `dontAsk` 也做成卡片，補成六格。前者省事，而且六格會讓速查表變得太滿。
- 改標題的話記得同步 `src/App.tsx` 的 `LIVE_TITLES`（D-5 最後一節）。

### 2.【矛盾】模擬器只演三格，但旁邊的文字說循環有更多格

- 檔案第 1 行的註解自己寫著：「這個模擬器只演 default → acceptEdits → plan 這三格。實際上 Pro/Max 開機在 auto，按第一下才進 manual，而且啟用的選用模式會插在 plan 後面。」
- 也就是說，學員按那顆模擬鈕看到的循環，跟底下文字描述的循環對不起來，而且畫面上沒有任何一句話說明模擬器是簡化過的。
- **建議**：模擬器的狀態列旁邊補一個小標，例如「示意：只演常用的三格」。旁邊已經有一個「介面為示意」的標籤，但那指的是外觀，不是循環格數。
- 不建議把 `auto` 加進模擬器：那會讓預設起始狀態變成全放行，第一眼的印象反了。

### 3.【會過期】這一頁與 `11d2_M1_TerminalKeys`（Slide 45）是同一批資料，兩頁都缺 C-1 註解

- 模式名稱、循環順序、Pro/Max 的預設值，這三樣全部是 C-3 點名最會過期的項目，而這兩頁的內容目前是一致的，代表有人同步過。沒有查證日期的話，下一個人只能整段重查。
- **建議**：兩個檔案各補 C-1 的三行，並互相點名對方（「這一組數值與 `30_Cheat_Perms` 同步，改一邊要改兩邊」）。這一條跟 5-2 那個「`11c2` 的數字是 `19a` 的複本」是同一種病。

### 4.【缺漏】`31_Cheat_Dials` 的「邊界大小」沒有告訴學員怎麼縮

- 旋鈕一有明確的操作（`Shift + Tab`），下一頁四個模式裡有三個都標著旋鈕一。旋鈕二在下一頁只對到 `plan` 一格，而 `plan` 是整個鎖成唯讀，不是「縮小」。
- 真正對應「縮小邊界」的是 `dontAsk`，但它被寫在最底下那段密集的文字裡，而且標明不在循環中。
- 結果是：整頁花一半篇幅建立的旋鈕二，學員讀完不知道實際要怎麼轉。
- **建議**：`31_Cheat_Dials` 最後那個 Callout 已經在講「怎麼轉」，在那裡補一句旋鈕二的答案，例如「邊界則是靠限制它能用哪些工具、以及讓它只在一個資料夾裡工作」。這一句也接得上章節八「放手之前，先設好四道邊界」那一頁。
