## Slide 66｜規矩該存在哪：這次對話，還是這個專案

**這頁的教學意圖**：手冊做的不是讓它變聰明，是換了規矩的存放位置。

## Slide 67｜CLAUDE.md 可以放的四個位置

**畫面**
上方一句「一份可以用很久，專案變大才會用到分層」，旁邊一句原則：越靠近你正在改的檔案，講得越具體。中間四層由上往下縮排排列，每一層一行路徑加名稱、放什麼、例子；第二層（專案根目錄）是主色，標著「前面你寫的那一份就是它」。底下一句：同一件事講法不同時，下面的蓋過上面的。

**逐字稿**（`meta.script`，45 秒）

> 一份放在專案根目錄的手冊可以用很久，專案變大才需要分。位置有四個。家目錄那份放跨專案的個人偏好，例如回答一律用繁體中文。專案根目錄那份是主力，前面你寫的就是它，會進版控，團隊共用。子目錄那份動到那一區才讀進來，例如這一區的元件一律用 canvas 畫。最後是 CLAUDE.local.md，不進版控，寫只有你這台機器成立的事，例如你本機測試用的網址。原則只有一句：越靠近你正在改的檔案講得越具體，同一件事講法不同時，下面那層蓋過上面。

**這頁的教學意圖**：四層的差別只有「放哪、放什麼、什麼時候載入」三個欄位；每一層都要給得出例子，衝突時下面蓋過上面。
**預估時間**：1 分鐘

## Slide 68｜一份手冊該寫多長？

**畫面**
上方「一份大約 200 行以內」，下面一句解釋為什麼。中間一句：所以變長的時候，動作不是往下加，是回頭整理。接著一塊列「整理的時候先砍這三類」。最後一行講第一版用 `/init` 生草稿。

**逐字稿**（`meta.script`，57 秒）

> 再來是文件大小的問題。一份大約控制在 200 行以內，這是官方文件給的目標值，不是硬規定：越長，被遵守的比例越低，因為規矩越多，每一條分到的份量就越少。所以手冊變長的時候，動作不是接著往下加，是回頭整理。那要砍哪些？先砍三類。第一類，它讀程式碼就查得到的，像是用了哪些套件、檔案放在哪。第二類，只在某一區成立的，搬到剛才講的子目錄那一層，動到那一區才載入。第三類，寫了也驗不出來的，例如回覆要專業一點，那種留著只佔位置。另外第一版不必從零寫，輸入斜線 init，它會讀過你的專案生一份草稿。但它只寫得出現況，不是規矩，所以拿到草稿第一件事是改，不是存。

**這頁的教學意圖**：兩百行是提醒回頭整理的門檻，不是硬規定；而且要說得出整理時先砍哪三類。
**預估時間**：1 分鐘

## Slide 69｜換成 Codex 或 Cursor，手冊還讀得到嗎

**畫面**
上方提問「換工具要重寫一份嗎？」，答「不用，`AGENTS.md` 是跨工具的共通檔名」。中間一塊是要跟它講的那句話（建捷徑，不要複製成兩份），底下一行小字放實際的指令與 Windows 的替代做法。下面一塊寫實例：這份簡報的專案就是這樣設定的。最後一塊標著「2026 年 9 月之後」，講新版 Claude Code 自己也讀得懂 `AGENTS.md`，但預設只在沒有 `CLAUDE.md` 的時候才讀。

**逐字稿**（`meta.script`，61 秒）

> 有些夥伴可能會想說：寫了一份 CLAUDE.md，換成別家工具是不是要整份重寫。不用。其實還有一個叫做 AGENTS.md 的檔案，它是跨工具的共通檔名，Codex、Cursor 都會讀。它最早是 OpenAI、Google、Cursor 幾家各自在做，後來收斂成同一個開放格式，現在跟 MCP 歸在同一個基金會底下。做法是在專案裡建一個 AGENTS.md，讓它指向同一份 CLAUDE.md。這個東西叫符號連結，英文是 symbolic link，指令是畫面上那一行，你不用自己打，把那句話跟它說就好。為什麼是連結，不是複製成兩份？兩份分開之後你只會記得改其中一份，過一陣子兩邊的規矩就不一樣，而你不知道該信哪一份。連結只有一份本體，改哪一邊都是同一個檔案。Windows 上建符號連結要管理員權限，嫌麻煩就用替代做法：在 CLAUDE.md 開頭寫一行 at AGENTS.md，那個符號的意思是把整份併進來。最後補一件事：新版的 Claude Code 自己也讀得懂 AGENTS.md，但預設只在你沒有 CLAUDE.md 的時候才讀。你已經寫好手冊了，所以那個連結還是要做。

**這頁的教學意圖**：一份內容兩個檔名，換工具不用重寫；要說得出為什麼是捷徑不是複製兩份，以及 Windows 的替代做法。
**預估時間**：1 分鐘

### 1.【矛盾】Slide 68 說「後面『手冊越寫越長怎麼整理』那一段」，但它不在這一章

- `31_HandbookLength` 的口白點名了一個後面的段落。照 `npm run map`，那一段是 Slide 105 到 110（LIVE index 81），屬於**章節六**，中間隔了三十幾頁，而且中間還隔了整個「規則失效的三種原因」與「Hook」。
- 這不算指錯（那一段確實存在，名字也對得上），但它是 B-4 那類最容易在搬頁之後失效的句子，而它現在寫在 `meta.script` 裡，`check:slides` 完全掃不到。
- **建議**：不用改句子，但在 `31_HandbookLength.tsx` 補一行註解記下它指向哪一頁（`harness/17_HealthOverview`），讓之後搬頁的人知道這條線存在。同一個處理方式適用於所有在 `meta.script` 裡點名別段的頁面。

### 2.【矛盾】Slide 67 的四層與 Slide 63 的 `/context` 畫面對不起來

- Slide 67 列了四個位置：`~/.claude/CLAUDE.md`、`./CLAUDE.md`、`src/xxx/CLAUDE.md`、`./CLAUDE.local.md`。Slide 63 的模擬輸出只列了前兩個，而且沒有標它們分別是哪一層。
- 兩頁只差四頁，而且 Slide 63 那一格的說明正是「全域、專案、子目錄可能同時載入」。學員在 Slide 63 讀到那句話的時候沒有對應物，到 Slide 67 才拿到名字，順序是反的。
- **建議**：跟 5-5 待處理第 2 條一起處理。Slide 63 那兩行補上「專案／全域」的標記之後，這兩頁就接得起來了，Slide 67 不用動。

### 3.【缺漏】Slide 67 的第三層與第四層沒有例子，另外兩層有

- `LAYERS` 裡 `eg` 欄位只有前兩層有值（「回答一律用繁體中文」、「前面你寫的那一份就是它」），子目錄與 `CLAUDE.local.md` 兩層是空字串。
- 而這兩層恰好是學員最沒有概念的兩層，尤其 `CLAUDE.local.md`：「只有你這台機器成立的事」這句話很抽象，沒有例子的話讀者想不出什麼事情是只有自己那台機器成立的。
- **建議**：補兩個例子。子目錄那層可以寫「這一區的元件一律用 canvas 畫」；本機那層寫「我的測試資料庫在哪個路徑」或「我這台機器用的是 Windows」這一類。兩個都是一行的事。

### 4.【該驗證】Slide 69 的 Windows 替代做法沒有被這門課的其他地方接住

- 那行小字寫「Windows 一般帳號建不了捷徑，改在 `CLAUDE.md` 開頭寫一行 `@AGENTS.md` 匯入」。
- 這是整份簡報唯一一次出現 `@` 開頭的匯入語法。學員（尤其 Windows 使用者）會照做，但這裡沒有說那一行寫下去之後怎麼確認它生效了，而上一段才剛教過 `/context` 就是幹這個的。
- 另外這個做法的方向跟正文相反：正文是 `AGENTS.md` 指向 `CLAUDE.md`，這個替代做法是 `CLAUDE.md` 匯入 `AGENTS.md`，也就是兩份檔案都要有內容。小字裡沒有講這件事。
- **建議**：那行小字補半句，「（這種做法兩個檔案都會存在，規矩寫在 `AGENTS.md` 那一份；寫完用 `/context` 確認兩份都在清單裡）」。這一頁的檔頭已經有 C-1 的查證註解，順手把這個分支也記進去。
