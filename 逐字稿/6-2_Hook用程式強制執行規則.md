## Slide 92｜Hook 是什麼，可以拿它做什麼

**畫面**
上方一句「Hook 不是寫給它看的，是工具自己會跑的一段檢查」。中間兩塊，上面標著「兩份檔案，寫給不同的對象看」：`CLAUDE.md`（寫給它看的／可能沒讀到，讀到了也可能漏掉）、`.claude/settings.json`（寫給工具看的，Hook 就放這裡／它沒有不照做的選項）。下面一排四步的流程圖。再下面是被擋時它會看到的那句話：「偵測到中文破折號，請改用逗號、句號、冒號或括號。」最後一句講什麼時候值得掛。

**逐字稿**（`meta.script`，103 秒）

> 規則歸位的四個去處，第一個是 Hook。這個東西多數人沒碰過，所以先講它到底是什麼。差別在這段話是寫給誰看的。手冊是寫給它看的，它可能沒讀到，也可能讀到了還是漏掉。Hook 不是寫給它看的，是寫給工具看的：你把設定寫在專案的 .claude 資料夾底下一個叫 settings.json 的檔案裡，擋的動作是工具自己做的，跟它記不記得沒有關係，它也沒有不照做的選項。流程是這樣：你交代一件事，它動手之前先停下來，把當下要做的事交給你那段設定檢查一次，說可以才過得去。被擋的時候它會看到你寫的理由，然後自己換一個寫法再來。這份簡報就掛著一條：寫檔案之前先看有沒有中文破折號，有就退回去。那實際上可以拿它來做什麼？講幾個常見的。第一，金鑰或密碼寫進程式碼，存檔之前擋下來，這是最多人掛的一條。第二，動到正式環境的資料庫、或者刪掉整個資料夾這種回不來的指令，直接不准。第三，每次存檔之後自動跑排版，這種不是擋，是幫你補一個你一定會忘記的動作。第四，它說做完了的時候自動跑一次測試，沒過就叫它回去改。判斷標準兩個：違反了會出事的，還有每一次都要做、但你一定會忘記提醒的。

**這頁的教學意圖**：Hook 的保證來自「執行的是工具不是 AI」；被擋時那句理由是給它看的，它會自己重來。
**預估時間**：1 分鐘

## Slide 93｜Hook 的三層機制

**畫面**
上方一句「前兩層挑條件，第三層才是要做的事」，底下一句小字：要做的事簡單的話一行指令就好，複雜的要寫成一支小程式，請 Claude 幫你寫。中間三格：什麼時候（Event）、哪幾次要管（Matcher）、要做什麼（Handler），每一格底下用灰字填上這份簡報那一條的答案。下面貼出 `.claude/settings.json` 真正的樣子（巢狀 JSON），三個位置各掛一個箭頭標著時機、範圍、動作，`command` 的值是 `node scripts/slide-guard.mjs`。最後一句：「三層要寫齊。沒寫範圍，它每一次用工具都會跳出來檢查。」

**逐字稿**（`meta.script`，96 秒）

> 一條 Hook 拆開只有三層，而前兩層都是從清單裡挑一個，真正要想的是第三層。第一層問什麼時候，叫 Event。第二層問哪幾次要管，叫 Matcher。第三層問要做什麼，叫 Handler。拿這份簡報掛的那一條套進去就很好懂。什麼時候？Claude 要寫檔案進去之前。哪幾次要管？只有寫檔案跟改檔案那幾次，它讀東西的時候不要來煩我。要做什麼？去跑一支檢查，那支檢查會把不合規的擋下來，並且回一句話告訴它哪裡不行。畫面下面那段就是這份簡報真正的設定檔，括號比較多，你只要找三個位置：標著時機的那一行是 PreToolUse，標著範圍的是 matcher，標著動作的是 command，後面接的就是要跑哪一支檢查。等一下換你掛一條，掛完打開那個檔案，看到的也是這個形狀。那「不用自己寫程式」是什麼意思？時機跟範圍這兩層是從清單裡挑一個，沒有什麼好寫的。第三層才看情況：要做的事簡單，一行指令就好；複雜的要寫成一支小程式，像這份簡報這一支就有一百多行。但那支不用你自己寫，你把要擋什麼講清楚，請 Claude 寫，你負責測一次。三層要寫齊，最常漏掉的是中間那層範圍。

**這頁的教學意圖**：三個英文名詞其實是同一段設定的三個位置；沒寫範圍是最常見的自毀方式（後果留到 Slide 95 展開）。
**預估時間**：1 分鐘

## Slide 94｜Hook 第一層：時機，每個階段記一個

**畫面**
上方一句「三十幾種，按階段各記一個」。中間四格，各標階段與設定名稱：接到指令（SessionStart）、工具執行前（PreToolUse，標著最常掛）、工具執行後（PostToolUse）、收尾（Stop，標著最常掛）。下面再列常用的另外六個。最後一句收尾。

**逐字稿**（`meta.script`，82 秒）

> 第一層是時機，也就是這段檢查要在什麼時候跑。官方支援三十幾種，你完全不用背，照一輪對話的四個階段各記一個就夠了。第一個，你剛開一個新對話，或者接續昨天那一段，這個時機叫 SessionStart，適合每次開工都要先講一次的東西。第二個，它準備要動手了但還沒動，叫 PreToolUse，這是四個裡面最重要的。第三個，它做完了，檔案已經寫進去，叫 PostToolUse，適合事後補一刀，例如自動排版。第四個，它覺得整件事做完要收工了，叫 Stop，適合在這裡驗收一次，沒過就叫它回去改。常用的還有六個，畫面下面列著，需要的時候再查就好。這裡有一個關鍵：要在它動手之前攔下來，只有工具執行前那一個做得到，因為那時候它還沒動手。工具執行後已經寫進去了，只能事後補救。收尾那一個不一樣，它是在它說「我做完了」的時候才跑，所以你可以在那裡驗收，沒過就退回去叫它重做，但那時候東西已經寫下去了，不是攔在動手之前。

**這頁的教學意圖**：時機不用背，但「只有工具執行前擋得住」這一條要記住，其他都只能事後補做。
**預估時間**：1 分鐘

## Slide 95｜Hook 第二層：條件，只留你要管的工具

**畫面**
上方一句「同一個時機會來很多次，挑你要檢查的」。中間一排三步：時機到了、看它在用哪個工具、只有這幾個要檢查。下面是實際的那一行寫法 `matcher: Write|Edit|MultiEdit`，接著一排工具名稱標著要不要管：Read ✗、Bash ✗、Write ✓、Edit ✓、MultiEdit ✓、WebFetch ✗。最後一塊黃框講範圍開太大的後果，收在「路徑得在下一層的指令裡自己判斷」。

**逐字稿**（`meta.script`，96 秒）

> 第二層是範圍，也是最多人直接跳過的一層。為什麼需要它？因為你剛才選的那個時機，一輪對話裡會來很多次。以工具執行前來說，它可能正要讀一個檔案、可能要跑一行指令、也可能真的要寫檔案，每一次都會經過你這條 Hook。範圍那一行的作用，就是從裡面挑出你真正要檢查的那幾種。這份簡報掛的那一條寫了三個工具。Write 是整個檔案重寫一次，Edit 是把檔案裡某一處的文字換掉，MultiEdit 是一次換好幾處。三個都是在動你的檔案，所以三個都要管；Claude 讀東西的時候就不會被打擾。不寫這一行也能跑，但代價是它每一次動作都插手一遍，煩到最後你會自己把它關掉。這裡最容易誤會：範圍那一行挑的是工具，不是資料夾。那要怎麼限定資料夾？在同一條 Hook 裡多寫一個 if，像畫面上這個，只管 src 底下 api 那個資料夾。下一頁的五個例子裡會再用到兩次，連它的地雷一起講。不想用 if 的話，就得在下一層那支檢查裡自己判斷路徑，這份簡報那一支就是這樣寫的。這條一開始沒有挑檔案，結果連專案自己的工具腳本都被擋了三次。

**這頁的教學意圖**：範圍管的是「哪個工具」不是「哪個資料夾」，要限資料夾得在動作那一層自己判斷。
**預估時間**：1 分鐘

## Slide 96｜Hook 第三層：動作，條件過了要做什麼

**畫面**
上方一句「五種動作，從跑一段指令開始」。中間一排三步：時機到了、範圍也符合、執行這個動作。下面五格排成兩欄：跑一段指令（command，標著起點）、呼叫一個 API（http）、呼叫接上的工具（mcp_tool）、交給模型判斷（prompt）、派子代理去查（agent）。最後一句警告。

**逐字稿**（`meta.script`，40 秒）

> 第三層是動作。時機到了、範圍也符合，它要做什麼？五種。跑一段指令，最常用。呼叫一個 API，把這次的資料送到你指定的網址。呼叫你接上的 MCP 工具。交給模型判斷一次，適合沒辦法用規則寫死的情況。派一個子代理去查，能做的最多也最慢。不是每個時機都支援五種，而且寫了不支援的不會報錯，只會安靜地什麼都不做。所以從跑指令開始，它每個時機都支援，你自己在終端機就測得出來。

**這頁的教學意圖**：五種動作的能力與成本遞增；「寫了不支援的不會報錯」是這一層最大的坑。
**預估時間**：1 分鐘

## Slide 97｜五個完整的例子：時機、範圍、動作

**畫面**
最上方那條三層軌仍亮在「動作」。開場一句講底下這幾段是填在前一頁那個外層裡面的。五塊依序出現，每一塊上面是動作的名稱（`command`、`http`、`mcp_tool`、`prompt`、`agent`）與情境，底下是三層各填什麼：時機、範圍（其中兩個用到 `if`）、動作的設定。五塊之後一塊列 `if` 的三種寫法與 `Edit` 那個地雷，再一塊「那它查完之後呢？」講三種結果（放行、擋下來附理由、只補一段訊息）。最後一句講時機與範圍是情境決定的、動作才是你在挑的。

**逐字稿**（`meta.script`，150 秒）

> 三層都講完了，接下來五個完整的例子，每一個都把三層填好，你可以直接照抄。第一個，排版。情境是 Claude 寫完檔案之後自動跑一次排版。時機選工具執行後，因為要先有檔案才排得了。範圍只留動到檔案那幾次。動作是跑指令，指令就寫你平常在終端機打的那一句。第二個，通知。情境是 Claude 要動到上線那一區之前，送一則通知到公司的系統，讓人知道有這件事。時機選工具執行前。範圍除了挑工具，還多寫了一個 if，再縮到那個資料夾。動作是呼叫一個網址，把網址填進去就好。第三個，掃描。情境是 Claude 寫完檔案之後，叫你接上的掃描工具掃這個檔案。時機一樣是工具執行後，檔案存在了才掃得到。動作要寫三個欄位：哪一台伺服器、哪一個工具、要把什麼丟過去。畫面上那個大括號錢字號的寫法，意思是把這次被寫的那個檔案路徑帶過去。第四個，交給模型判斷。情境是文案寫進去之前，先讓模型讀一次看口氣會不會太兇，這種事你寫不成規則。要擋就得在動手之前，所以時機是工具執行前，範圍用 if 只管文件那一區。prompt 裡那個 ARGUMENTS 會被換成這次事件的資料。第五個，派子代理。情境是 Claude 說做完了，派一個出去查有沒有漏改別的地方。時機是收尾，而收尾不是在用工具，所以沒有工具可以挑，範圍那一行不用填。五個看完你會發現，時機跟範圍是照情境決定的，動作才是你真正在挑的那一個。最後補 if 的三種寫法：只管某個資料夾底下的，寫 Edit 括號 src 斜線 api 斜線兩顆星；只管某種副檔名的，寫 Edit 括號星點 ts；不管它在哪一層、只要資料夾叫 secrets 就管，前面加兩顆星。這裡有一個地雷：括號前面那個字一律寫 Edit。Edit 在這裡涵蓋所有會動到檔案的工具，Write 跟 MultiEdit 那幾次也算在裡面。你如果照直覺寫成 Write 括號，不會報錯，但那一行永遠不會被拿去比對，等於你以為限定了、其實沒有。那它查完之後呢？五種的回報方式是一樣的，只有三種結果：放行；擋下來並附一句理由，Claude 會看到那句理由，換個做法再來一次；或是不擋，只補一段訊息給它參考。而擋得住與否看的是時機那一層，不是動作那一層：動手之前擋得住，動手之後就只能補救。最後，前兩種動作跑的是確定的規則，後兩種要判斷，判斷就有判斷錯的時候，也比較慢。所以從跑指令開始，真的寫不成規則了再往下換。

**這頁的教學意圖**：把三層填成五個完整的例子，讓學員看出時機與範圍是跟著情境變的；動作的排序本身就是建議的順序，從跑指令開始。
**預估時間**：3 分鐘

## Slide 98｜如何掛上你的第一條 Hook

**畫面**
上方一句「不用自己編設定檔，把這句交給它」。中間一排四步：貼這句給它、它去寫設定、寫一個假金鑰、看它擋不擋。下面一段可以直接用的 Prompt。最後是驗收的三件事，第三件是「它寫進哪一個檔案了（這一題該進專案的 `.claude/settings.json`）」。

**逐字稿**（`meta.script`，36 秒）

> 回到歸位第一題：金鑰不能寫進程式碼。設定檔不用你自己編，把畫面上那句交給它。三層它會自己填，你要盯的是測試。最常見的失敗不是寫錯，是它從來沒被觸發過，而你不會發現。驗收三件事：假金鑰真的被擋下來了嗎，被擋的時候有沒有講清楚哪裡不行，還有它把設定寫進哪一個檔案。這一題該進專案的 settings.json，掉在家目錄，以後每個專案都會被檢查。

**這頁的教學意圖**：Hook 交給它寫就好，你要顧的是驗收；沒被觸發過的 Hook 等於沒掛，而掛錯位置的 Hook 會跟著你去每一個專案。
**預估時間**：8 分鐘（動手，含實機）

## Slide 99｜Codex 也有 Hook，一樣是這三層

**畫面**
上方一句「Codex 也是這三層，每一層可以挑的選項比較少」。中間一張兩欄對照表：時機（Claude Code 三十幾種／Codex 十來種）、動作（五種／只有跑指令）。下面一句講剛掛的那一條搬得過去，接一句「兩邊都還在改版，掛之前查一次文件」。最後一句收尾。

**逐字稿**（`meta.script`，48 秒）
