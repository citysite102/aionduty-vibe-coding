## Slide 94｜Hook 是程式在擋，不是它記得

**畫面**
上方一句對照。中間兩塊：`CLAUDE.md`（可能沒讀到，讀到了也可能漏掉）、`settings.json`（你寫設定，工具自己執行）。下面一排四步的流程圖。再下面是被擋時它會看到的那句話：「偵測到中文破折號，請改用逗號、句號、冒號或括號。」最後一句講什麼時候值得掛。

**逐字稿**（`meta.script`，45 秒）

> 規則分流的第一個去處就是 Hook，那它到底是什麼？手冊是請它記得，而它可能沒讀到，也可能讀到了還是漏掉。Hook 完全不一樣，你寫一段設定，擋的動作是工具自己做的，它沒有決定權。順序是你交代一件事，它動手之前先停下來，把接下來要做的事交給你的設定檢查一次，說可以才過得去。被擋的時候它會看到理由，自己換寫法重來。這份簡報就掛著一條：寫檔案之前先看有沒有破折號。什麼時候值得掛？違反了會出事的，還有每一次都要做的。

**這頁的教學意圖**：Hook 的保證來自「執行的是工具不是 AI」；被擋時那句理由是給它看的，它會自己重來。
**預估時間**：1 分鐘

## Slide 95｜一條 Hook 拆開只有三層

**畫面**
上方一句「你寫的是設定，不用自己寫程式」。中間三格：什麼時候檢查（Event）、這一次要不要管（Matcher）、到底做什麼（Handler），每一格底下用灰字填上這份簡報那一條的答案。下面貼出 `.claude/settings.json` 的樣子，三個名詞對到三個位置。最後一句提醒三層要寫齊。

**逐字稿**（`meta.script`，45 秒）

> 它長什麼樣？放心，你寫的是一段設定，不用自己寫程式，而且拆開只有三層。第一層問什麼時候檢查，叫 Event。第二層問這一次要不要管，叫 Matcher。第三層問到底做什麼，叫 Handler。用這份簡報那一條對回去：時機是它要寫檔案之前，範圍是只有寫檔案跟改檔案要管，動作是擋下來並告訴它哪裡不行。下面那塊是它在檔案裡的樣子，三個名詞對三個位置。三層要寫齊。沒寫範圍它照樣能跑，但每一次用工具都會跳出來檢查，你很快就會想把它關掉。

**這頁的教學意圖**：三個英文名詞其實是同一段設定的三個位置；沒寫範圍是最常見的自毀方式。
**預估時間**：1 分鐘

**【轉場 → Slide 96】**

> 三層逐一展開，先看第一層。

## Slide 96｜第一層：每個階段先記一個

**畫面**
上方一句「三十幾種，按階段各記一個」。中間四格，各標階段與設定名稱：接到指令（SessionStart）、工具執行前（PreToolUse，標著最常掛）、工具執行後（PostToolUse）、收尾（Stop，標著最常掛）。下面再列常用的另外六個。最後一句收尾。

**逐字稿**（`meta.script`，45 秒）

> 第一層是時機。官方支援三十幾種，聽到這裡先別慌，你不用背，按階段各記一個就夠。接到指令是 SessionStart，開新對話或接續舊紀錄的時候。工具執行前是 PreToolUse，它準備動手但還沒動。工具跑完是 PostToolUse，東西已經寫進去了，適合自動排版這種補動作。收尾是 Stop，它覺得做完了，適合在這裡驗一次，沒過就叫它回去改。下面六個需要時再看。加起來十個，重點是只有工具執行前擋得住，因為那時候它還沒動手，其他都是事情發生完才觸發，只能事後補做。

**這頁的教學意圖**：時機不用背，但「只有工具執行前擋得住」這一條要記住，其他都只能事後補做。
**預估時間**：1 分鐘

## Slide 97｜第二層：只留你要管的那一次

**畫面**
上方一句「同一個時機會來很多次，挑你要檢查的」。中間是實際的那一行寫法 `matcher: Write|Edit`，下面一排工具名稱標著要不要管：Read ✗、Bash ✗、Write ✓、Edit ✓、WebFetch ✗。最後一句警告範圍開太大的後果。

**逐字稿**（`meta.script`，45 秒）

> 第二層是範圍，這一層最常被跳過。時機到了，這一輪它可能在讀檔案、跑指令，也可能在寫檔案，範圍那一行決定哪幾種要管。畫面上那一行就是實際的寫法，下面那排是結果：寫檔案跟改檔案會被檢查，讀東西不會被打擾。不寫也能跑，代價是它每一次都插手，然後你會想把它關掉。要注意它管的是哪個工具，不是哪個資料夾。這條原本沒有判斷路徑，連專案自己的腳本都被擋了三次，後來在指令裡加上只管投影片那一區才解決。

**這頁的教學意圖**：範圍管的是「哪個工具」不是「哪個資料夾」，要限資料夾得在動作那一層自己判斷。
**預估時間**：1 分鐘

## Slide 98｜第三層：條件過了要做什麼

**畫面**
上方一句「五種動作，從跑一段指令開始」。中間五格排成兩欄：跑一段指令（command，標著起點）、呼叫一個 API（http）、呼叫接上的工具（mcp_tool）、交給模型判斷（prompt）、派子代理去查（agent）。最後一句警告。

**逐字稿**（`meta.script`，45 秒）

> 第三層是動作。時機到了、範圍也符合，它要做什麼？五種。跑一段指令，最常用。呼叫一個 API，把這次的資料送到你指定的網址。呼叫你接上的工具。交給模型判斷一次，適合沒辦法用規則寫死的情況。派一個子代理去查，能做的最多也最慢。有一件事我一定要先講，因為它安靜得很可怕：不是每個時機都支援五種，寫了不支援的不會報錯，只會什麼都不做。所以從跑指令開始，它每個時機都支援，你自己在終端機就測得出來。

**這頁的教學意圖**：五種動作的能力與成本遞增；「寫了不支援的不會報錯」是這一層最大的坑。
**預估時間**：1 分鐘

> 三層都講完了，換你掛一條。

## Slide 99｜換你掛一條 Hook

**畫面**
上方一句「不用自己編設定檔，把這句交給它」。中間一段可以直接用的 Prompt。下面是驗收的兩件事。

**逐字稿**（`meta.script`，45 秒）

> 換你動手掛一條。回到第一題那個例子：金鑰絕對不能寫進程式碼。你不用自己編設定檔，把這句話交給它：每次你要寫檔案之前，先檢查內容裡有沒有 API 金鑰，有就擋下來，掛完故意寫一個假的測一次給我看。三層它會自己填，你要盯的是最後那一步。最常見的失敗不是寫錯，是它從來沒被觸發過，而你不會發現。驗收兩件事：假金鑰真的被擋下來了嗎，被擋的時候有沒有講清楚哪裡不行。那句理由是寫給它看的，它會拿著理由再試一次。

**這頁的教學意圖**：Hook 交給它寫就好，你要顧的是驗收；沒被觸發過的 Hook 等於沒掛。
**預估時間**：8 分鐘（動手，含實機）

**【轉場 → Slide 100】**

> 掛好了，那換一個工具還算不算數。

## Slide 100｜同一條 Hook 搬到 Codex

**畫面**
上方一句「Codex 也是這三層，可以選的比較少」。中間一張兩欄對照表：時機（Claude Code 三十幾種／Codex 十來種）、動作（五種／只有跑指令）。下面一句講剛掛的那一條搬得過去。最後一句收尾。

**逐字稿**（`meta.script`，45 秒）

> 換一個工具還算不算數？這是值得問的一題。Codex 也有 Hook，也是這三層，差別是每一層可以選的比較少。時機 Claude Code 開三十幾種，Codex 目前是十來種。動作差最多，Claude Code 有五種，Codex 只有跑指令，所以交給模型判斷、派子代理去查那些搬不過去。但你剛掛的那一條用工具執行前，動作是跑指令，兩邊都有，搬得過去。所以不用背名稱，要練的是講清楚：什麼時候檢查、管哪一次、做什麼。

**這頁的教學意圖**：三層結構是跨工具的，能選的項目才是各家的差異；要練的是描述能力不是記憶。
**預估時間**：1 分鐘

### 1.【矛盾】Slide 95 與 Slide 97 寫的 `matcher` 跟這個專案實際的設定不一樣

- 兩頁都寫 `matcher: Write|Edit`。實際 `.claude/settings.json` 裡是 `"matcher": "Write|Edit|MultiEdit"`。
- 這兩頁的設計原則就是「照抄這份簡報真的掛著的那一條」（`62_HookHowTo` 與 `63_HookThreeLayers` 的檔頭都寫著要用真的例子、學員查得到）。少一個 `MultiEdit` 讓這個承諾破掉，而且那個工具名稱本身有教學價值：它剛好說明了「同一件事可能有好幾個工具名，範圍要寫齊」。
- 另外 Slide 97 下面那排工具清單（Read ✗、Bash ✗、Write ✓、Edit ✓、WebFetch ✗）也沒有 `MultiEdit`。
- **建議**：兩頁的 `matcher` 都補成 `Write|Edit|MultiEdit`，Slide 97 的工具清單加一格 `MultiEdit ✓`。順手在 `65_HookMatcher` 的檔頭註解記一行，說明這裡跟 `.claude/settings.json` 綁在一起，改設定要改投影片。

### 2.【矛盾】Slide 97 說「範圍管的是哪個工具，不是哪個資料夾」，但同一段的補救說法容易被誤讀

- 口白最後那句：「這條原本沒有判斷路徑，連專案自己的工具腳本都被擋了三次，後來在指令裡加上只管投影片那一區才解決。」
- 問題在「在指令裡加上」這幾個字。學員這一頁學的是第二層（範圍），而這個補救其實發生在第三層（動作）裡面。兩層的區分正是這一組七頁的骨架，這一句卻把它們混在一起，而且沒有明說「所以路徑要在第三層處理」。
- 畫面上那句更短（「這條原本沒有判斷檔案路徑，連專案自己的工具腳本都被擋了三次」），連解法都沒有。
- **建議**：畫面那句補上半句結論，例如「路徑得在下一層的指令裡自己判斷」。這一句同時替第三層鋪路。

### 3.【會過期】Slide 96、98、100 的數量全部是外部事實，但檔頭沒有 C-1 註解

- 這一組宣稱的數字有：官方支援「三十幾種」時機、動作「五種」、Codex「十來種」時機且「只有跑指令」。Slide 96 底下那六個時機名稱（`UserPromptSubmit`、`PostToolUseFailure`、`PermissionRequest`、`SubagentStop`、`PreCompact`、`SessionEnd`）更是逐字的 API 名稱。
- CLAUDE.md C-3 已經把 `harness/68_HookCodex` 列進「特別容易過期」的清單，但那個檔案跟 `64_HookEvents`、`66_HookHandler` 都沒有 C-1 的三行。
- `64_HookEvents` 的檔頭有一段很好的自律註解（「要更完整的一律去官方文件，那份會改版」），但它沒有寫日期，也沒有寫查哪一頁。
- **建議**：三個檔案各補 C-1 三行，點名 Claude Code 的 hooks 文件與 Codex 的對應文件。這一組的內容密度高，重查成本比別頁高得多。

### 4.【缺漏】Slide 99 的驗收沒有涵蓋「它把 Hook 掛在哪一層」

- 這一頁把設定工作整個交給 Claude（「三層它會自己填」），驗收只有兩件事：假金鑰有沒有被擋、理由講清楚了沒。
- 但它可以把設定寫進三個不同的地方：專案的 `.claude/settings.json`（進版控，團隊共用）、`settings.local.json`（不進版控），或者家目錄那一份（所有專案都吃得到）。三者的後果差很多，而這正是單元 5-7 那一頁（零件放在兩個地方）建立的觀念。
- 學員掛完一條擋金鑰的 Hook，如果它掉在家目錄，之後每個專案都會被檢查，而他不會知道為什麼。
- **建議**：驗收清單加第三條，「它寫進哪一個檔案了？」並補一句預期答案（這一題該進專案的 `.claude/settings.json`）。這一條也把這一組跟前一章的資料夾地圖接起來。
