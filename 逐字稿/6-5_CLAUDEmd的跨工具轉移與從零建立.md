## Slide 119｜三個地方，差別只有兩件事

**畫面**
上方一句提問與答案。中間一張三欄表：Claude Projects（網頁版 claude.ai／只有你上傳的檔案／不會動你的電腦）、Cowork（桌面版的一個頁籤／你綁的那一個資料夾／能讀能寫，不執行指令）、Claude Code（終端機或桌面版的 Code 頁籤／整個專案資料夾／能執行指令、跑測試、版控），最後一列標為主色。兩個比較的欄位標在表頭：碰得到哪些檔案、能不能自己動手。

**逐字稿**（`meta.script`，44 秒）

> CLAUDE.md 是 Claude Code 在讀的檔案，但你不會每天都開它，有時候只是想在網頁上問一句話。換到別的地方，前面學的要重學嗎？不用，這一點可以放心。手冊怎麼寫、分層怎麼分、規則該放哪，三個地方都成立。會變的只有兩件事：它碰得到哪些檔案，以及它能不能自己動手。網頁版只看得到你上傳的檔案，桌面版的 Cowork 綁一個資料夾、能讀能寫但不執行指令，Claude Code 整個專案都能讀，也能跑測試跟版本控制。

**這頁的教學意圖**：三個介面的差別只有兩個維度（碰得到什麼、動不動得了手），寫法完全共用。
**預估時間**：1 分鐘

## Slide 121｜跨工具名詞對照表

**畫面**
一張三欄表：這件事／Claude Code 叫它／別家叫它，每一列附一句「為什麼要有這個」。四列：專案規則手冊、先想再動手、分工與派工、自己跑自己修。最後一段講到新工具第一天要找的四樣東西。

**逐字稿**（`meta.script`，52 秒）

> 前面講的都是 Claude Code，換一家會不會白學？不會，這四件事換到 Cursor、Codex 或別家一樣成立，換工具要重學的只有名字。專案規則手冊在這裡叫 CLAUDE.md，別家叫 AGENTS.md，或者放在 Cursor 的 rules 資料夾底下，內容幾乎不用改。先想再動手，這裡是 plan 模式，別家叫 Chat-only 或 Ask。分工派工，這裡叫子代理，別家叫 Agent Teams 或 Role。自己跑自己修，這裡是寫好完成條件讓它自己驗，別家叫 Autonomous Loop 或 Goal-oriented Loop。到新工具的第一天，你要找的就是這四個東西放在哪裡。

**這頁的教學意圖**：換工具的成本是查四個名字，不是重學一套方法；找不到的那一項代表那個工具還沒做。

## Slide 122｜換成你的工作，手冊該寫什麼

**畫面**
上方五張提案檔案卡：A 客戶（英文版）、B 客戶（不收 PDF）、C 客戶、D 客戶（成本外洩，標紅）、E 客戶。中間一句講每一份都要重講什麼。下面一塊列出該寫手冊的三個條件（重複發生、有你自己的規矩、每次都要重講），再下面是三個空格的題目，最後掛著「先自己想三十秒」。

**逐字稿**（`meta.script`，40 秒）

> 換一個完全不是程式的工作。你負責寫客戶提案，這個月寫了五份，每一份都要重新交代提案分哪幾段、公司簡介用哪一版、語氣要多正式。A 客戶要英文版，B 客戶不收 PDF。而 D 客戶那一份，你差點把成本結構貼進要寄出去的檔案裡。這件事跟程式一點關係都沒有，但三個條件全中：重複發生、有你自己的規矩、每次都要重講。如果要交給 Claude 做，你的手冊會寫什麼？三格各一條，先自己想三十秒。

**這頁的教學意圖**：把整章的方法搬到非程式的工作上，而且題目是學員自己先答。
**預估時間**：2 分鐘（含留白）

## Slide 125｜每次都要重講的，寫進根目錄手冊

**畫面**

## Slide 126｜提案那三條，各自該放哪一層

**畫面**
一張對照表：第 1 題那三條→根目錄手冊、第 2 題那一條→Hook（標硬）、第 3 題那一條→子目錄，各附一句理由。最後一句收尾。

**逐字稿**（`meta.script`，42 秒）

> 第一題那一條不該只寫在手冊裡，成本外洩的代價太高，光靠文字擋不住，要加一道 Hook，在檔案要寄出去之前擋下來。第二題那一條，各客戶的專屬格式分到子目錄，用到那個客戶的時候才讀，這份手冊才不會越長越肥。第三題答出來那三條，是你每次都要重講的格式，留在根目錄那份就好。所以三個問題問完，你拿到的不只是內容，連每一條該用什麼方式擋也一起決定了。

**這頁的教學意圖**：三題不只產出內容，也同時決定了每一條的層次。
**預估時間**：1 分鐘

## Slide 127｜換成你自己的工作，怎麼開始

**畫面**
上方一句主張：第一份三行就可以上場。中間排成一條流程線的三站：挑一件重複做過三次以上的事、照三個問題各寫一句、下次再做同一件事時貼上去。最後一句講什麼時候才要加 Skill 或 Hook。

**逐字稿**（`meta.script`，42 秒）

> 這三個問題跟你用哪個工具無關，換成別的 AI、換成完全不同的工作，要問的還是這三題。換成你自己的工作就從這裡開始：挑一件你這個月重複做過三次以上的事，照三個問題各寫一句，先不要求完整。下次再做同一件事的時候把它貼上去，缺什麼再補。第一份三行就可以上場，真的不用等它寫完整。至於什麼時候該加 Skill、什麼時候該加 Hook，等你被同一件事絆到第二次再說，那時候你自然會知道它屬於哪一種。

**這頁的教學意圖**：起步的門檻是三行，而且升級的時機由症狀決定不是由規劃決定。
**預估時間**：1 分鐘

- **建議**：補 C-1 三行，點名 `code.claude.com/docs/en/mcp` 的安裝那一節與 Notion 的 MCP 入門頁（兩個網址畫面上已經有了，抄進註解即可）。這一頁的內容在這門課裡是最容易整段失效的其中一頁，因為連參數都寫死了。

### 2.【矛盾】Slide 122 到 126 是三題，Slide 89 到 93 是四題，而且答案的排序反了

- 轉移演練的三題順序是：每次都要重講的（→ 根目錄）、違反了會出事的（→ Hook）、只在特定情況的（→ 子目錄）。
- 分流那一組的四題順序是：會出事的（→ Hook）、只在某一區的（→ 子目錄）、有固定步驟的（→ Skill）、以上皆非（→ 根目錄）。
- 兩組的順序幾乎完全相反，而分流那一組的口白特地強調「順序不能換，因為它是照擋得住的程度排的」。轉移這一組把最該先問的那一題放在第二個。
- 這一組的答案（Slide 126）順序也是照題號排的，所以三題的層次在畫面上是「軟、硬、中」，看不出階層。
- **建議**：兩種改法。把轉移三題的順序調成跟分流一致（會出事的先問），這樣兩組互相強化；或者在 Slide 122 或 Slide 126 加一句說明，講清楚這三題是「從最容易想得到的開始」而不是分流的順序。第一種比較好，因為這一段的職務就是證明同一套方法搬得過來。

### 3.【缺漏】轉移演練少掉了 Skill 那一層

- 分流四題裡的第三題（有固定步驟、用到才需要 → Skill）在轉移演練裡完全沒有出現，三題的答案是根目錄、Hook、子目錄。
- 但那個提案情境**剛好有一個非常典型的 Skill**：「一份提案要分哪幾段、公司簡介用哪一版、語氣多正式」其實是一套有順序的產製流程。現在它被歸到根目錄手冊。
- Slide 127 最後那句有補救（「什麼時候該加 Skill 或 Hook，等你被同一件事絆到第二次再說」），但那是把問題推遲，不是回答。
- **建議**：不建議加第四題（三題的節奏是對的，而且 `41_TransferCase` 的畫面已經設計成三格）。改在 Slide 126 那張對照表底下補一行，說明 Skill 那一層在這個例子裡還用不到，以及什麼時候會用到（例如「等你連產製步驟都固定了，第一題那三條就會變成一個 Skill」）。

### 4.【矛盾】Slide 119 的三個介面與 Slide 18 的「桌面版」指的不是同一個東西

- 這一頁把 Claude 的介面分成三個：Claude Projects（網頁）、Cowork（桌面版的一個頁籤）、Claude Code（終端機或桌面版的 Code 頁籤）。
- 但學員從 Slide 18（`10f_M1_DesktopFirst`）開始，一路到章節五寫手冊、掛 Hook，用的都是被稱為「桌面版」的東西，而照這一頁的分類那其實是「桌面版的 Code 頁籤」，也就是 Claude Code。
- 也就是說「桌面版」這個詞在這門課裡一直指的是 Claude Code 的一種開法，但這一頁把 Cowork 也叫做桌面版的一個頁籤。學員在這裡會開始懷疑自己前面一百頁用的是哪一個。
- **建議**：這一頁的第三列補半句點名，例如「Claude Code（終端機，或桌面版的 Code 頁籤，**也就是你前面一直在用的那個**）」。一句話就把前一百頁接住了。
- 這件事照 B-6 值得掃一次全片：`grep -rn "桌面版" src/slides src/slides-recorded` 看有沒有別頁也在用這個詞指不同的東西。
