## Slide 162｜把專案推上 GitHub，它才不只在這台電腦

**畫面**
頁首有 `LiveDemo`。上方三格風險：硬碟壞了、換一台電腦、想傳給別人看。中間一塊定義 GitHub，分兩用（給你自己用、給部署平台用）。下面一段可複製的 Prompt，是一次到位的版本（直接寫 public，推之前先檢查 `.gitignore` 與寫死的金鑰、寫 README、確認 repository 名稱），底下一行小字說明為什麼這裡直接寫 public、private 留到下一頁。最後一句講你不用打 git 指令。

⚠️ **這是單元 8-4 的第一頁**，所以口白前四段是整支影片的開場（這一段在做什麼、為什麼卡住你的是帳號不是程式），**畫面上沒有這幾句**，不要跳過。

**逐字稿**

> 前面那幾支做的都是同一件事：把一個功能交辦出去，讓它自己跑到完成條件過為止。計時器現在會記你跑過幾趟，也會自己驗。
>
> 但有一件事從頭到尾沒變過：它只存在你這一台電腦上。你沒辦法傳給任何人，換一台電腦也打不開。接下來這一段就是把它送出去，從存到 GitHub 開始，一路到拿一個手機打得開的網址。
>
> 先說一件事，免得你以為接下來還是一直貼指令：這一段卡住你的多半不是程式，是帳號跟授權。登入 GitHub、授權 Vercel、去 Supabase 複製金鑰，這幾下它做不到，因為那是你的帳號，它沒有你的滑鼠。所以這一段的節奏會變成「它做一段、停下來叫你點一下、你點完它再繼續」。
>
> 那個「停下來叫你點一下」其實你認得，就是前面講的人類閘門。只是這一次你沒有寫，它本來就過不去。
>
> 好，從第一步開始。你前面做的那些存檔點，一個都沒有離開過你這台電腦。這件事在三種情況下會變成問題。硬碟壞了，整個專案跟著沒了，沒有第二份。
>
> 換一台電腦，要自己複製資料夾，還常常漏東西。想傳給別人看，總不能把整個資料夾壓縮寄過去。
>
> 解法是 GitHub，它就是專案的線上存放處。
>
> 推上去之後，那些存檔點會有一份在雲端。它有兩個用途，而且第二個對你更重要。
>
> 第一個，給你自己用：換電腦、找回舊版本、給別人看，都從這裡。
>
> 第二個，給部署平台用。這一句請記住，它是後面走不走得下去的關鍵：Vercel 不是讀你的電腦，是讀 GitHub。
>
> 所以沒有推上去，後面部署整條路就接不上，不管你本機跑得多好。也就是說，推上 GitHub 不是備份而已，它是上線那條路的第一步。
>
> 這件事你前面學 Git 的時候就看過一次了，這裡是真的要用了。下面這段話可以直接複製：幫我把這個專案推到 GitHub。
>
> 這段指令是一次到位的版本：直接指定 public，並且在推之前先檢查 `.gitignore` 與有沒有寫死的金鑰、寫一份 README、確認 repository 名稱。金鑰那一條寫成「找到先告訴我，不要自己改」，不要刪掉也不要簡化，金鑰的事等一下會整頁講。
>
> 最後這句：你不用打任何 git 指令。它會自己建好、推上去，然後把網址給你。桌面版的 Code 頁籤右下角也有按鈕可以按。
>
> 但是有一件事它做不了，而且這是整堂課到現在第一次遇到，所以我要先講：它會停下來等你。前面每一步都是它自己做完的，所以第一次推的時候畫面停住，多數人的第一個反應是「壞了」。
>
> 沒有壞，是 GitHub 要確認你是本人。三件事只有你做得到。
>
> 第一，你要先有一個 GitHub 帳號。還沒有的話現在去 github.com 註冊一個，免費。
>
> 第二，第一次推的時候要在瀏覽器登入並且按同意。它會給你一段文字或一個連結，你照著做完，再回到對話框跟它說好了。
>
> 這一步跟前面講部署授權是同一回事，你的帳號它代不了。
>
> 第三，這個專案設成 public。那段指令裡已經直接寫了，因為練習專案本來就是要給人看的；什麼情況該改成 private，下一頁講。
>
> 裡面有客戶資料或還沒公開的東西就選 private，之後隨時改得回來。
>
> 如果中間卡住、看不懂它在說什麼，最簡單的做法是把它給你的那段訊息整段貼回去，跟它說「我看不懂，告訴我現在要點哪裡」。

**這頁的教學意圖**：GitHub 有兩個用途，而「部署平台讀的是 GitHub 不是你的電腦」是後面走得下去的前提。
**預估時間**：4 分鐘（動手）

## Slide 163｜金鑰和客戶資料不能跟著推上去

**畫面**
兩個判斷並排。判斷一：public 還是 private，各附適用情境與一句限制。判斷二：哪些檔案不跟著走，列出幾個打叉的檔名。下面一塊介紹 `.gitignore`，並把它接回規則歸位的第一格。再一塊「它怎麼知道那串字是金鑰？」列出三種偵測方式、跑的位置與限制。最後一句講 Vercel 綁一次就好。

**逐字稿**

> 判斷一，公開還是不公開。public，想當作品集給人看、想讓人試用的選這個。而且有一個限制：免費帳號要用 GitHub 自己掛網頁的話，只能選這個。
>
> private，跟工作有關、裡面有客戶的東西的選這個。
>
> 這種要上線就接 Vercel，它吃 private。一般的建議是：不確定就選 private，之後隨時可以改成公開，反過來很麻煩。
>
> 但這一格選什麼，會決定你上線能走哪一條路。所以它是隱私的選擇，同時也是路線的選擇。等一下部署的時候會回來收這一題。
>
> 判斷二，哪些檔案不跟著走。畫面上打叉的那幾個就是不能推上去的。
>
> 為什麼要特別講，理由寫在下面：推上 public 之後才發現，刪掉也來不及，紀錄裡還留著。
>
> 這一句你在講安全邊界的時候聽過同樣的結論：金鑰一旦被推上去，就當它已經外洩了。
>
> 再來這一塊有一點里程碑的意思：這是你自己設的第一道機制。前面學了那麼多「規則要用擋的不要用寫的」，這是第一次你真的擋了一個東西。
>
> 擋住這些檔案的東西叫 `.gitignore`。列在裡面的檔案，git 根本不會碰。
>
> 這份清單是你自己列的，跟它說「幫我建一份 `.gitignore`，把金鑰、環境設定與客戶資料擋掉」它就幫你建好。
>
> 然後它把這件事接回去了：這就是前面規則歸位的第一格，會出事的交給機制，不要只寫進手冊。差別在於這次是程式在擋，不經過 AI 的判斷。
>
> 這裡會有人問一個很好的問題：所謂的檢查，程式真的分得出哪一串字是金鑰嗎？分得出來，但它不是看得懂你的密碼，它是在比對長相，三種做法疊在一起。
>
> 第一種，固定格式。各家服務發出來的金鑰有自己的開頭跟長度，有的還帶檢查碼，所以一看就認得出是哪一家的。
>
> GitHub 認得的那一組叫 partner patterns，掃到的時候它還會通知那家服務把那把金鑰作廢。
>
> 第二種，看旁邊的名字。那串字前面寫著 password、api_key、token 這類字眼，那就很可疑。
>
> 第三種，像不像亂碼。一長串沒有規律、唸不出來的英數字，本來就不像人會寫的文字。
>
> 跑的位置有兩個。掛在你機器上的檢查可以在推出去之前就擋下來；GitHub 那邊也會自己掃，公開的專案免費，而且掃的是整段歷史紀錄，不是只看你這一次推了什麼。
>
> 它偵測到的時候會直接把那一次推送擋掉，告訴你擋在哪一行。但限制要講清楚：它認得的是「長得像金鑰的字串」。
>
> 你自己取的那種好記的密碼，它只能靠第二點猜，猜不到就漏了。
>
> 所以真正的解法不是靠掃描，是一開始就不要寫進程式碼，放進 `.env` 再用 `.gitignore` 擋住，掃描只是最後一道。
>
> 所以你現在手上有兩道同一種性質的防線：`.gitignore` 擋 git，`settings.json` 的 deny 擋 AI 讀。
>
> 兩個擋的是不同的人，所以兩個都要有。只擋一邊，另一邊照樣會把東西帶出去。
>
> 最後那句是在預告下一步：推上去之後，Vercel 綁一次 GitHub 就好。之後你只要說「幫我更新上線」，它推完，網站自己跟著換新版。

**這頁的教學意圖**：public／private 的選擇會決定上線路線；`.gitignore` 是學員親手設的第一道機制。
**預估時間**：4 分鐘

## Slide 164｜部署上線：把 GitHub 上的專案接上 Vercel
**畫面**
上方一段長的 Prompt，附複製鈕，底下一句解釋它為什麼那麼長。中間一塊 Vercel 的四步（登入、選 repo、按 Deploy、拿到網址），每一步附一句說明，底下一句講接上之後每推一次就自己重新上線。再下面一個灰底的 Callout 講 GitHub Pages 這條路，以及它的兩個限制（要 public、沒有地方放不能外流的金鑰）。然後是「卡住的話，通常是這五件事」。最後一個綠色 Callout 講做完你手上會有什麼。

**逐字稿**

> 這一步要做的就是把網址生出來。先看這段 Prompt，它比前面幾段都長：幫我把這個資料夾部署到 Vercel。
>
> 先確認本機打開沒問題，推上 GitHub，再接 Vercel 完成部署。需要我去瀏覽器授權的時候停下來告訴我要點哪裡。
>
> 完成後把網址給我，並且確認那個網址真的打得開。
>
> 底下那句解釋了它為什麼長：它把要做什麼、什麼時候該停下來問你、做完給你什麼都講完了。這三段結構你應該認得，那就是這一章開頭那五個步驟的縮寫版。
>
> 中間那半句「需要我去瀏覽器授權的時候停下來告訴我要點哪裡」，就是 Human Gate。
>
> 因為授權這件事它真的做不到，它沒有你的滑鼠。
>
> 這門課只走 Vercel 這一條，四步。第一步，用 GitHub 帳號登入 vercel.com，不用另外註冊，也不用在電腦上裝任何東西。
>
> 第二步，選你剛推上去的那個 repo。如果你前面選了 private，它一樣選得到，只是授權的時候要把那個 repo 勾進去。
>
> 第三步，按 Deploy，等它跑完。計時器這種純前端的專案不用改設定，它自己判斷得出來要怎麼打包。
>
> 第四步，拿到網址，長得像「你的專案名點 vercel 點 app」，免費，馬上就能傳給別人。
>
> 接上之後有一件事會一直幫你：你每推一次，它就自己重新上線一次，網址不會變。這也回答了前面那個「為什麼要先推上 GitHub」：Vercel 看的是那個 repo，不是你的電腦。
>
> 底下那個灰框是另一條路，GitHub Pages。你在別的教學裡大概會看到它，所以我講一下它的限制在哪。做法是在 repo 的 Settings 找到 Pages，Source 選你的分支，存檔，就會拿到「你的帳號點 github 點 io 斜線專案名」。好處是不用再開一個平台的帳號。
>
> 但免費帳號的 repo 要設成 public 才掛得上去，而前面的建議是不確定就選 private。另外一件是等你做自己的題目才會撞到的：只要有一把不能外流的金鑰，你就需要一個「只有伺服器讀得到」的地方放它，GitHub Pages 沒有那個地方，Vercel 有。計時器這個題目用不到，下一個題目很可能用得到，所以這門課一路走 Vercel。
>
> 兩邊的後台都會改版，按鈕位置跟名字可能跟我講的不一樣。流程不會變：推上 GitHub、授權、選 repo、部署。
>
> 這一頁的另外一半會比上面那段 Prompt 更花你的時間：卡住的五件事。
>
> 這五件不是你做錯，它們幾乎每個人都會撞到，因為它們都牽涉到你的帳號跟授權，那是它幫不了你的部分。
>
> 第一，它停下來叫我去瀏覽器點同意。這是正常的，第一次推上去要授權 GitHub，它沒辦法幫你點。點完回來跟它說「好了，繼續」。
>
> 第二，推不上去，說認證失敗。GitHub 現在不收密碼了。跟它說「幫我改用瀏覽器授權登入 GitHub」，它會帶你走一次。
>
> 第三，推上去了，但 Vercel 找不到我的 repo。private 的 repo 要在 Vercel 授權那一步勾進去，回到授權頁面重選一次，把那個 repo 加進可存取的清單。
>
> 第四，部署成功，但打開是一片空白。多半是 `index.html` 不在 repo 最外層，或程式裡寫死了你電腦上的路徑。把網址跟畫面截圖一起貼給它。
>
> 第五，我改了東西，但網址上還是舊的。改完要再存一次檔、再推一次，平台才會知道要重新上線。第五條特別標著「這是最多人以為壞掉的地方」。
>
> 請記住它，因為它不會有任何錯誤訊息，畫面上一片正常，只是內容是舊的，你會一直重新整理然後懷疑人生。
>
> 做完你手上會有什麼：一組別人打得開的網址，對方不用裝任何東西，手機也開得起來。然後是驗收方式，這一段請務必照做，不要用電腦開一下就算數：用手機開一次那個網址，不要用你部署的那台電腦，也不要連同一個 wifi。
>
> 手機開得起來，才代表它真的在線上，不是只有你這台打得開。
>
> 所以現在真的去拿手機開一次，下一頁從你看到的那個畫面開始講。

**這頁的教學意圖**：真的生出網址；Vercel 的四步裡哪兩步要自己點；GitHub Pages 的 public 限制是它不當主線的理由；五個卡點各自的處理方式。
**預估時間**：15 分鐘（動手，含實機）

## Slide 165｜手機打開，紀錄卻是空的

**畫面**
上方一組對照：你的電腦（12 趟、連續出勤 5 天）對上你的手機（0 趟、連續出勤 0 天），底下一句提問。中間一塊給答案，並引出資料庫（那個東西就叫資料庫、用 Supabase 這類託管服務），最後一行接到下一頁（接下來就把它接上去，四步）。下面一塊列部署平台後台的四個地方。最後一個 amber 的 Callout：綠燈不等於打得開。

**逐字稿**

> 我猜你第一個反應是「是不是哪裡做錯了」。沒有，這一頁就是要讓你撞到這件事。你的電腦上顯示 12 趟、連續出勤 5 天，手機上是 0 趟、0 天。同一個網址，同一個人，紀錄卻不一樣。
>
> 為什麼？這個答案你在加航行日誌那一頁就聽過了。因為 `localStorage` 是記在那台電腦裡的。它從來沒有離開過你的筆電。
>
> 這一句要聽清楚：網站是上線了，資料沒有。程式跟資料是兩件事。你上線的是程式，而資料從頭到尾都躺在你的筆電裡。這就是你在加航行日誌那一頁選擇的代價。
>
> 那時候 `localStorage` 讓你不用註冊、不用後端、不用付錢，一句話就有。它的代價現在來了。
>
> 要讓任何一台裝置打開都看得到同一份紀錄，就需要一個放在雲端、大家共用的地方。
>
> 那個東西就叫資料庫。你前面看過它的樣子（四張表那一頁），現在你知道它為什麼存在了。用 Supabase 這類託管服務就好，不用自己架，但會多出註冊帳號、建一張表、貼一把金鑰這幾下設定。
>
> 這件事等一下就做，四步，其中兩步要你自己動手。先把這一頁剩下的講完。
>
> 再來是實用的部分：部署交給它動手，但後台這四個地方你要自己看得懂。
>
> 這四個是 Vercel 的叫法，換一家平台名字不一樣，但這四種東西都會有。
>
> 第一，Deployments，每一次上線的紀錄。綠燈代表建置成功，紅燈點進去看最後幾行紅字，那就是它失敗的原因。
>
> 第二，Build Logs，建置過程的完整輸出。網站打不開的時候，這裡通常已經寫清楚是缺了哪個套件或哪個檔案。
>
> 第三，Environment Variables，不能外流的金鑰放這裡，而且只有伺服器那一側讀得到。
>
> 這一欄你的計時器用不到，先記著就好：純前端的網頁讀不到它。等你的題目有了後端那一天，它是「本機好好的，上線就壞」的頭號嫌疑犯。
>
> 第四，Functions 或 Runtime Logs，網站跑起來之後出的錯記在這裡。建置成功但畫面是白的，答案幾乎都在這一頁。
>
> 再來要把最容易搞混的兩件事分開，這個混淆會害你查錯方向：綠燈不等於打得開。Deployments 那顆綠燈說的是「檔案送上去、建置沒有失敗」。
>
> 它不會幫你打開網站看一眼。綠燈配上白畫面是最常見的組合，原因多半在 Functions 那一頁的錯誤紀錄裡。

**這頁的教學意圖**：程式上線不等於資料上線；後台四個分頁各自對應一種症狀；綠燈只代表建置成功。
**預估時間**：6 分鐘

## Slide 166｜把紀錄搬上 Supabase，換台裝置也看得到

**畫面**
頁首有 `LiveDemo`。開場一句講接資料庫就是把紀錄從這台電腦搬到一個雲端的共用地方。中間四步，每一步右上角標著「你自己做」或「可以發包」：建表（發包）、複製可以公開的那把金鑰（自己做）、把那把金鑰填進程式碼裡（自己做）、打開 RLS 並寫一條規則（發包）。下半左邊一段可複製的 Prompt（五點），底下接一塊「為什麼是它？換別家行不行」（三個理由、同類的四個名字、要換時問的三件事）；右邊兩塊：兩把金鑰只有一把該出現在前端（底下接回五道邊界的第二道），以及一個 amber 的 Callout「沒有登入，大家就是共用同一份」。最後一塊講做完怎麼確認。

**逐字稿**

> 這件事有解，而且不難：把紀錄從「這台電腦的瀏覽器」搬到一個雲端的共用地方，就是接資料庫。
>
> 程式那一段你不用寫。但下面四步裡有兩步得你自己動手，因為那是你的帳號跟你的金鑰，它沒辦法代你點。
>
> 第一步，開一個 Supabase 專案，建一張表。欄位就是你前面那三個：出發時間、飛行分鐘數、有沒有完成。表讓它幫你建，你只要在後台看一眼欄位對不對。
>
> 第二步，複製那把可以公開的金鑰。Supabase 會給你兩把，這裡要很小心：前端用的那把本來就設計成會被看到；另一把是後台用的，權限很大，這個題目完全用不到，不要複製它，更不要貼進對話。
>
> 第三步，把那把金鑰填進程式碼裡。你可能會覺得怪，前面不是說金鑰不能寫進程式碼嗎？這一把不一樣，下一頁我會把兩種分開講。先記住原因：它本來就會跟著網頁送到每一個訪客的瀏覽器，藏不住，所以它被設計成看到也沒用。你的計時器是一個 index.html，連打包都沒有，平台的環境變數它根本讀不到，貼進去只會拿到一片空白。
>
> 第四步，打開 RLS，再寫一條規則。RLS 全名是 Row Level Security，白話講就是「這張表的每一列，誰能讀、誰能寫」。沒開的話，任何人拿到那把公開金鑰就能把你的表讀光、刪光。這一步不能跳過，案例三會整段講這個取捨。
>
> 畫面左下那段話可以直接複製。裡面第 1 點跟第 3 點不要刪掉，那兩句是煞車：第 1 點要它先列步驟不要動檔案，第 3 點是金鑰我自己填，你在程式碼裡留一個空字串加註解，告訴我填在哪一行。
>
> Prompt 底下那一塊回答一個你現在一定會想問的問題：為什麼是 Supabase，換別家行不行。
>
> 這堂課挑它有三個理由：免費方案不用綁信用卡、資料庫跟登入在同一個後台所以你不用再接第二個服務、而且它是開源的，之後真的要搬走，資料拿得回來。
>
> 同一類的還有 Firebase、Neon、PlanetScale、Pocketbase，換哪一家都做得到這一頁的事，所以你公司已經在用別家就用別家。
>
> 真正要帶走的是換的時候問哪三件事，因為名單會過期，問法不會。第一，免費方案夠不夠你這個專案用。第二，資料拿不拿得回來。第三，它的說明文件夠不夠普及。
>
> 第三個最容易被忽略：太冷門的服務，Claude 會把設定寫錯，而你又看不出來。這一條對不寫程式的人特別重要，因為你驗不動那段設定。
>
> 右邊這一塊解釋為什麼那把金鑰可以公開：純前端的網頁藏不住任何字串，使用者打開開發者工具就看得到。所以能放前端的只有那把本來就設計成可以公開的，而真正擋住別人的不是金鑰，是 RLS 那條規則。
>
> 底下那一句要停一下講：這是你整堂課第一次手上真的有一把金鑰，而它剛好是可以公開的那一種，所以就寫在程式碼裡跟著推上去。放手前那五道邊界的第二道，講的是另外一把，就是後台那把權限很大的，這個題目完全用不到。兩種的差別下一頁整理成一塊。
>
> 最後這一塊我要先說，免得你做完發現不是你想的那樣：接上資料庫之後，換一台裝置確實看得到同一份紀錄。但這個計時器沒有帳號，所以別人打開你的網址，看到的也是同一份。
>
> 要變成「我的紀錄跟著我走」，還要再加一個登入。這就是為什麼章節三說 Supabase 是「資料庫加會員登入」兩件一起賣的。自己用的話，現在這樣就夠了；要給別人用，就把登入加上去。
>
> 做完怎麼確認？在電腦上跑一趟，然後拿手機開同一個網址。手機上看得到那一趟，才算接上了。看不到的話，九成是金鑰貼漏了幾個字，或是 RLS 那條規則把讀取也一起擋掉了，把畫面截圖連同網址貼回去給它。

**這頁的教學意圖**：接資料庫四步裡哪兩步只能自己做；兩把金鑰只有一把能進前端，真正擋人的是 RLS；而沒有登入就是所有人共用同一份，這是這個題目解不掉的那一半。

## Slide 167｜哪一種金鑰可以寫進程式碼，哪一種不行

**畫面**
開場一段講兩句話都對、差別在是哪一種，並給出那一句判斷標準（這串字被別人看到，他能拿去做什麼）。接著一塊灰底的「打開你的網址，那串金鑰就印在原始碼裡」，叫學員當場按右鍵檢視原始碼搜那串字。中間三格並列：綠色「前端用的那一把」、紅色「後台用的那一把」、灰色「不是金鑰，只是設定」，每一格三行（它是什麼／拿到的人能做什麼／放哪裡）。最後一個 sky 的 Callout「那我們剛剛寫進去的那一把，風險在哪」，裡面分成綠字「擋得住」與紅字「擋不住」兩段。

> 我們剛剛把一把金鑰直接寫進程式碼，而前面講部署的時候，我說的是金鑰不要寫進程式碼。兩句話都對，差別在是哪一種。
>
> 要分它只要問一件事：這串字被別人看到，他能拿去做什麼。
>
> 先驗給你看。打開你剛做好的那個網址，在頁面上按右鍵，選「檢視網頁原始碼」，然後 Ctrl + F 搜我們剛剛貼的那串字。它就在那裡。每一個打開你網站的人都看得到，而且你沒有辦法把它藏起來，純前端的網頁就是這樣。所以能放進去的，只有被看到也沒差的那一種。
>
> 畫面上第一格就是那一種，也就是前端用的那一把，我們剛剛貼進去的就是它，所以答案是可以寫。那有人把它複製走，他到底能做什麼？具體講：他可以讀你全部的紀錄，也可以新增一筆，就這兩件。改跟刪做不到，因為那條 RLS 規則沒開放這兩種。
>
> 第二格是後台那一把。你其實見過它：接 Supabase 的時候我說 Supabase 給你兩把，另一把是後台用的，這個題目用不到，不要複製它，就是這一把。我們從頭到尾沒有用過它。
>
> 它為什麼不能外流？因為它無視 RLS，你寫的那條規則對它沒有用，拿到的人可以把你整張表清空。同一類的還有會跟你收錢的 API 金鑰、資料庫密碼，那種是被人用你的帳號一直打，帳單算你的。而且公開的 repo 會被程式掃，金鑰掃到就被人拿走了，不用等誰特地來找你。
>
> 第三格嚴格講不是金鑰：專案網址、表的名字、某個功能的開關。知道了也做不了什麼，只是以後可能會改。我把它放進來，是因為它常常跟金鑰擺在同一欄，很多人就以為那一欄裡的東西都是祕密。
>
> 講到這裡你心裡大概有一個問題：那我們剛剛寫進去的那一把，風險到底是什麼？不會真的完全沒有吧。
>
> 有。而且要講清楚：它安全不是因為藏得好，是因為 RLS 那條規則擋著。你現在是前端直接對資料庫，中間沒有你寫的程式，那條規則就是唯一的一道。
>
> 我用計時器現在真正的那兩條規則來講，比較具體。
>
> 擋得住的是：別人改不掉、也刪不掉你的紀錄，因為規則只開放了讀取跟新增這兩件事。離譜的資料也進不來，規則上寫著分鐘數的範圍，出發時間也不能是未來。
>
> 擋不住的就是剛才第一格講的那兩件：讀全部、塞假紀錄。原因不是規則寫壞了，是這個計時器沒有登入，所以規則只認得出「有人從前端來」，它認不出是誰。
>
> 這裡要特別講一句，因為很多人第一個反應是「那我把金鑰藏起來」：藏不了，也沒有用。網頁一定要把金鑰送出去才呼叫得到 Supabase，打開開發者工具的 Network 那一頁就看得到它。放進 Vercel 的環境變數也一樣會被送出去。
>
> 所以要把這件事收起來，只有一條路：讓資料庫認得出是誰在寫。那就是登入，下一頁講。
>
> 我剛剛講了一句「前端直接對資料庫，中間沒有你寫的程式」，那句話其實描述了你現在整個專案的樣子。下一頁把它畫出來，順便回答你大概已經想問的：那我要加登入怎麼辦。

**這頁的教學意圖**：分金鑰看的是「拿到的人能做什麼」，不是它叫什麼；純前端藏不住東西，學員當場驗一次；那一把的安全來自 RLS 而不是它本身，所以要盯的是 Policies。

## Slide 168｜前端、資料庫、沒有後端：要加登入怎麼做

**畫面**
上方三格並列：綠色「前端（有）」、灰色虛線框「你自己的後端（沒有）」、綠色「Supabase（有）」，每一格一句說明，第三格點明 Supabase 不只是資料庫。底下一段講所以每一次讀寫都是前端直接打 Supabase 的 API。底下整列一塊「想讓每個人只看到自己的紀錄，要先有後端嗎」，答案是不用，接一條四格的流程（登入／拿到通行證／每次多帶一張／規則改成比對身分），一句講通行證跟公開金鑰的差別，再附一段可複製的 Prompt（五點）。

**逐字稿**

> 這是你現在手上這個專案的樣子，三格。
>
> 第一格，前端，你有。就是那個 index.html，它被下載到訪客的手機或電腦上，在那裡執行。
>
> 第三格，Supabase，你也有。這裡要澄清一件事，因為前面幾頁我都簡稱它資料庫，你可能以為它就只是一個資料庫。不是。它是一包服務：資料庫是核心，但同一個後台還有登入、檔案儲存，還有 Edge Functions。
>
> 另外它會自動把你的資料表變成一組 API，這也是為什麼你的網頁可以直接讀寫資料，你並沒有自己寫過任何一支 API。
>
> 中間那格是空的：你自己的後端，也就是一段跑在伺服器上、由你決定邏輯的程式。剛才講的 Edge Functions 就是放這個的地方，只是你還沒寫任何一段。我把它畫成虛線不是在說你做錯了，是要你看清楚現在這條路徑長什麼樣。
>
> 所以每一次讀或寫，都是前端直接打 Supabase 的 API，中間沒有你的程式。這不是陽春版，Supabase 這類服務本來就是設計成讓前端直接連的，安全靠 RLS 擋，不是靠把金鑰藏起來。代價是那一道寫錯就沒有第二層。
>
> 底下這塊回答一個很多人會卡住的問題：想讓每個人只看到自己的紀錄，是不是要先自己寫一個後端？不用。登入那一段 Supabase 已經幫你寫好了，你的網頁直接用它，那一把公開金鑰就夠。
>
> 底下這條流程就是登入之後多出來的東西，四步。
>
> 第一步，使用者在你的網頁上登入，輸入 email 跟密碼，或者收一封登入信點進來。這一段 Supabase 幫你做，你不用自己寫。
>
> 第二步，登入成功之後 Supabase 回你一張通行證，瀏覽器把它存起來。這裡要特別講清楚，因為你聽到「存在瀏覽器裡」大概會想說那不是又回到剛才那個問題嗎。不一樣：它不是另一把金鑰，它是「你是誰」的證明，而且會過期，通常一個小時就要換一張新的。
>
> 第三步，之後每一次讀或寫，網頁會多帶這張通行證。注意原本那把公開金鑰還是要送，兩個一起送，缺一個都不行。
>
> 第四步，RLS 那條規則改成比對身分，從「誰都讀得到」變成「只動得了自己那幾筆」，比的就是通行證上的那個身分。規則是在資料庫那一端執行的，不在你的網頁裡，所以使用者繞不過去。
>
> 所以通行證一樣看得到，但公開金鑰代表的是「任何人」，它代表的是「這一個人」，規則比對的是後者。這就是為什麼加了登入，那條規則才收得起來。
>
> 下面那段 Prompt 可以直接複製。第 1 點跟第 4 點不要刪：第 1 點要它先列步驟不要動檔案，第 4 點是叫它不要擅自引進新的金鑰，不然你會莫名其妙多出一個要保密的東西。
>
**這頁的教學意圖**：把現況畫成三格，讓學員看清楚「沒有後端」長什麼樣，以及 Supabase 不只是資料庫；加登入不需要後端，而登入拿到的是「代表這一個人」的通行證，不是第二把金鑰。
**預估時間**：7 分鐘

## Slide 169｜什麼時候要自己寫後端，以及怎麼做

**畫面**
開場一句講登入是現成的，以及三種情況的共同點：不能在訪客的瀏覽器裡做，而且只有你的專案知道規則。中間三格：要用會被拿去花你錢的金鑰、要定時做事、要做繞不過的檢查。底下一段可複製的 Prompt（艦長講評，五點），膠囊上寫著「真的要做的時候照這段講」。最後一段小字：`api/` 是 Vercel 的規定、金鑰那一欄到這裡才用上、Edge Functions 是同一套，以及後端不會幫你擋人。

> 登入那一段 Supabase 已經幫你寫好了，所以剛才那一頁你不用自己做任何後端。那什麼情況是沒有現成的可以用、得你自己寫一段？三種，共同點是那件事不能在訪客的瀏覽器裡做，而且只有你的專案知道規則。
>
> 先把一件事說清楚，免得混淆：Supabase 的登入本身就是跑在伺服器上的後端，只是它是別人幫你寫好的。所以這一頁講的不是「有沒有後端」，是「有沒有現成的可以用」。
>
> 第一種，你要用的金鑰會被拿去花你的錢。最常見的就是叫 AI 幫使用者寫一段摘要：那把 API 金鑰是按用量計費的，你放進網頁就等於公開，別人拿去打，帳單寄給你。寄 email、收款的金鑰也是同一類。
>
> 第二種，你要定時做事。每天早上八點寄一封報表，沒有人打開網頁的時候也要跑，就不能靠訪客觸發。
>
> 第三種，你要做使用者繞不過的檢查。例如名額只剩一個、兩個人同時按，這種判斷放在前端會被繞過。案例三整段在講這件事。
>
> 那真的要做的時候，第一句話怎麼開口？就是底下這一段，可以直接複製。我用計時器當例子：加一個「艦長講評」。前端把這週的航行日誌送給一支後端程式，它呼叫 AI 用任務艦長的口氣講評這一週，指出你最常中斷的是哪個時段，最後下一句下週的指令。你自己的題目換掉第 2 點就好。
>
> 順帶說一下為什麼挑這個例子：最常中斷的時段，其實前端自己算也算得出來，不需要 AI。但「用艦長的口氣講評」跟「下一句指令」不行，那是 AI 才做得到的，而那把金鑰就是不能放前端的那一類。這兩件要一起，才構成一個非自己寫後端不可的功能。
>
> 這段話裡有兩件事值得知道。
>
> 第一，api 斜線那個資料夾，是 Vercel 的規定。放在那裡的檔案它不會送去瀏覽器，而是留在它自己的電腦上執行，還自動配一個網址給它，就是你原本的網址後面加上斜線 api 斜線檔名。你不用設定任何東西，放進去就算數。這也是為什麼同一個專案可以同時有前端跟後端，差別只在檔案放在哪個資料夾。
>
> 第二，金鑰填進 Vercel 後台的 Environment Variables。這一欄你應該有印象，前面我說過你的計時器用不到它，到這裡才真的用上：這支程式跑在 Vercel 的電腦上，所以它讀得到，而訪客的瀏覽器讀不到。
>
> 第 5 點是驗收，用的是我們前面用過的那一招：打開開發者工具，看請求送去的是你自己的網址，而且裡面沒有金鑰。
>
> 另一條路是用 Supabase 自己的 Edge Functions，做法一樣，只差檔案放哪裡。兩條都在你已經有的帳號裡，不用再找第三個服務。
>
> 最後補一件很容易誤會的事：加了這一層，不代表就只有你能用了。那支網址一樣是公開的，誰知道都打得到。要限定只有登入的人用得了，還是得先有登入，也就是上一頁那一步。後端解決的是「金鑰藏哪裡」跟「哪些事不能交給瀏覽器做」，不是「是誰」。

**這頁的教學意圖**：把「後端」從一個嚇人的詞變成三種看得懂的情況，加一段可以直接貼的 Prompt；`api/` 生效是平台的規定不是魔法；環境變數那一欄到這裡才用上；後端解決的不是「是誰」。
