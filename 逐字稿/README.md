# 逐字稿

一個錄製單元一個檔案，檔名是 `單元編號_單元名稱.md`。單元編號與範圍用 `npm run units` 查，**不要手抄**，搬頁之後 X-Y 會整批重排（CLAUDE.md B-2c）。

## 寫作前提

- **全片預錄、非同步自學**，鏡頭前沒有學員。不要寫「各位同學」「我們今天來看」這類對著一群人講的話。
- **開場白照單元的位置分兩種，不要 38 支都用同一句。** 2026-09-20 以前全片固定寫
  `Hello，我是 Samuel，歡迎來到這個單元。`，理由是每一支都是獨立影片。但連著看的時候，
  同一句開場 38 次是很重的模板感，所以改成：
  - **章節的第一個單元**（1-1、2-1、3-1、4-1、5-1、6-1、7-1、8-1、9-1）報名字，
    句型是 `Hello，我是 Samuel，接下來進到第 N 章。`，後面接這一章要處理什麼。
  - **同章節的後續單元不要重新自我介紹。** 直接承接上一段（「前面那些零件，你現在叫得出名字了。接下來看它們在真的專案裡被拿來做什麼。」），
    或者直接開始做（「好，接下來直接動手。」）。
  - **開場不要跟上一個單元最後那句轉場講同一件事。** 兩支接著看的時候那兩句是連在一起的，
    重講一次接縫最明顯。2026-09-20 掃出 8 處逐字重複，病根都是「Hello」下面那一句
    又把轉場說了一遍；砍掉那一句，轉場自己就是開場。
  - 六個第一頁是 `meta.script` 的單元（4-5、5-1 到 5-5），開場寫在 `.tsx` 那一份，
    改完跑 `npm run check:rec`。

- **會過期的外部事實不要變成拿不掉的句子。** 價格、方案名稱、模型名稱、權限模式名稱、
  介面位置、安裝需求、某個工具目前支不支援某功能，這些一年內都可能改，改了就要重錄。
  寫法是把「當下的數字」跟「不會過期的判斷」分開講，例如「這是我錄的時候的數字，
  方案名稱跟金額各家都在調，你去官網看一眼當下的就好」。**但學員當下要動手的步驟不要拿掉**，
  該講按哪裡就講按哪裡。相關的查證規範見 CLAUDE.md C 章。

- **操作頁不要用旁白塞滿等待時間。** 實機執行、等 Agent 跑完、結果出現前的那幾秒，
  逐字稿寫 `【等待 Agent 執行，不補旁白】`、`【停頓】` 這種括號提示就好。
  尤其那一段的教學目的本來就是「你不用一直動手」的時候，聲音更不該一直替畫面填空。
  這類提示只在真的能改善節奏的地方加，不要每頁都放。
- **不要寫課務交代**：「等一下會發下去」「現在把電腦打開」「請按下一頁」。理由同 CLAUDE.md D-2。
- 投影片上已經有的字**不要整句照念**。逐字稿的職務是補充畫面沒寫的：為什麼、實例、常見的誤解。
- 每頁 45 秒是預錄拆頁的上限（`npm run check:rec` 會算），live 頁沒有硬性限制，但同一個節奏比較好剪。

## 敘事風格：照講師現場課的調性

風格基準是 `slide_1_41_現場教學逐字稿_設計檢查.md`（居家先生 AI 流程優化工作坊的現場稿）。那份是現場課，這門課是預錄，**借的是敘事邏輯與用詞，不是現場語**。

### 借過來的六件事

1. **先講學員現在的處境，再講內容。** 一頁的頭兩句先接住他為什麼會卡，而且要歸因到事情本身，不是歸因到他。<br>例：「很多人不是不努力學工具，而是工具本來就還在變。」<br>不要寫成後設導覽（「這頁很重要，因為⋯」），那是 CLAUDE.md D-2 禁的。同一件事講成內容就合法，講成簡報的結構就不合法。
2. **第一人稱表態。** 「我先講在前面」「我會把它理解成」「這裡先忍住」「我的判斷是」。講師的立場要出現，讀起來才不像說明書。
3. **連續短設問。** 抽象講完，丟三到四個具體的問題讓人自己對答案。<br>例：「資料從哪裡來？格式清不清楚？誰要接手？多久內要回應？」
4. **預判誤解，當場堵住。** 一句話講完，如果有一個很容易聽歪的方向，立刻補一句擋掉。<br>例：「它降低了理解門檻，但這不代表專業不重要，判斷與責任還是在人身上。」
5. **列點後面各跟一句白話。** 不要只給名詞。「保留，是這一步真的有價值，而且現在做法也合理。」
6. **收尾給判斷原則或順序，不給口號。**<br>例：「注意順序：消除、重新設計、加速、新增。不要一開始就加速。」<br>不是「答得出這三題，這一段就過了」那種（D-2 禁的收尾金句）。

### 用詞

白話動詞優先：卡住、忍住、硬做、回頭看、串回來、拿出來看、換掉、接住。不要為了正式而換成書面語。

術語第一次出現就用一句白話翻譯，不要讓人以為要背名詞。例：「Connector、API、Webhook，講白話就是系統能不能穩定把資料交出來。」

### 不借的

參考稿是現場稿，這幾類一律不跟：

- 點名與集體稱呼：「各位同學」「請大家」「大家一起」（固定的單元開場白是例外，見上一節）
- 現場調度：「等一下我們會⋯」「花 15 分鐘」「先猜猜看」
- 後設導覽：「這頁我們來看」「接下來三頁講⋯」

理由是這門課全片預錄、鏡頭前沒有學員（見上一節），以及 CLAUDE.md D-2。

## 印成 PDF

```bash
npm run pdf      # → 逐字稿/逐字稿全集.pdf
```

把 38 個單元照章節順序合成一份 A4、可點目錄的 PDF，錄製或校稿時比翻 38 個檔案順。
版面把四種東西分開：逐字稿是藍框大字（要念的）、轉場是橘框（接著念，不要停）、
教學意圖與預估時間是灰底註記（不用念）、待處理整段降一級（投影片的問題，不是稿）。

產出物不進版控，改完逐字稿重跑一次就好。腳本在 `scripts/transcripts-pdf.mjs`，
靠 Chrome 的列印引擎排版，沒有額外相依套件。

## 檔案結構

每一頁三塊：

- **畫面**：這一頁上面有什麼，錄的時候對照用。
- **逐字稿**：照著念的內容。
- **【轉場 → 下一頁】**：上一頁講完到下一頁出現之間那句話。**錄的時候不要停**，這句是接的，停了剪接要另外補。
  <br>**轉場只做接續，不要先把下一頁第一句要講的事講掉。** 兩邊都講一次，念起來就是同一句話說兩遍，
  而且接縫的位置最明顯。2026-09-20 掃出 76 處這種重疊，病根是每頁開頭都補了「接住上一頁」的句子，
  但轉場本來就在做那件事。<br>判斷標準：把轉場跟下一頁的第一段接起來念，有沒有哪個意思出現兩次。

每一支逐字稿到最後一頁就結束，沒有附錄。

> 2026-10-27 之前每一份最後面還有一塊「待處理」，記的是寫逐字稿時發現的投影片問題。
> 那些條目早就逐條處理完了，而裡面的頁碼是發現問題當時的編號，搬頁之後對不上任何一頁，
> 所以整區移除。要查某一條當初是怎麼回事，去 git 歷史翻那個日期之前的版本。
> **還有效的錄製提醒已經搬到各檔開頭的「錄製註記」。**

## 預錄拆頁的逐字稿，照抄 `meta.script`

Slide 67 起有 46 頁是預錄拆頁（`src/slides-recorded/`），它們的檔案裡本來就有一份 `meta.script`，那才是錄製時要念的字，而且 `npm run check:rec` 會按「中文字數 ＋ 英文詞數 × 2」算長度，每頁上限 45 秒。

**這些頁面的逐字稿一律照抄 `meta.script`，不另外寫一份。** 理由是 CLAUDE.md A-4 記過的同一個坑：口白長度是從 `script` 算出來的，這裡另寫一份更長的版本等於製造第二份真相，而且錄的人照著唸會超時。

要改口白就去改那個檔案的 `meta.script`，改完跑 `npm run check:rec`。這份文件負責的是它旁邊那些欄位：畫面、教學意圖、轉場、待處理。

分節頁與座標頁（`kind: 'reference'`）不套 45 秒上限，但一樣有 `script`，處理方式相同。

## 章節三之後補的兩個欄位

3-x 的檔案每一頁多了兩行，之後的單元沿用：

- **預估時間**：抓剪接與整支影片長度用。標「動手」的頁面含實機時間。
